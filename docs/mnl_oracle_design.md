작성: 2026-11-12. v1(같은 파일)을 다음 두 가지 지시에 맞춰 고쳐 썼다.
① 지표는 **"MNL로 구축한 세계에서 Oracle로 최적화했을 때 나오는 천장값"**이다. ② **참여율**을 충전 판단 규칙과 대조해서 설계한다.

## 2. 목표 재정의 — "MNL 세계의 천장값"을 잰다

### 2.1 세계와 칸

참여율 p에서 차량은 둘로 나뉜다.

- **참여자 (비율 p)**: 엔진이 고른 휴게소로 간다 (§2.3, 완전 준수)
- **비참여자 (1−p)**: 스스로 MNL로 고른다

| 칸 | 참여자의 정책 | 비참여자 | 의미 |
|---|---|---|---|
| **바닥 J_MNL** | (참여자 없음, p=0) | MNL | MNL로 구축한 현실 세계 |
| **엔진 J_Sk(p)** | S1·S2·S3·S4 | MNL | 엔진이 만든 개선 |
| **천장값 J\*(p)** | **완전정보 Oracle** (롤링 고정점, §2.3) | MNL | **이 작업의 핵심 지표** |

### 2.2 보고할 지표

1. **천장값 곡선** `J*(p)`, p ∈ {0.3, 0.6, 0.9, 1.0}과 **천장 절감률** `(J_MNL − J*(p)) / J_MNL`
   - "MNL 세계에서 완전정보로도 이만큼까지만 줄일 수 있다"를 p별로 보여준다
2. **엔진 격차 축소율(MNL 세계판)** `(J_MNL − J_Sk(p)) / (J_MNL − J*(p))`
   - 기존 사다리(바닥 S0, 천장 UE)와 **분리해서** 보고한다
3. 보조 지표: 이탈 수(reason별), P95 대기, 병목 칸 — 기존 KPI와 같은 정의

비용 정의는 기존과 같다: **총비용(h) = 총 체류 + 이탈 대수 × 120분.**

### 2.3 천장값을 내는 Oracle

비참여자는 **화면 대기에 반응한다.** 그래서 Oracle이 참여자를 옮기면 비참여자의 선택도 바뀐다. 배정표를 고정해 놓고 비용만 다시 계산하는 방식은 쓸 수 없다.

그래서 기존 `PERFECT_ROLLING`의 메커니즘을 그대로 쓴다.

1. **1회차**: MNL 바닥 런의 실현 도착을 오라클 미래로 넣는다
2. **k회차**: 직전 회차의 실현 도착(비참여자의 반응 포함)을 오라클로 넣는다
3. `moved_share`가 0에 가까워질 때까지 반복하고, 진동하면 진동 자체를 보고한다 (기존 규칙)

**정합성 확인**: p=1이면 비참여자가 없으므로 기존 `PERFECT_ROLLING`과 같아야 한다. 이 경우 MNL은 1회차 오라클 출처로만 영향을 준다. 이것을 검증 V5로 강제한다.

> 진짜 사후 최적해(피크 3~4시간 MILP 정확해 + 전일 하한, DESIGN §8.3)는 이 작업의 범위가 아니다. 위 천장값은 "완전정보 벤치마크"이며 최적성을 보장하지 않는다.

## 3. 참여율 — 충전 판단 규칙과의 관계와 구현 판단

### 3.1 충전 판단과 참여율은 층이 다르다 (코드 확인)

| 층 | 무엇을 정하나 | 어디서 | 참여율이 건드리나 |
|---|---|---|---|
| 차량 속성 (한 번 추첨) | 이탈 비용(lognormal), habit_soc(normal), 기회 충전 여부 | `ue_demand.build_trip_demands`, `OPPORTUNITY_STREAM=2`에서 **순서대로** 추첨 | **안 건드린다** |
| 충전 필요·충전량 | 목적지 도달 가능 여부, 목표 SoC(상한 0.8), habit_soc 반영, max_stops | `world/charge_decision.py`. S0는 같은 함수를 호출한다(`s0.py`의 `_reaches_dest`, `_soc_out`) | **안 건드린다** |
| **휴게소 선택** | 후보 중 어디로 갈지, 이탈할지 | 각 `Policy.decide()` | **여기만 갈린다** |

→ 결론: **참여율은 "누구의 `decide()`를 엔진이 하느냐"만 정한다.** 충전할지, 얼마나 충전할지는 참여 여부와 무관하게 같아야 한다. 그래야 참여율의 효과가 순수하게 배정 효과로 남는다(DESIGN §2.3: 충전량은 결정변수가 아님).

### 3.2 추첨 방식 (판단)

```
u_i = U(0,1) — (seed, ev_id) 해시로 차량마다 한 번 고정 (새 스트림 PARTICIPATION_STREAM)
참여자  ⇔  u_i < p
```

이렇게 하는 이유:

- **기존 스트림을 쓰면 안 된다.** `OPPORTUNITY_STREAM`은 이탈 비용·habit_soc·기회 충전을 **순서대로** 뽑는다. 여기서 하나를 더 뽑으면 기존 차량 속성이 전부 밀린다. `runner.py`의 주석("확률을 바꿔도 EV 집합은 그대로여야 한다")과 같은 원칙이다.
- **중첩**: p=0.3의 참여자 ⊂ p=0.6의 참여자 ⊂ p=0.9의 참여자. p를 올릴 때 "참여자가 늘어난 효과"만 보이고, 다른 사람이 뽑혀서 생기는 잡음이 없다.
- **공통 난수**: 같은 시드에서는 S1~S4와 Oracle이 **같은 참여자 집합**을 상대한다.
- 해시 기반이라 차량 생성 순서와 무관하고, 기존 코드를 고치지 않고 래퍼 안에서 계산할 수 있다(`EVState.ev_id`만 있으면 된다).

참여 여부는 **진입 시점에 고정**한다(정적). 메모의 동적 참여율(엔진 정확도에 반응하는 p)은 같은 u_i에 **시각별 임계값 p(t_entry)**만 바꾸면 된다. 중첩과 공통 난수가 그대로 유지되므로 다음 단계로 둔다.

### 3.3 수락

DESIGN §2.3대로 **참여자는 배정을 그대로 따른다.** 이번 단계에서는 p가 유일한 행동 제약 손잡이다.
v1의 수락 보너스 κ는 실측 근거가 없는 두 번째 손잡이라서 **후속 민감도**로 미룬다. 그때도 같은 ε를 쓰면 이 구조를 확장할 수 있다.

### 3.4 비참여자를 UE가 아니라 MNL로 두는 이유 (DESIGN §2.3과의 차이)

- UE는 하루 전체를 열거하는 **오프라인 균형**이다(`_run_ue`). Δt 루프에서 일부 차량만 UE로 움직이게 할 방법이 코드에 없다.
- DESIGN §1.2는 UE를 "모든 엔진보다 정보가 많은 참고 천장"으로 정의하고, 재현 검증 전에는 "현실"이라 부르지 말라고 한다. 비참여자(=현실 운전자)를 UE로 두면 이 정의와 충돌한다.
- MNL에서 θ→∞이면 S0(현재 바닥)와 같아지므로, 기존 바닥과 연속성이 유지된다.

→ **이 차이는 DESIGN §2.3을 벗어나는 결정이므로 팀 합의가 필요하다** (§6 질문 2).

### 3.5 참여율이 엔진에 주는 영향 (코드로 확인한 부작용)

- **S1+ 예약 원장**은 엔진 정책만 쓴다(`s1.py:136` `ledger.book`). 시뮬레이터는 원장을 쓰지 않는다. 그래서 비참여자의 도착은 원장에 **보이지 않고**, 엔진은 화면 대기(`StationView.wait_min`, 실제 큐 전체)로만 그들을 본다.
  - 이것이 현실의 "앱은 자기 사용자만 안다"에 해당한다. **p가 낮을수록 엔진이 약해지는 것은 버그가 아니라 측정하려는 효과다.**
- **S4의 재질문**(`reask_en_route`): 주행 중인 비참여자는 답에서 **빼면** 경로를 유지한다(`corridor_sim.py` 398~401행). 래퍼는 이 방식으로 비참여자를 보호한다.
- **Oracle**: 오라클 행에는 비참여자를 포함한 **전원의 실현 도착**이 들어간다. 완전정보라는 정의에 맞다.
- **효과 참여율 보고**: p는 모든 EV에 걸리지만 실제로 의미가 있는 것은 충전이 필요한 차다. 결과에는 "충전 차량 중 참여자 비율"을 따로 적는다.

## 6. 결정이 필요한 것

1. **기반 브랜치**: origin/main에서 새 로컬 브랜치(예: `develop/mnl-ceiling`)를 만들어도 되는가? (로컬 전용, push 안 함)
2. **비참여자 = MNL**: DESIGN §2.3("비참여 = UE 방식")과 다르다. 팀에 공유할 결정이다.
3. **시나리오**: 천장값을 낼 세계를 고른다. 추석 9/25 + EV 15%(메모의 계획)인가? 추석 5%는 혼잡이 거의 없어서(#147) 천장과 바닥이 거의 같게 나올 가능성이 높다.

## 부록 — v1에서 유지하는 것

- **MNL 효용 (1차)**: `V = −(T_charge + β_w·W_screen)`, 이탈 선택지 = `−escape_cost_min`. θ 하나만 보정하고, β_w는 {1.0, 1.5, 2.0}을 스윕한다. 요금·우회시간·편의시설은 데이터 부족으로 제외한다.
- **보정 방식**: 추석 공통 ME 장비 집합 안의 휴게소 점유율 TVD로 보정하고, 설은 계수를 고정한 채 검증한다. MLE는 하지 않는다(선택 집합이 관측되지 않음).
- **"27%"의 정체**: 설 상행 adoption 시나리오에서 UE를 천장으로 둔 격차 축소율 27.5%다(`docs/ladder.md`). 스프린트 메모의 S4 5,963h 표는 저장소에서 출처를 찾지 못했다.
