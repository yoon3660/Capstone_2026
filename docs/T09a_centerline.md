# T-09a 경부선 도로중심선 적재 및 검증

## 1. 데이터 처리 원칙

- 도로공사 `도로중심선_이정_좌표` CSV에서 경부선(노선번호 10/0010)을 추출한다.
- X좌표값은 위도(lat), Y좌표값은 경도(lon)로 사용한다.
- 원본 이정은 `official_offset_km`에 보존한다.
- 시뮬레이션용 이정은 `offset_km`에 저장한다.
- 좌표 이상이 발견되어도 근거 없이 원본 위경도를 수정하지 않는다.

## 2. 이정 불연속 보정

원본 CSV에서 241.1km 다음 이정이 241.7km로 나타났다.

지도상 두 좌표는 인접한 도로 위치로 확인했으며,
프로젝트 합의에 따라 241.7km 이후 이정에서 0.5km를 차감한다.

- 원본 이정: `official_offset_km`
- 보정 이정: `offset_km`
- 보정 후 모든 인접 이정 간격: 0.1km
- 보정 후 전체 이정 범위: 0.0~422.5km

이 보정은 프로젝트의 작업용 거리 기준이며,
원본 이정의 오류 원인 자체가 공식적으로 확인된 것은 아니다.

- 추가 점검: 인접 좌표의 직선거리가 120m 초과

## 4. 노선 및 휴게소 검증

- 구서IC~양재IC 중심선 기준 거리: 415.058km
- 공통 노선 JSON 좌표 수: 4,153개
- 이정 단조 증가 및 좌표·이정 개수 일치 확인
- 실제 중심선 임의 지점 50개의 거리→좌표→거리 왕복 오차: 출력 기준 0m
- 휴게소 35곳 중심선 매칭 완료
- 휴게소 스냅거리 1km 초과: 0곳
- DB의 상·하행 corridor 길이: 각각 415.058km
- DB에서 도로 범위를 벗어난 휴게소: 0곳

기존 노선 길이는 391km였으며, 새 기준과 24.058km 차이가 났다.
새 기준의 결과를 후속 교통류 파라미터 및 셀 분할에 사용할 예정이다.

주의: 415.058km는 보정 이정과 IC 스냅을 통해 산출한
프로젝트의 거리 좌표계 길이이다.
모든 원본 좌표의 실제 도로상 위치가 정확하다는 의미는 아니다.

## 5. 재현 및 실행 순서

필요한 원본:
- 도로공사 `도로중심선_이정_좌표` CSV
- 도로공사 OpenAPI 인증키 (`.env`의 `EVDT_EX_API_KEY`)

원본 CSV는 `data/raw/`에 준비한다.
원본 CSV와 생성된 Parquet는 Git에 포함하지 않는다.
