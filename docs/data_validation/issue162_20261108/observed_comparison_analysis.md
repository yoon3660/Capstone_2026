## 원인: 확인 사실과 가설

### 1. 목적지까지 필요한 양 중심의 충전

확인한 설정은 `habit_soc=0`, 목표SoC 상한0.8이다. 상한0.8은 모든 차가80%까지 충전한다는 뜻이 아니다. `engine/ue_demand.py`는 남은 거리·안전 여유에 따른 목표를 계산하고, 도착SoC보다 필요한 만큼 더 충전한다. 목적지까지 충분한 차량은 필요 충전 수요에서 빠진다.

따라서 '여기서 미리 넉넉히 충전해 두자'는 행동이 부족해 작은 kWh 세션이 늘어났을 가능성이 크다. 다만 실제 출발SoC·목적지·충전 목표가 관측되지 않아 habit 설정 하나가 전체 차이의 원인이라고 확정할 수 없다.

### 2. 같은 에너지를 공급하는 데 걸리는 시간도 다름

분포의 합계 비율인 `총 에너지÷총 기록 충전시간×60`은 ALL 비교에서 실측59.17kW, 모델137.44kW이고, 공통ME에서는 실측59.09kW, 모델122.88kW다. 이는 세션별 출력의 산술평균이나 실제 장비 출력 실측값이 아닌, 각 집합의 에너지/시간 비율이다.

모델 시간은 차량 충전곡선 출력·차량 최대출력·장비 정격출력 중 최솟값으로 계산한다. 따라서 단순히 모든 차량에 정격출력을 그대로 적용한다고 볼 수는 없다. 다만 차종 구성, 충전하는 SoC 구간, 동시형 전력 공유 미반영, 실제 출력 저하, 기록시간 정의 차이가 높은 비율에 기여했을 가능성이 있다. 같은 장비 ID여도 같은 차량·SoC 구간은 아니다.

모델 평균 에너지는 실측의42.9%인데 시간은18.5%다. 적은 에너지뿐 아니라 높은 에너지/시간 비율이 겹친다. 실제 경과시간24.15분과 기록 충전시간22.88분의 차이 약1.27분만 추가해서는 약18.65분의 충전시간 차이를 설명하지 못한다. 이1.27분을 조작시간으로 확정할 수도 없다.

### 3. 목적지·초기SoC·선택이 위치 분포에 함께 작용

이번 설정은 OD 실측 대신 IC 진출 위험률로 목적지를 뽑고, 초기SoC도 가정 분포로 만든다. 이들이 어디서 충전 필요가 발생하는지를 정한 뒤 UE가 충전 계획을 선택한다. 천안삼거리·죽암의 부족은 이 전체 흐름을 점검해야 한다. 선택 엔진만 원인으로 단정하면 수요 생성 단계의 오류를 놓칠 수 있다.

### 4. 공급 수정만으로는 차이가 해소되지 않음

상용16개를 제외한282→266 비교에서 관측28곳 모델 세션은8,346→8,347, 공통ME는1,232→1,436이다. 총량보다 운영사/장비 배정이 이동했다. 등록 신규51개 실제 가동, 고장, 동시형 공유출력, 원본에만 있는 장비 ID 관계는 여전히 불확실하다.

### 5. 충전 혼잡 부족과 교통 정체는 구분

짧은 모델 충전은 동일 도착 수요에서 장비가 빨리 비게 하므로 충전 대기가 작아질 방향으로 작용한다. 다만 이것의 실제 기여율은 통제 실험 전에는 모른다. 이번 실행은 고정80km/h, 날짜별 독립 실행, 단일seed7이므로 CTM 정체 원인·연속 대기열·시드 불확실성을 검증한 결과가 아니다.

## 다음 검증의 우선순위

1. 초기SoC·목적지·목표 충전량을 분리해 kWh 부족의 발생 지점을 확인한다.
2. 비슷한 장비·차량·SoC 조건에서 충전곡선과 시간 정의, 동시형 공유출력을 확인한다.
3. 천안삼거리·죽암 등 모델ALL이 실측ME보다 작은 지점의 후보·선택·유입을 추적한다.
4. ME/비ME 커버리지와 실제 운영 공급을 확인한 후 전체 건수 보정을 판단한다.
