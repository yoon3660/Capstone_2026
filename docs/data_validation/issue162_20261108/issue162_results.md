## 2. 원본 확보와 검산

사용자가 제공한 `20261014 2026년9월 기후부 충전기 충전이력(상세내역).xlsx`를 지정된 Desktop 경로에서 읽었다. 원본 복사·수정은 하지 않았다. 73,868,553바이트, SHA-256 `50716c25032348ed9ea1bc8794f33faf9639155d85565bf3312beee6c522ef04`. 재추출 전후 동일하다. [공식 게시물](https://ev.or.kr/nportal/board/generalView.do?ARTC_ID=23358&boardType=publicdata&curPage=1&searchValue=)은 출처 참조이며 공식 서버 첨부와 바이트 동일성까지 검증한 것은 아니다.

#64 XML 행 파서를 재사용했다. 시트 dimension이 A1이므로 일반적인 자동 크기 추정에 의존하지 않았다. 원본 616,206행을 읽어 35곳 명칭·방향 기준과 9/18 충전소 ID로 연결했다. 날짜는 KST로 해석하며 시간대 필드가 따로 있다는 뜻은 아니다.

- 추석 시작 범위: **2026-09-24 00:00 이상~09-28 00:00 미만**. 시작이 범위 안이면 종료가 밖이어도 시작 건수에 포함한다.
- 원본 충전소 ID 접두부는 전부 ME. **다른 운영사까지 포함하는 전체 고속도로 거래라고 보지 않는다.** 내장 SQL의 거래 필터·마스터 조인으로 인한 미포함 범위는 남아 있다.
- 추석 4,480행 / 원본 행 번호 4,480개 / 완전 중복 0 / 종료 결측 0 / 음수·결측 충전량 0.
- 0kWh 33건은 원본대로 보존. 경과시간 0인 2건은 시작 건수에 포함하고 양수 경과시간 분포에서만 제외. 기록 충전시간 0은 5건이다.
- 기록 충전시간이 시작~종료보다 긴 96건은 숨기지 않았다. 이전 진단에서 차이는 모두 1분 이내였으며 정의·반올림 영향 가능성을 별도 표시한다.
- 경과시간 120분 초과 8건도 임의 제거하지 않았다. 원본 오류인지 장시간 기록인지 구분할 근거가 없다.
- 관측 28곳, 미관측 7곳. 망향 DOWN·죽암 DOWN·황간 DOWN·경주 DOWN·통도사 DOWN·칠곡 UP·옥천 UP은 **N/A**이며 0건으로 비교하지 않는다.
- 35곳×96시간=3,360행 시간표를 만들었다. 관측 28곳의 2,688셀 안에서 기록이 없는 시간만 0을 채웠다. 합계 4,480건 및 kWh 합계가 세션 원장과 일치한다.
- 기간 전 시작하여 넘어온 **10건**은 충전 시작 건수에 더하지 않고 시간창 안의 경과 구간에만 포함했다. 기간 안에 시작하여 밖에서 끝난 10건은 전체 세션 분포와 시간창 내 구간 합계를 구분했다.

원본 필드 정의·SQL 한계는 [기존 원본 검토](../issue162_validation.md)와 [내장 SQL](../sp5_charging_source_sql.txt)에 연결했다. 충전 시작 시각은 대기열 도착 시각이 아니다.

**266은 실제 동시 충전 가능한 물리 포트 266개가 확정됐다는 뜻이 아니다.** 9/18 등록 레코드당 1슬롯, 정격출력 독립 공급, 연휴 가동을 가정한다. 상용차 제외 후 DOWN145/UP121이다. 출력 공유·고장·개통 시점은 별도 불확실성이다. 9/18 상태코드는 1/2/3/5/9로 섞여 있어 모든 장비가 당시 정상 대기였다고 주장하지 않는다. 9/18 상태 하나로 추석 4일 내내의 가동 여부도 확정할 수 없다. 과거 취소 공고 4건의 기록은 삭제하지 않았으며, 등록 자체를 개통 증거로 대체하지 않았다.

상용차 16개는 #64의 실제 채택 ID 215개와 대조하고, 2026년 등록 제외 51개와 나눠 확인했다. 추풍령 양방향·통도사 DOWN·언양 UP에 각 4개이며 [제외 장비 원장](excluded_commercial16.csv)에 남겼다.

9월 이력에는 있으나 9/18 공급 명부에 없는 ID는 월 전체 **4쌍**이다: 서울하이패스센터 `ME22B311/81`, 옥천만남 `ME18C506/01`, 양산 UP `ME19D201/01·02`. 모두 **9/1 기록부터 존재**하므로 단순히 9/18 이후 새로 설치됐다고 해석할 수 없다. 그중 추석에는 3쌍에서 77건(서울하이패스센터22, 양산55)이 관측됐다. 이름·방향으로 실측 원장에 보존하고, 명부 ID와 별도 장비라는 근거가 없으므로 모델 공급에는 더하지 않았다. 장비 교체·명부 누락·ID 변경 여부는 미확정이다.

이력 95개 관측 ID 중 공통 집합은 **92개**, 해당 실측은 **4,403건**이다. 새 장비에 2월 세션 분포를 붙이거나, 이름이 같다는 이유로 원본 ID를 다른 ID로 바꾸지 않았다.

공유 DB는 같은 장소·출력·타입을 묶는 구조라 원본 ID를 추적할 수 없었다. **docs 안의 DB 복사본만** 해당 중복 금지 제약을 풀어 개별 ID로 구성했다. 총 정격출력별 대수는 282 참고 설정에서 공유 DB와 일치함을 확인했다. 이후 16개만 제외했다. 개별 ID 순서 변화가 동률 장비 선택에 영향을 줄 수 있어 #147 실행의 비트 단위 재현이라고 부르지 않는다.

## 4. 생성 방법과 실행 범위

#64의 흐름인 **원본→휴게소 매핑→시작/경과 구간 집계→동일 날짜 UE→실측 대조**를 따랐다. 공용 엔진·모델 알고리즘은 수정하지 않았다. 원본 이력을 그대로 모델에 입력해 같은 값을 출력시키는 검증은 하지 않았다.

모델 입력은 추석 교통량으로 생성한 EV이며 EV 비중5%, seed7, holiday 출발 SoC, `habit_soc=0`, 목표 상한0.8, 기존 차종·충전곡선, 고정 주행속도80km/h, `MAX_POWER_IDLE`, UE 최대50회·gap0.8%를 사용했다. EV 비중·SoC·목적지 위험률은 가정이고 9월 충전이력으로 관측된 값이 아니다. OD 실측은 설정하지 않았다. 일별 기온은 16개 지점·시각 표본 평균이지 정식 24시간 평균이 아니다.

주 결과는 4일×양방향, **8회 모두 DONE**. 282개 참고 실행도 8회 완료했다. 단일 시드 결과이므로 시드별 범위나 신뢰구간은 제시하지 않는다. #147에는 공유 충전 이벤트 파일이 없어, 확보한 #146 마스터·교통 입력과 현재 공용 UE로 만든 **새 로컬 기준선**이다. #147의 요약값을 복제했다고 주장하지 않는다.

각 날짜는 독립 실행이다. 날짜를 넘긴 시작은 실제 달력 날짜로 재배치했지만 다음 날 실행의 대기열과 연결한 연속 96시간 재현은 아니다. 9/23 모델 차량의 이월도 없다. 자정 부근 건수·동시 세션 해석에는 이 한계가 있다. 실행 로그의 설명 문구 중 '2026 설 재현'은 공통 레이어 표시의 잔존 문구이며 실제 사용 파일·일자는 `config_*.yaml`, `temperature_samples.csv`, `run_manifest.csv`로 확인한다.

첫 시도는 Windows 출력 인코딩이 경고 기호를 기록하지 못해 FAILED였다. UTF-8 출력으로 바로잡고 새 run ID로 다시 실행했다. 실패 이력은 보존하고 비교에는 DONE 8개만 사용했다.

## 6. 왜 차이가 나는가: 확인 사실과 추론

1. **확인: 모델 충전량이 작다.** 기본 `habit_soc=0`이므로 일정 잔량까지 충전하려는 목표가 없고, 거리·예비량에 따른 필요 충전량을 계산한다. `engine/ue_demand.py`의 `calculate_target_soc` 호출과 설정으로 확인했다. **추론:** 실제로 여유 있게 더 충전하는 행동을 충분히 담지 못해 kWh·충전시간을 함께 낮출 가능성이 크다. 원인별 기여율이나 habit 목표값은 이번에 보정하지 않았다.
2. **확인: 위치 분포가 다르다.** 천안삼거리·죽암 UP 부족, 언양 UP 등 집중이 보인다. **추론:** 목적지를 IC 위험률로 뽑는 방식, 출발 SoC, 필요 충전 판정, UE 선택이 함께 작용할 수 있다. 충전 이력에는 출발지·목적지·초기 SoC가 없어 하나를 확정할 수 없다.
3. **확인: ALL은 과다, 공통ME는 과소다.** 비교 모집단과 운영사 배정이 총량 판단을 크게 바꾼다. EV 비중을 낮춰 ALL 건수만 맞추는 보정은 금지해야 한다. 실제 비ME 로그 확보 전에는 총 EV 충전 수요가 얼마나 과다한지 확정하지 않는다.
4. **확인: 주행은80km/h 고정이고 모델은 한산하다.** 실제 교통 정체·도착 지연·연속 대기열 재현을 검증한 실행이 아니다. 짧은 충전시간은 혼잡 부족에 기여할 수 있지만 **이번 충전 비교가 CTM 정체 실패 원인을 증명하지는 않는다.** #160에서 별도 다룬다.
5. **확인: 등록 공급에는 불확실성이 남는다.** 신규51개가 모두 연휴 내내 정상 운영된다는 증거, 동시형 전력 공유, 고장, 누락 ID 교체 관계가 없다. 공급을 실측 피크에 맞춰 조정하지 않고 한계로 남겼다.

## 7. #153·#131에 전달할 결론과 완료 범위

- 원본·기간·35곳 매핑·관측범위·중복/결측 검사·실측 이용 통계·모델 원장·전체/휴게소/일/시간/분포 비교: **로컬 산출 완료**.
- 동일 범위와 정의를 모두 만족한 사전 정확도 기준: 아직 없으므로 임의 PASS/FAIL을 부여하지 않음. 시작 건수·충전량·시간·동시 세션은 **조건부 진단**.
- 실제 대기시간·실제 물리 점유시간·짝지어진 세션 시간 MAE: **검증 불가**. 대기를 충전 기록에서 만들어 내지 않음.

- 후속 우선순위: ① 목표 충전량·목적지 가정이 짧은 세션을 만드는 영향 분리 ② 공통 장비/운영사 커버리지와 누락 ID 확인 ③ 신규·동시형 실제 가동 공급 확인 ④ 충분한 시드와 연속 기간에서 재확인.
- [통합 검증 인계표](validation_handoff.csv)에 수치·범위·판정·한계를 작성했다. #162는 **비교 분석 작업 완료, DT 외적 정확도 확정은 보류**로 인계할 수 있다. GitHub 티켓을 닫거나 수정하지 않았다.

## 민간 충전기 이력 추가 확보 문의 현황

2026-11-10 기준, 한국환경공단에 민간 충전기 충전이력 데이터 제공 가능 여부를 문의한 상태다. 사용자 전달에 따르면 **2026년 11월 23일에 문의 결과가 나올 수 있으나, 회신 일정과 데이터 제공은 확정되지 않았다.** 민간 충전기 자료이므로 제공받지 못할 가능성도 있다.

따라서 현재 검증에는 추가 민간 충전기 이력이 포함되지 않았다. 자료를 확보하면 제공 기간·운영사·장비 범위와 필드 정의를 확인한 뒤 비교를 보완한다. 제공받지 못하면 ME 중심 실측과 모델 ALL의 모집단 차이를 현재 검증의 한계로 유지한다.

## 8. 재현·보존

`prepare.py`는 #64 XML 파서와 기존 9월 진단의 매핑을 재사용하며 모든 출력은 이 폴더에 쓴다. `--resume`은 이미 확보한 월 원장을 사용한다. `prepare_passenger.py`는 실제 #64 ID 명부를 대조해 상용16개를 분리한다. `run_baseline.py --passenger`는 공용 demand builder 입력/결과를 기록하는 래퍼와 공용 runner를 호출한다. 래퍼는 난수·인자·반환값을 바꾸지 않는다. `compare.py --passenger`가 새 원장의 비교표를 생성한다.

공급 DB를 실행 후 덮어쓰지 않도록 검사한다. 재실행은 기존 DONE 결과를 지우는 방식으로 하지 말고 별도 산출 폴더와 run ID를 사용한다. 입력 파일과 코드는 [해시 목록](input_manifest.json), 정합성은 [검산표](quality_checks.json), 작업영역 보존은 [보존 결과](workspace_after.json)를 참조한다. 원본 XLSX·원본 DB 본체·src/config·Git 인덱스의 해시는 유지됐다. 산출물은 docs에만 작성했다. **예외:** 원본 DB를 읽기 전용 연결로 조회하는 과정에서 `data/processed/issue146_chuseok/scenario_master.sqlite-shm` 공유메모리 보조 파일 1개의 메타데이터 변경이 감지됐다. 원본 DB 본체 해시 변화와 docs 밖 Git 상태 변화는 없지만, 이를 'docs 밖 파일 변화 0건'이라고 보고하지 않는다. 보조 파일을 삭제하거나 타임스탬프를 되돌려 숨기지 않았다.
