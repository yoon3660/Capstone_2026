# #146 추석 수요 파이프라인 및 시나리오

2026-09-24~27 경부선 양방향 수요를 기존 설 파이프라인으로 생성했다. 기존 노선·콘존·IC·휴게소·CTM 셀·충전 행태를 유지한다. 파이프라인 구축과 검산을 마쳤으며, **CTM 성능 기준 통과를 의미하지 않는다.** UE·S0~S4 비교 실행은 #147 범위다.

## 구현 및 검산

- `build_chuseok_demand.py`: 기존 VDS 정리·진입량·중간 진출입 함수를 재사용한다. 날짜·방향별 `volume.csv`, `entry_exit.csv`, `through.csv`, `ctm_entries.parquet`, `hourly_od.parquet`, `synthetic_ev.parquet`를 만든다. OD는 가중 기대량이며 CTM 진입량에 추가하면 중복이다.
- `validate_chuseok_inputs.py`: VDS·TCS 범위, 구간 통과량, 공급, CTM 속도·통행시간 및 설 비교 결과를 생성한다.
- 기존 `audit_issue134_readonly.py --chuseok`에 추석 고정 기대값을 추가했다. 구현은 `audit_issue146_readonly.py`로 분리했다. **194개 통과**: 행 수·중복·키 차집합, 원본 재정리, 진출입 재계산, DB 길이·시설·셀 집계, 원본 좌표 재투영을 검사하며 불일치 시 실패한다.
- 콘존132개의 시작·종료 위치 차이0m, DB휴게소35곳의 원본 위·경도 일치, 중심선 재투영 위치 최대 차이 약0.50m. 원본에만 있는 A00088·A00230은 충전 시설 DB의 대상 밖이며 누락 오류로 간주하지 않는다.
- 공통 CTM 검산과 추석 검산에서 5분 기록의 종료 시각을 해당 집계 시간대에 배정하도록 수정했다. 예: 60분→0시, 1440분→23시. 시간 경계 회귀 검사를 추가했다.

## 시나리오

`config/scenario_chuseok_{down,up}[_adoption].yaml` 네 파일이다. 방향별 모형 진입량 최대일을 선택했다.

| 설정 | 하행 | 상행 |
|---|---|---|
| 날짜 | 9/24 | 9/26 |
| `demand.period` | chuseok2026 | chuseok2026 |
| 기온 | 22.98°C | 20.41°C |
| 공급 | 19곳·153기 | 16곳·129기 |

기온은 각 날짜 서울·대전·대구·부산의 00/06/12/18시 실측16개를 동일 가중 평균했다. 전 구간 연속 관측이나 공식 일평균을 뜻하지 않는다. [기상청 출처](https://www.weather.go.kr/w/weather/land/aws-obs.do)를 config 주석에도 적었다.

공급은 **9/18 환경공단 등록 스냅샷 대용치**를 기존 휴게소에 매핑했다. 설 기본 DB와 휴게소별 수량이 모두 같아 합계282기, **차이0기**다. 설의 별도 BASE215 조건과는 다른 비교다. 추석 당일 실제 가동 대수·고장 이력은 미확보다. 792개 CTM 셀은 기존 노선에서 재현되므로 교체하지 않았다.

기본 시나리오 EV5%, adoption10%는 설과 같은 비교 가정이다. 기본 생성기의 4.1% 출력은 민감도·검산용이며 config의 5%/10%와 구분한다. **어느 비율도 실제 경부선 EV 통행 비율로 확정하지 않았다.**

## TCS 사용 결정

진입 시각·대수를 VDS로 고정하고, 목적지 일부에 일별 TCS39·시간별 TCS64를 혼합해 비교했다. 기점 매핑2km 이내, 일별 TCS 기점합≤VDS 모형 진입량인 범위만 사용했다. 나머지는 기존 분포를 유지했다. 9/24 양방향과 9/27 상행은 품질 표시 때문에 시간별 후보에서 제외했다. 시간 라벨이 진입·진출 중 어느 시점인지 미확정이다.

- 일별 혼합8/8, 시간별 혼합5/5에서 기존 구간 통과량 WAPE가 증가했다. 각각 약0.11~1.39%p, 0.24~1.05%p 증가다.
- 기본 `od_profile: null`을 유지하고 config에 이유를 적었다. `load_od_profile`은 수정하지 않았다.
- 기존 `validate_sections.py`를 추석 피크 양방향에도 실행했다. 80km/h·05시 이후 기준 WAPE는 하행9.5%, 상행6.4%다. 혼합 방식 비교는 공통90km/h를 사용했다.
- 대응된 내부 TCS OD의 대·km 부족분은72.1~75.1%다. 기존 설33%와 모집단이 같다는 근거가 없어 결손 증가율로 해석하지 않는다.

TCS34는 입출구 집계 대조, TCS35·39는 일별 OD, TCS64는 시간별 OD로 구분해 사용했다. 이번 검증은 수요 생성에도 쓰인 VDS를 비교 기준으로 사용하므로 독립 예측 검증이 아니다.

## 설 대비 동일 기준 비교

설2/15~18과 추석9/24~27 각4일 양방향이다.

| 항목 | 설 | 추석 |
|---|---:|---:|
| 첫 관측 단면 진입량 | 540,492 | 550,896 |
| 중간 진입 포함 모형 진입량 | 2,695,125 | 3,303,344 |
| 합성 EV: 동일4.1% | 110,502 | 135,436 |
| 합성 EV: 동일5% | 134,754 | 165,160 |

모형 진입량은 첫 단면과 경계별 순증가량의 합이다. 순변화만으로 동시 진입·진출을 각각 식별할 수 없고, 기간별 유효 콘존도 다를 수 있다. 실제 통행 전수나 실제 EV 증가로 해석하면 안 된다.

## CTM 검증 및 미해결 사항

종료 시각 배정을 수정한 최신8개 날짜·방향 결과:

- 속도 MAPE6.80~47.35%, 정체 재현율0~0.0052. 기존 종합 기준(MAPE≤15%, 재현율≥0.5, 오경보율≤0.3)을 충족한 조합은 **0/8**이다.
- 같은 구간·시간의 속도로 환산한 통행시간 MAPE2.04~24.21%. 개별 서울–부산 실측 통행시간과의 비교는 아니다.
- DSRC 잠정 후보와의 통행시간 MAPE10.82~29.13%. 집계 시각 기준 미확정으로 보조 지표다.
- 차량 보존오차 절댓값은0.000001대 미만이다. 차로 수를 매핑한 VDS 최대유량 대용치는1,716대/시간/차로로2,200에 닿지 않았다. 이 값만으로 원인을 단정하지 않는다.

자유속도, 전역·국소 용량, 합류 우선순위, 진입 시차, 초기 도로 차량 수, 속도 산정을 조정해 **110개 실행 결과**를 비교했다. 하행9/24·상행9/25를 보정일로 삼고 다른 날짜를 분리해 확인했으나 속도·통행시간·정체 지표가 함께 일관되게 개선된 후보는 없었다. 일부 후보는 보정일에서 기각해 추가 날짜 검사를 생략했다. 기본 CTM 모수는 변경하지 않았고 `travel_time: fixed`를 유지한다. 실험 코드·상세표·해시는 로컬 보관이다.

5분 입력 정합화, 동적 OD 추정, 관측 동화까지 완료한 것은 아니다. 실제 충전 체류·가동 이력도 미확보다. #147의 결과는 위 수요·공급·통행시간 가정을 명시해 해석해야 한다.

## 팀 재현 절차

원자료·가공본·DB는 기존 `.gitignore` 정책에 따라 커밋하지 않는다. #145 공유 원자료를 `data/raw/issue145_chuseok/`에 배치하고, 기존 설 실행에 쓰는 도로 원본·가공본·DB를 준비한다. 도로 좌표 감사는 `gyeongbu_route.json`의 `meta.raw_dir`에 지정된 IC·휴게소 원본도 읽는다.

추가 참조 입력은 별도 `issue146_reference_inputs.zip`으로 전달한다. 저장소 루트에 풀면 다음 파일이 배치된다. 이 묶음은 원자료를 대신하는 다운로드가 아니라 기존 위치 대응·검산 결과를 고정한 재현용 입력이다.

- `data/processed/issue145_chuseok/reference/`: `chuseok_tcs_all_daily.parquet`, `route_position_crosswalk.csv`, `conditional_engine_position_inputs.parquet`, `travel_time_candidates_14days.parquet`
- `data/processed/issue145_chuseok/`: `kma_observation_samples.csv`, `sep18_gyeongbu_supply_candidates.csv`

저장소 루트에서 실행한다. `--reference-dir`로 참조 입력 폴더를 변경할 수 있다.

```powershell
python scripts/build_chuseok_demand.py --out data/processed/issue146_chuseok
python scripts/validate_chuseok_inputs.py --out data/processed/issue146_chuseok
python scripts/audit_issue134_readonly.py --chuseok --report-dir data/processed/issue146_chuseok/coordinate_audit
```

첫 명령의 기본 EV비율4.1%가 감사 기대값이다. 다른 비율은 `--ev-share`와 별도 출력 폴더를 사용한다. 시나리오 러너는 config의5%/10%로 생성하므로 이 감사용 EV 원장과 혼동하지 않는다.

#147 실행에는 기존 DB 사본에 기존 `seed_vehicles.py --db <사본>`을 적용하고 `EVDT_DB_PATH`를 그 절대 경로로 지정한다. 차종·충전곡선·기온 계수만 기존 seed로 채우며 원래 DB는 보존한다.
