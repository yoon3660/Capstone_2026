# #168 결과 — MNL 세계의 천장값과 기존 천장(27.5%) 비교

**결론은 §5, 예외 규칙은 §2.** 시드 3개 결과라 통계적 확정이 아니라 방향 확인이다.

## 1. 무엇을 비교했나

| 세계 | 바닥 | 천장 | 기준점 |
|---|---|---|---|
| 기존 (27.5%의 세계) | S0 | 완전예측 (`PERFECT_ROLLING`, 1회차 미래 = S1) | UE |
| MNL (이 티켓) | MNL (θ=0.05, w=1, 추석 보정) | MNL 천장 = 같은 완전예측 경로, 1회차 미래 = MNL 바닥, 비참여자 MNL | **같은 UE** |

- **무대**: 설 상행 adoption (`config/scenario_seollal_up_adoption.yaml`, EV 10%, 기회 충전 20%). 27.5%가 나온 무대와 같다
- **시드**: 1~3 (같은 시드끼리 대응)
- **천장 회차**: 최대 2회
- **관측 예측 strength**: 0.30
- **DB**: 원래 `evdt.db`의 사본 (BASE215)
- **비교 지표 — 27.5%와 같은 식**: `UE 기준 격차 축소율 = (바닥 − 천장) / (바닥 − UE)`

UE는 같은 차량·수요로 따로 푼 균형이다. 그래서 바닥을 S0로 두든 MNL로 두든 같은 값이고, 두 세계가 이 끝점을 공유한다.

## 2. 예외 규칙 — 정차 한도 소진 이탈

모든 엔진이 같이 쓰는 충전 판단 규칙의 결함이 있다(`docs/meeting_memo_stranded_escape_20261112.md`). 장거리 차가 SoC 74% 근처에서 5%p씩 찔끔 충전하다 `max_stops`를 다 써 버리고 이탈한다. 이 결함이 비교를 오염시키지 않도록 아래 규칙을 적용했다.

| 규칙 | 내용 |
|---|---|
| **R1 정의** | `reason = no_plan`이면서 그 차의 충전 정차 수가 `max_stops` 이상인 이탈을 **정차 한도 소진 이탈**로 분류한다 (`n_exhausted`) |
| **R2 이중 보고** | 모든 비용 지표를 **기존 총비용**(`total_h` = 체류 + 이탈 × 120분)과 **소진 제외 비용**(`total_ex_h` = 소진 이탈 비용을 뺀 값) 두 기준으로 낸다 |
| **R3 판정** | 두 기준에서 **결론 방향이 같을 때만** 결론으로 쓴다. 다르면 "공통 규칙 결함에 오염됨"으로 표시하고 결론을 보류한다 |
| **R4 수정 금지** | 이 티켓에서는 충전 판단 규칙·`max_stops`·목표 SoC를 바꾸지 않는다. 원인 해결은 회의 메모와 #149로 넘긴다 |
| **R5 이탈 맞춤** | 기존 비교 규칙(`docs/compare_rule.md`, S1 대비 ±35%)을 그대로 적용한다. 어긴 칸은 표시하고 격차 축소율을 결론에 쓰지 않는다 |
| **R6 무대 제외** | 대기가 거의 0인 무대(추석 EV 5%, 9/25 EV 15%)는 천장 비교에 쓰지 않는다. 소진 이탈이 비용의 대부분이라 R3를 통과할 수 없다 |
| **R7 이탈 유형 분해** (2026-11-12 추가) | 이탈을 **정차 소진 / 줄 이탈 / 기타**로 나눠 보고하고, 바닥 → 천장 감소를 체류와 이탈 유형별 몫으로 나눈다. 그리고 이탈 1대 비용 E를 0~8h로 바꾼 격차 축소율을 함께 낸다(E = 0이 체류만). MNL은 이탈 선택지에도 잡음을 줘서 **줄 이탈**을 만들고, R1~R3는 이 유형을 거르지 못하기 때문이다(§3.1). 결론의 **방향**은 E ≤ 4h에서 같을 때만 쓰고, **크기**는 E 범위로 보고한다 |

UE는 계획 전체를 세우므로 소진 이탈이 구조적으로 0이다(#59 테스트). 따라서 R2에서 UE 값은 두 기준이 같다.

**읽는 법**

- **방향은 이탈 가정에 덜 민감하다.** E가 0~2h면 시드 3개 모두 MNL 세계의 격차 축소율이 낮다. 체류만 보면 차이가 오히려 더 커진다(−12.6%p). 이탈을 없앤 몫이 MNL 세계의 축소율을 **부풀리는** 쪽이기 때문이다. E가 4h를 넘으면 방향이 흐려진다
- **크기는 이탈 가정에 크게 기댄다.** MNL 세계의 축소율은 E에 따라 7%에서 41%까지 움직인다. "약 19%"는 E = 2h라는 가정 위의 한 점일 뿐이다
- **MNL 바닥의 줄 이탈(약 4%)은 검증하지 않은 값이다.** θ = 0.05면 잡음 크기가 약 20분이다. 이 무대는 충전 비용(대기 + 충전)이 60~100분이라 이탈 비용 120분과 잡음 범위 안에서 겹친다. 그래서 줄 이탈이 많이 생긴다. 보정 무대인 추석은 대기가 거의 0이라 이 현상이 드러나지 않았다(θ = 0.05에서 48대)

### 3.2 개선 1 — 이탈 판정을 S0 규칙으로 (2026-11-12, 구현·스모크만)

`MnlSettings.escape_mode` 를 추가했다. 기본값은 `"s0"` 다.

- **이탈할지**: 잡음 없는 S0 비용(대기 + 충전)의 최솟값이 이탈 비용보다 비싸면 이탈한다. S0와 같은 판정이다
- **어디서 충전할지**: 이탈하지 않는 차만 MNL로 휴게소를 고른다
- **위의 §3·§3.1 결과는 `"noisy"`(이탈에도 잡음)로 낸 값이다.** `"noisy"`는 민감도용으로 남겼다
- **테스트로 고정한 것**
  - θ = ∞이면 두 방식 모두 S0와 같다
  - `"s0"`이면 θ(0.01~1)와 w(1.0·1.5)에 관계없이, 누가 이탈하는지가 S0와 한 대도 다르지 않다

**스모크 (설 상행 adoption, 시드 1, 바닥만):**

| 바닥 | 총비용 | 체류 | 이탈 (줄 · 소진) | 평균 대기 |
|---|---:|---:|---:|---:|
| S0 | 7,242h | 6,654h | 294 (240 · 53) | 36.7분 |
| MNL `"noisy"` (§3의 값) | 6,790h | 6,122h | 334 (321 · 12) | 32.4분 |
| **MNL `"s0"`** | **7,114h** | **6,622h** | **246 (233 · 12)** | 35.8분 |

- S0와 `"noisy"` 값은 §3의 시드 1 실행과 같다. 재현 확인이다
- `"s0"` 방식에서 MNL 바닥의 이탈은 S0 대비 0.84배로, ±35% 안이다. 선택이 퍼지면서 줄이 줄어 오히려 이탈이 적다
- **바닥 차이가 크게 줄었다.** S0보다 452h 싸던 것이 128h로 줄었고, 체류는 32h 차이뿐이다. 앞선 "MNL 바닥이 더 싸다"의 대부분은 잡음 이탈이 부하를 덜어 준 몫이었다
- 참고(시드 1, 천장은 기존 값을 그대로 둠): UE 기준 격차 축소율은 기존 29.0%다. MNL `"s0"` 바닥에서는 22.6~27.0%다. 천장을 MNL 천장으로 두면 22.6%, 기존 완전예측으로 두면 27.0%다. **시드 1개이고 천장을 다시 돌리지 않았다.** 판정은 개선 3의 재실행으로 한다

### 3.3 개선 2 — 설 충전이력(#167)으로 θ 재보정 (방법, 실행 중)

**원칙.** 실측 재현성 검증은 설 충전이력으로만 한다. 추석 θ = 0.05는 잠정값이었다(`mnl_calibration_168.md` 상단).

**MNL을 설 시나리오에 붙이는 방법.** #167이 S0를 돌린 것과 같은 20개 시나리오(2/13~2/22 × 상·하행, BASE215, EV 5%, 가정 레이어 없음)를 쓴다. `scripts/calibrate_mnl_seollal.py`가 아래 순서로 처리한다.

1. **설정**: #64 UE 실행에 쓴 그날의 `config.yaml`을 그대로 읽는다. 2/13 하행과 2/17 상행은 연구실 폴더, 나머지 날은 `ue_daily_base215/<방향>/runs/…`에 있다
2. **DB**: #64 연구실 `isolated.db`를 스크래치 폴더에 백업 사본으로 떠서 쓴다(`EVDT_DB_PATH`). 원본은 읽기 전용이다
3. **공급**: `sp3_64_daily_base215_runner.adapter`로 충전기를 BASE215로 덮는다. #167 S0와 같은 장치다
4. **세계 준비**: `run_mnl_world.prepare()`. run·DB 기록은 남기지 않는다
5. **정책 교체**: `run_cell(p=0)`으로 모든 차가 `MnlPolicy`를 쓴다. 같은 세계에서 S0(θ=∞)와 θ 7개 × w 2개를 돌린다. 이탈은 S0 규칙이다(개선 1)
6. **휴게소 대응**: 모델 `station_id`를 #64 `read_station_lookup`으로 휴게소 이름 key로 바꾼다
7. **비교**: `data/processed/issue167_seollal/seollal_observed_station_day_hour.csv`와 비교한다. 그날 시작한 충전만 세고, 관측 휴게소 안 점유율 TVD를 날짜·방향별로 낸 뒤 실측 시작 건수로 가중 평균한다(#167 `station_given_day`)

- **미리 정한 기준은 통과다.** 두 접기 모두 검증용 날에서 MNL이 S0보다 실측 분배에 확실히 가깝다. "모두가 가장 싼 곳으로 몰리는 S0"는 설 실측과 맞지 않는다
- **그런데 θ가 작을수록, 즉 비용을 덜 볼수록 더 잘 맞는다.** 최적점은 균등 무작위다. θ ≤ 0.02 구간은 TVD 차이가 0.01 안이라 사실상 구분되지 않는다. 그래서 설 재현 무대로는 θ를 식별할 수 없다
- **원인 1: 이 무대는 대기가 거의 0분이다.** 비용 차이가 충전시간에서만 나고, 충전시간은 가장 가까운 휴게소가 가장 짧다. 그래서 비용을 볼수록 앞쪽 휴게소에 몰린다. 대기 반응을 볼 수 없으니 w도 식별되지 않는다
- **원인 2: 충전 규칙 결함과 얽혀 있다.** S0는 가까운 곳에서 찔끔 충전을 반복하다 정차 한도에 걸린다(소진 이탈 2,981대, 충전 시작 34,002건). θ가 작으면 먼 곳도 골라 한 번에 많이 넣으니 정차가 줄어든다(197대, 29,018건). TVD 개선의 일부는 이 결함을 피한 몫이다(#149)
- **원인 3: 남은 분배 오차(TVD 약 0.28)는 비용으로 설명되지 않는다.** 휴게소별 매력(ASC), 수요·목적지 생성, 운영사 범위 차이의 몫일 수 있다. 최소 설계 밖이므로 다음 이슈로 넘긴다

**천장 비교(개선 3)에 주는 영향.** 비교 무대(설 상행 adoption)는 평균 대기가 30분이 넘어 θ에 따라 결과가 크게 달라진다. θ → 0은 "줄을 전혀 보지 않는 운전자"라 그 무대에서는 비현실적이다. 따라서 θ 하나를 채택하지 않고 **범위로 보고**한다. 후보는 θ ∈ {0.01, 0.05, 0.1}이다. 0.01은 설에서 구분되지 않는 구간의 위쪽 끝이고, 0.05는 추석 잠정값이다.

**MNL이 확률을 정하는 방식 (휴게소별 가중치가 아니다).** `P(s) ∝ exp(−θ·C_s)`, `C_s = w·대기_s + 충전시간_s`다. 휴게소마다 확률이 다른 이유는 비용뿐이고, 줄이 생기면 그 휴게소의 확률이 내려간다. θ는 모든 휴게소에 같은 값 하나다. 이 실험이 끝나면 구조는 그대로 두고 θ 값만 바꾼다(`ADOPTED_THETA`).

## 4. 확인한 것

1. **기존 결과를 재현했다.** 같은 무대에서 기존 완전예측 26.6%, S2 21.7%가 나왔다. `docs/ladder.md`의 27.5%, 21.0%(시드 14개)와 같은 범위다. 비교 틀이 맞게 짜였다는 근거다.
2. **천장의 절대값은 거의 같다.** MNL 천장 5,951h, 기존 천장 5,917h이고, 시드별 차이가 +196 / −129 / +34h로 방향이 일정하지 않다. 전원이 따르면(p=1) 천장은 완전예측 경로가 정하고, MNL은 1회차 미래로만 들어가기 때문이다.
3. **바닥이 달라졌다.** MNL 바닥(6,768h)이 S0 바닥(7,169h)보다 **시드 3개 모두 266~488h 낮다.** S0는 같은 화면을 본 차가 한곳으로 몰리고 소진 이탈도 많다(46대 vs 12대). 반면 MNL 운전자는 선택이 퍼진다.
4. **그래서 격차 축소율이 낮아졌다.** 27.5%의 세계에서는 26.6%이고, MNL 세계에서는 19.0%다. 두 기준(총비용·소진 제외) 모두 같은 방향이고, 시드 3개 모두 낮아졌다 → **R3 통과.** 다만 시드 대응 차이의 신뢰구간(±13.5%p)이 0을 포함한다. 3개 시드로는 크기를 확정할 수 없다.
5. **p=0.6은 결론에 쓰지 않는다.** MNL 천장 p=0.6은 이탈 맞춤에 미달했다(R5). MNL 세계의 S1·S2(p=0.6)는 바닥보다 나쁘다. 예약 원장에 참여자만 들어가 비참여자의 줄을 못 보기 때문이다(`engine/participation.py` 문서). 이건 참여율 담당 티켓에서 다룰 현상이다.
6. **고정점에 닿지 않았다.** 두 세계 모두 마지막 회차의 배정 변화가 29~37%다. 기존 문서(`DESIGN.md` §8.2: 32~37%)와 같은 성질이다. 천장값은 "상한 추정치"다.

## 5. 판정 — 티켓의 질문에 대해

> MNL로 만든 세계에서 낸 천장이 기존 천장보다 더 유효한 기준인가?

- **천장 자체는 같다.** MNL을 넣어도 완전정보로 도달하는 비용(약 5,900~6,000h)은 바뀌지 않는다
- **달라지는 것은 바닥이다.** MNL 바닥은 추석 휴게소 분배를 S0보다 잘 맞춘다(TVD 0.544 → 0.367, `mnl_calibration_168.md`). 이 실험에서는 비용도 S0보다 5.6% 낮다
  - **단, 이것으로 "더 현실적"이라고 판정하지 않는다 (2026-11-12 정정).** 추석 이력(#162, ME 4,480건)은 판정이 보류된 자료라 실측 재현성 검증에 쓰지 않는다. **실측 재현성 검증은 설 충전이력(#167, 2/13~2/22, 11,405건)으로만 한다.** 추석 결과는 θ를 정하는 데 쓴 잠정값으로만 남기고, 설 검증은 (2/2) A에서 한다
- **따라서 27.5%는 현실적인 개선 여지를 과대평가한다.** S0 바닥이 실제보다 나쁘게(쏠림 + 소진 이탈) 잡혀 있어서다. 현실에 가까운 바닥에서 완전정보 천장이 메우는 몫은 **약 19%**(시드 3개, ±7.4)다. 두 비용 기준에서 같은 방향이다
- **엔진 평가 기준으로는** 바닥을 MNL로 바꾸는 것이 더 유효하다. 천장은 기존 완전예측을 그대로 쓰면 된다. 다만 크기(−7.6%p)를 확정하려면 티켓 완료조건대로 **시드 5개 이상**이 필요하다

> **§3.1 이후 정정 (R7).** 위의 "약 19%"와 "MNL 바닥이 5.6% 싸다"는 둘 다 이탈 1대 = 2h 가정에 기댄다. 이 가정 아래에서 MNL 세계 격차 축소의 69%가 MNL 바닥의 줄 이탈을 없앤 몫이다. 이 줄 이탈은 실측으로 검증하지 않았다.
>
> - **유지하는 것**: "MNL 바닥에서는 완전예측이 메우는 몫이 기존 27.5%보다 작다"는 **방향**. 이탈 비용 0~2h에서 시드 3개 모두 같고, 체류만 보면 차이가 더 크다
> - **보류하는 것**: 크기. 이탈 비용에 따라 7~41%로 움직인다. 그리고 "MNL 바닥이 S0보다 싸다"는 이탈 비용이 7.55h 미만일 때만 성립한다

3. **완전예측은 S2에게조차 시드별 천장이 아니다.** S2가 시드 4·10에서 완전예측보다 싸다. 완전예측은 고정점에 닿지 않은 "상한 추정치"라 시드마다 흔들린다. 그래서 천장 검사는 평균만이 아니라 **시드별 위반 수**도 보고해야 한다
4. **MNL과 무관하다.** p = 1에서는 MNL 세계의 천장도 같은 계산이다

**팀원 README의 경고 중 #168에 직접 걸리는 것 — ⚠3 "바닥–천장 격차 축소율을 쓰지 말 것".** 바닥과 천장의 이탈 대수가 다르면 분모의 모집단이 다르다. 팀원 무대에서는 S0 426대 vs 완전예측 95대다. #168의 27.5% 식도 같은 문제를 안고 있다. #168에서는 S0 243대 vs 완전예측 49대이고, MNL 바닥은 θ에 따라 200~420대다. 그래서 #168의 격차 축소율은 다음 조건으로만 쓴다.

- R7처럼 이탈 비용 범위(E = 0~2h)를 함께 보고한다. E = 0이 체류만이다
- 이탈 차이가 큰 칸끼리의 축소율은 **방향**만 쓰고 크기는 쓰지 않는다
- 판정 문서(`docs/decision_mnl_adoption_168.md`)의 격차 축소율 칸도 같은 조건을 단다

## 5.3 스프린트 노트 "적절한 천장"과 구현의 대응 (2026-11-12)

| 노트의 내용 | 구현 상태 | 차이 / 빠진 것 |
|---|---|---|
| "오답이 있던 시나리오를 끝까지 돌린 뒤, 정답지를 들고 처음부터 맞춰본다" | **구현됨.** `PERFECT_ROLLING`이 이 방식이다. 1회차 미래는 S1 실행(기존 세계)이나 MNL 바닥 실행(MNL 세계)의 실제 도착이고, 이후 회차는 직전 회차의 도착이다 | 고정점에 닿지 않는다(배정 변화 29~37%). 그래서 "상한 추정치"다 |
| 후보 1: 완전예측 = 오라클 정보 + 우리 엔진 | **구현됨.** 다만 엔진은 **S2** 구조다 | 노트의 "S4에 근접(준 천장)"은 실제로는 **S4가 더 싸다**(위반 의심, §5.2). 그래서 완전예측-S3/S4 포락선이 필요하다 |
| "운전자의 이기적 판단을 배제하고 중앙 관제가 배정한 결과" | **일치하지 않는다** | 완전예측은 S2 정책이다. 원장과 완벽한 예측을 보지만 **차마다 자기 비용**을 최소화한다. 네트워크 전체 비용을 최소화하는 중앙 배정은 사후 최적해(SO·MILP)다 |
| "완전예측 결과를 그대로 사후최적해로 사용" | **용어 주의** | 완전예측은 사후 최적해가 아니라 휴리스틱 + 완벽 정보다. 사후 최적해(MILP, DESIGN §8.3)는 **구현하지 않았다**(범위 밖) |
| 후보 2: SUE(Daganzo & Sheffi 1977)로 모방 세상을 만든다 | **1단계(모드 A)만 구현했다.** 근시 MNL: 지금 화면의 대기에 인지 오차를 더해 고른다. θ → ∞이면 S0다 | **SUE(모드 B)는 계획된 2단계다.** 설계 때 "모드 A를 먼저 하고, MNL 도입이 정해지면 모드 B(SUE)를 추가 구현"으로 정했다. 모드 B는 도착 시점의 실제 대기에 인지 오차를 더한 확률적 **균형**이고, θ → ∞이면 UE다(`ue.py`의 고정점 풀이 재사용). 이 결정이 설계 문서 v2와 티켓에서 빠져 있어 여기와 `ticket_mnl_extra_params.md`에 다시 적는다. 지금 결과를 "SUE 결과"라고 부르지 않는다 |
| "그로부터 사후최적해를 구한다" | **구현됨** (MNL 세계의 완전예측) | p=1이면 천장은 기존 세계와 같은 계산이다. **MNL은 천장이 아니라 바닥을 바꾼다.** 사후 최적해(MILP)는 구현하지 않았다 |
| "정교한 튜닝 없으면 신뢰성 급감 → 프로젝트 파라미터 인용 가능한지" | **확인함** | 설(#167) 교차 검증에서 S0보다 확실히 낫다. 하지만 θ는 식별되지 않았다(최적점이 균등 무작위). 노트가 걱정한 신뢰성 문제가 실제로 나타났다. ASC 등 추가 모수는 다음 이슈로 넘긴다 |
| "UE는 정답뿐이라 사후최적해를 구할 수 없다" | **일치** | UE는 27.5% 식의 끝점(분모)으로만 쓴다 |
| "추석 데이터로 모델 비교 후 적합한 천장 탐색" | **바뀜** | 실측 재현성 검증은 설 충전이력(#167)으로만 한다. 추석 이력은 판정 보류 자료다 |

**아직 빠진 것.**

1. 완전예측-S3/S4와 천장 포락선. 기존 코드를 고치지 않고 `_inject`로 예측만 `OracleForecast`로 바꿔 만들 수 있다. 팀원의 시드별 값으로 위반이 확정되면 만든다
2. 사후 최적해(MILP). 진짜 하한이다. 다음 스프린트로 넘긴다
3. **SUE(모드 B).** MNL 도입이 정해지면 추가로 구현한다(`ticket_mnl_extra_params.md` A)
4. 노트·발표의 용어 정정: 지금 결과는 "MNL 모드 A(근시 확률 선택)", "완전예측 = 사후최적해"는 "완전예측 = 정보의 천장"으로 부른다

## 7. 재현

```bash
# 공통: EVDT_DB_PATH = evdt.db 사본, --data-root = 원래 저장소 루트
python scripts/run_mnl_world.py --config config/scenario_seollal_up_adoption.yaml --seeds 1 \
    --p 0.6 --stages S1,S2 --rounds 2 --classic --data-root <evdt> --out runs/mnl_world/seollal_up_adoption_cmp/seed1
#   (시드 2·3 도 같은 식)
python scripts/run_mnl_world.py --config config/scenario_seollal_up_adoption.yaml --seeds 1-3 \
    --p 1.0 --rounds 2 --ue --data-root <evdt> --out runs/mnl_world/seollal_up_adoption_cmp/p1_ue
python scripts/run_mnl_world.py --merge runs/mnl_world/seollal_up_adoption_cmp/{seed1,seed2,seed3,p1_ue,p1_ue_resume} \
    --out runs/mnl_world/seollal_up_adoption_cmp/merged
```

`p1_ue`는 시드 2 도중 세션 종료로 멈췄다. 남은 부분은 `p1_ue_resume`(시드 2~3)으로 다시 돌렸다. 병합은 결정적으로 같은 칸의 중복을 하나로 합친다.
