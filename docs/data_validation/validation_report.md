- 선행 문서의 적용 기간·모집단·설정이 이번 평가와 맞는 범위에서 결과를 사용한다. 근거 충돌·버전 차이·누락이 있을 때만 추가 확인 항목으로 분리한다.

이하 전체 검증표의 기존 행과 결과를 유지한다. #64의 선행 검증 상세 이력은 §7에 보완했다. 이 문서는 검증 기록이며, GitHub 완료 체크·후속 이슈 생성·PR 제출을 대신하지 않는다.

## 1. 판정 기준

- **PASS** — *명시한 검사*에 대해 기준 충족. 해당 현실 현상 전체가 적합하다는 뜻은 아님.
- **CONDITIONAL** — 특정 조건·범위에서 사용 가능하나 결측, 보간, 추정, 모집단 제한 또는 시나리오 가정이 있음.
- **FAIL** — 확인된 모순 또는 기존에 사전 정의한 검증 임계값 미달.
- **UNKNOWN** — 관측, 동등 모집단, 원본 계보 또는 타당성 근거가 부족하여 검증 불가.

**PASS 기준의 단위를 혼동하지 않는다.** VDS 키 PASS ≠ 관측값 무결성 PASS, 충전 알고리즘 테스트 PASS ≠ 대기시간 실측 PASS, 셀 생성 PASS ≠ 정체 재현 PASS.

## 4. 코드 검증과 현실 적합성 분리

> **이 절의 시점 주의 (2026-10-15 보강).** 아래 1·2는 **셀 적재 전** 구조 검증 단계의 기록이다. 그 시점 DB는 `cell=0`이었고, 이후 `--write`로 792행을 적재해 `validate`를 다시 통과했다 (§2 · §13 · `data_inventory.md`). **현재 상태는 `cell=792`다.** 두 진술은 모순이 아니라 순서다.

1. `python -m evdt.io.db validate`는 **현재 저장된** 차종 비중 합계, 곡선 0~1 연속성, 휴게소 위치 등의 기본 규칙을 검사한다. `cell`이 0행이면 해당 셀의 `q_max` 검사와 휴게소-셀 매핑은 실제 데이터를 검증하지 못한다 — **적재 전 단계가 그랬다.** 적재 후에는 이 두 검사가 실제 792행을 대상으로 동작한다.

### 8.5 후속 문서의 해석 충돌 — 이번에 확인한 중요 정정

1. **1.5/0.2는 조절 파라미터가 아니다.** `review_20261013.md` §4의 값은 상행47기·3시드에서 **선택 몫÷충전기 몫**으로 계산한 과선택 배율이다. 그 근거만으로 코드의 ‘출력별 선호 가중치1.5/0.2’를 중립화하는 실험을 설계하면 안 된다. 실제 별도 가중치 존재 여부는 별개의 코드 검사다. #64 일부 후속 제안의 가중치 표현은 이 근거 수준으로 정정해 읽는다.
2. **26.3분은 집계 수준을 확인해야 한다.** 리뷰 §3에서 나온 값은 비교가능25개소의 **지점별 점유분/시작건수 비율의 중앙값**이다. 이후 #129/#113 댓글은 이를11,405개 개별 세션의 길이처럼 표현한다. 이 두 통계는 같다고 볼 수 없으므로 개별 세션 보정 목표로 확정하기 전 집계 정의를 정렬해야 한다.
3. **34kWh는 모델 역산값이다.** #129 최신 댓글도 실측 kWh 칸을 ‘?’로 두고 원본 확인을 후속으로 남겼다. #131의 ‘34kWh 실측과 맞음’은 해당 댓글만으로 입증되지 않는다. habit_soc0.80은 보정 후보이며 현실 원인확정값이 아니다.

## 10. 현재 기본 DB ↔ 로컬 YAML 일치 검사 — PASS

검사일: 2026-10-14. 근거: 사용자가 제공한 읽기 전용 Python 검사 실행 출력(LOCAL_NEW). DB: `C:\Users\kimdohyun\dev\evdt\evdt.db`.

**방법:** `default_db_path()`로 결정된 DB를 SQLite `mode=ro`로 열었다. `read_vehicle_classes()`와 `read_temp_efficiency()`가 로컬 YAML에서 생성한 행을 DB 행과 비교했다. 키는 각각 `vclass_id`, `(vclass_id,soc_from)`, `temp_c`. YAML 변환 행에 있는 모든 필드(출처 문자열 포함)를 검사했고, 수치는 `math.isclose(rel_tol=1e-9, abs_tol=1e-9)`, 그 외 값은 직접 동등 비교했다. DB에만 있는 추가 열의 의미 검증은 이 검사 범위가 아니다.

**결론:** 현재 기본 DB의 차량·충전곡선·온도 입력은 현재 로컬 YAML 변환값과 일치한다. §4의 ‘DB 값과 YAML의 1:1 일치는 별도’였던 공백은 이 범위에서 해소됐다. 초기 검증 기록은 이력으로 유지한다.

**적용 한계:** 이 결과는 과거 #64의 `isolated.db`들에 대한 검사가 아니며 현재 로컬 YAML이 조회한 GitHub main 커밋과 동일하다는 증명도 아니다. 실제 차량 구성·충전시간·겨울 성능의 외적 타당성 PASS로 확대하지 않는다. DB나 모델 설정을 수정하지 않았다.
