# T-17 CTM 셀 분할

`src/evdt/world/cell_split.py` · `scripts/seed_cells.py` · 테스트 `tests/test_cell_split.py` (24건)

```bash
python scripts/seed_cells.py                    # 검증만
python scripts/seed_cells.py --write            # 셀이 비어 있을 때 저장
python scripts/seed_cells.py --write --replace  # 기존 셀을 지우고 다시 저장
```

시뮬레이터가 도는 무대다. 이게 없으면 CTM 을 얹을 수 없다.

## 1. 수정된 완료조건

처음 티켓은 `dt = 1분, 최소 셀 1.667 km, 방향당 약 216 셀` 이었다. 구현하고 보니
**현재 데이터로는 세 조건을 동시에 만족할 수 없었다** (§3). 아래가 수정본이다.

- [x] dt = **0.2분** (`config/flow_params.yaml` 의 `dt_min`). 단위는 여전히 분이다
- [x] **셀 목표 길이 L = 1.0 km** (`defaults.cell_length_km`). 차로 병합 임계값
      `min_cell_length_km`(0.5 km)와 **다른 키**다
- [x] **CFL 하한 = max(v_free, w_back) × dt ≈ 0.33 km.** 모든 셀이 이보다 길다
- [x] 앵커: 코리도 양 끝 + 휴게소 offset + 차로수 변경 지점(T-09b)
- [x] 앵커 사이 간격 g 를 floor(g / L) 등분 (최소 1등분)
- [x] 휴게소는 **반드시** 셀 경계. 휴게소끼리(또는 코리도 끝과) L 보다 가까우면 그
      사이는 L 보다 짧은 셀 한 칸이 된다. CFL 하한보다 짧으면 멈춘다
- [x] 차로수 변경 지점은 이웃 앵커와 L 이상 떨어질 때만 앵커. 가까우면 버리고 그
      셀은 걸친 구간 중 **적은 쪽 차로수**
- [x] IC 는 앵커로 넣지 않는다. 좌표 보간용으로만 쓴다
- [x] 셀 경계 4좌표는 T-09a 의 `point_at()` 으로 뽑는다
- [x] 방향당 **약 400 셀, 양방향 약 810 셀** (415 km 노선 기준). 크게 벗어나면
      `cell_length_km` 와 앵커를 의심한다
- [x] 테스트: 모든 셀 ≥ CFL 하한, L 보다 짧은 셀은 보호 앵커 사이에만
- [x] 테스트: seq 연속, 인접 셀 `offset_km_end == 다음 offset_km_start`
- [x] 테스트: 셀 길이 합 == 노선 길이 (오차 1 m 이내)
- [x] 테스트: 모든 휴게소 offset 이 셀 경계와 정확히 일치

기댓값도 바뀐다: cell 테이블 **약 810 행**, dt 0.2분이면 하루 7,200 스텝이라
**하루 약 580만 셀 업데이트**.

## 3. 원래 조건이 왜 불가능했나

### 셀 목표 길이와 CFL 하한은 다른 값이다

| 값 | 뜻 |
|---|---|
| CFL 하한 `max(v_free, w_back) × dt` | 이보다 짧으면 **물리적으로 불가능**. 한 스텝에 차가 셀을 건너뛴다 |
| 셀 목표 길이 L | 계산량과 공간 해상도의 **절충**. 하한보다 충분히 크게 잡는다 |

첫 구현은 둘 다 `defaults.min_cell_length_km` 하나로 읽었다. 그 키는 원래 debug/lanes
에서 **차로 프로파일 병합 임계값**으로 넣은 0.5 km 였다("이보다 짧은 차로 구간은
이웃에 병합"). 그대로 셀 길이로 쓰니 floor(g / 0.5) 등분이 셀을 전부 0.505 km 로
쪼갰고, 양방향 **1,555 셀**(예상 432 의 3.6배), 하루 **1,120만** 셀 업데이트(예상 62만의
18배)가 나왔다.

이건 구현 실수라기보다 **두 결정이 부딪힌 것**이다. #24 리뷰에서 CFL 위반을 고칠 때
dt 를 1.0 → 0.2 로 낮췄는데, 이 티켓은 그보다 먼저 `dt=1분, 셀 1.667 km` 를 전제로
쓰여 있었다. 같은 문제를 반대 방향으로 푼 셈이다.

### 1.667 km 는 서울만남의광장 때문에 불가능하다

서울만남의광장휴게소는 **하행 기점(양재IC)에서 0.559 km** 에 있다. 코리도 끝과
휴게소가 둘 다 셀 경계여야 하므로 0.559 km 셀이 생길 수밖에 없다.

```
"모든 휴게소가 셀 경계"  +  "모든 셀 ≥ 1.667 km"   → 양립 불가
```

실제로 L 을 0.8 km 만 올려도 원래 코드가 `보호된 앵커 사이가 너무 짧습니다: 0.000 ~ 0.559 km`
로 멈췄다. 팀원이 config 값(0.5)을 쓴 것은 1.667 로는 아예 안 돌기 때문이었다.

그래서 규칙을 바꿨다. **짧은 셀은 CFL 만 지키면 물리적으로 문제가 없다.** 휴게소를
경계에 두기 위해 필요한 곳에서만 L 보다 짧은 셀 한 칸을 허용하고, 몇 개인지 보고한다.
지금은 하나뿐이다.

### 가까운 차로수 변경 지점끼리는 예외를 던지고 있었다

T-09b 차로 프로파일의 변경 지점은 최소 0.501 km 간격이다(상행 192.108 ~ 192.609).
원래 코드는 차로수 변경 지점 두 개가 가까우면 "어느 쪽 차로수가 적은지 확인한 후
처리해야 한다" 며 멈췄다.

어느 쪽을 버려도 그 셀의 차로수는 걸친 구간 중 **적은 쪽**이 된다
(`assign_lanes_to_cells`). 그래서 왼쪽부터 훑어 앞의 것을 남기고 뒤의 것을 버린다.
순서가 정해져 있어 결과가 결정적이다.

## 4. 가짜 휴게소가 진짜 코리도에 섞여 있었다

**팀원이 가장 오래 헤맨 문제다. 원인은 리뷰어(나)가 만든 코드였다.**

`scripts/smoke_run.py` 는 배관 확인용으로 가짜 휴게소 3곳(안성·천안·옥천 "(가짜)")을
넣는다. 그런데 **진짜 하행 코리도 `gyeongbu_down` 에 직접** 넣고 있었다. 그리고
`seed_cells.py` 는 `station` 테이블을 코리도 구분 없이 전부 읽었다.

그 결과:

- 가짜 휴게소 3곳이 셀 앵커가 됐다. 셀 경계가 실제 휴게소가 없는 자리에 생겼다.
- 천안(가짜) 92.000 km 는 진짜 천안호두휴게소 91.363 km 와 **637 m** 붙어 있다.
  L 을 조금만 올려도 "보호 앵커끼리 너무 가깝다" 로 멈췄다.
- 이름에 "(가짜)" 가 붙어 있어도 분할 코드는 offset 만 보므로 오류 메시지에는
  숫자만 나온다. **원인이 코드 밖 데이터에 있어서** 코드를 아무리 봐도 안 보였다.

`smoke_run.py` 는 문서에서 실행하라고 안내하는 스크립트라, 한 번이라도 돌린 사람의 DB 는
전부 오염돼 있었다.

### 고친 것

| | |
|---|---|
| 격리 | 가짜 휴게소는 **전용 코리도 `smoke_down`** 에만 둔다. 진짜와 같은 이름공간에 두지 않는다 |
| 가드 | 진짜 코리도를 읽는 모든 곳(`read_station_chargers`, `find_stations_on_route`)이 가짜가 섞여 있으면 **멈추고 무엇이 섞였는지와 지우는 명령을 알려준다** |
| 자동 정리 | `smoke_run.py` 가 실행될 때 진짜 코리도에 남아 있는 예전 가짜 휴게소를 지운다 |
| 정리 스크립트 | `smoke_clean.py` 가 전용 코리도와 예전 방식의 가짜 휴게소를 모두 지운다 |
| 테스트 | 진짜 코리도에 가짜가 있으면 멈추는지, 전용 코리도는 정상으로 읽히는지 |

**조용히 걸러내지 않은 이유:** 한 곳에서만 걸러내면 다른 읽는 곳은 여전히 오염된 채로
돈다. 셀 분할만 고치고 충전소 탐색(T-21)은 여전히 가짜를 쓰는 식이다. 오염 자체를
드러내고 지우게 하는 것이 맞다.

### 이미 오염된 DB

셋 중 하나를 하면 된다.

```bash
python scripts/smoke_clean.py   # 가짜 데이터를 전부 지운다
python scripts/smoke_run.py     # 자동 정리 후 전용 코리도에 다시 만든다
```

셀을 이미 가짜 앵커로 저장했다면 다시 만든다.

```bash
python scripts/seed_cells.py --write --replace
```

## 5. 그 밖에 바꾼 것

- **판단 규칙을 모듈로 옮겼다.** `build_direction_cells` 하나가 한 방향 전체를 만든다.
  완료조건 테스트가 이 함수를 합성 데이터로 검사하므로 차로 프로파일(SHP 필요)이 없어도
  CI 에서 돈다. 스크립트의 런타임 검사는 그대로 두었다 — 실제 데이터에서 한 번 더 본다.
- **`--replace`.** 원래는 기존 셀이 있으면 저장을 거부만 했다. 셀 수가 바뀌면 upsert
  로는 예전 행이 남으므로, 한 트랜잭션 안에서 지우고 넣는다. `station.cell_id` 는
  `ON DELETE SET NULL` 이라 휴게소 행은 지워지지 않는다.
- **`cell_length_km` 는 `estimate_flow_params.py` 템플릿에도 넣었다.** 이 스크립트는
  config 파일 전체를 다시 쓰기 때문에 yaml 에만 넣으면 다음 실행 때 사라진다
  (develop/24 리뷰 항목 8 — config 가 손으로 쓰는 설정이자 생성물이다).
- **노선 길이 대조는 원래 구현에 이미 있었다.** DB `corridor.length_km` 와 경로 파일이
  1 m 이상 다르면 멈춘다. `docs/debug_lanes_log.md` §3-① 에서 "후속으로 넣어야 한다" 고
  적었던 이정축 어긋남 감지다.

## 6. 남은 것

- **dt 를 올릴 여지가 있다.** L = 1.0 km 에 v_free 98 km/h 면 CFL 이 허용하는 dt 는
  약 0.6분이다. 가장 짧은 셀(0.559 km)이 걸리므로 실제 상한은 약 0.34분. 0.2 → 0.3 으로
  올리면 셀 업데이트가 1/3 줄어든다. CTM 을 올린 뒤 계산 시간을 보고 정할 것.
- **`station.cell_id` 를 채우지 않는다.** 휴게소가 어느 셀 경계에 있는지는 offset 으로
  찾을 수 있지만, 스키마에 칸이 있으니 CTM 연결 때 채우는 것이 좋다.
- **IC 를 앵커로.** 팀원 코멘트대로 다음 스프린트에서 고려. 서울 근처 간격 문제는
  §3 의 "짧은 셀 한 칸 허용" 규칙으로 풀 수 있다.
