# 엔진 비교의 규칙 — 이탈을 맞추고 비교한다 (#123)

> 한 줄: **과잉반응 가설은 기각됐다.** 그리고 그 가설이 설명하려던 현상(#119 의
> "관측 예측이 완전 예측을 이긴다") **자체가 없었다** — 이탈을 맞추지 않은 비교였다.
>
> 이탈을 맞추면 순서가 단조롭게 복원된다.
> **S1 6.5% → S2 24.3% → 완전예측 28.8%.** 정보가 많을수록 낫다.

재현:

```bash
python scripts/matched_ladder.py --seeds 1-7          # 이탈 맞춘 사다리 (params 검증 포함)
python scripts/test_overreaction.py --seeds 1-7 --blur-scale 0.4   # 과잉반응 검정
```

## 1. 결과 — 이탈을 맞춘 사다리 (시드 6개)

| | 총대기h | 평균대기 | p95 | 병목칸 | 이탈 | 총비용h | **메운%** |
|---|---:|---:|---:|---:|---:|---:|---:|
| UE (천장) | 742 | 6.1 | 42.8 | 28.8 | 36.7 | 2,499 | 100% |
| S0 (바닥) | 4,853 | 38.2 | 130.9 | 93.7 | 233.2 | 7,439 | 0% |
| S1 | 4,859 | 38.3 | 112.6 | 130.5 | 49.2 | 7,118 | 6.5% |
| **S2 (관측, strength 0.30)** | 3,992 | 31.6 | **103.4** | 113.8 | 56.3 | 6,238 | **24.3%** |
| **완전예측 (벤치마크)** | 3,796 | 30.0 | 113.1 | **92.3** | 54.7 | 6,017 | **28.8%** |

이탈은 S1 대비 **+15% · +11%** 로 맞췄다.

### 지표마다 승자가 다르다

| | 이기는 쪽 |
|---|---|
| 총 사회적 비용 · 병목 칸 | **완전예측** (6,017h · 92.3칸) |
| **p95 대기** | **관측 예측** (103.4분). 완전예측은 **안 움직인다** (112.6 → 113.1) |

완전예측은 **병목 칸을 더 잘 없애고**, 관측 예측은 **최악 구간을 더 잘 깎는다.**
이건 이탈을 맞춘 뒤에도 남는 차이라 진짜다.

## 2. #119 의 헤드라인을 정정한다

`docs/s2_observed.md` 가 *"관측 예측이 S0→UE 격차의 **39.5%** 를 메운다. 완전
예측(28.8%)보다 낫다"* 고 적었다. **틀렸다.**

| | strength | 이탈 | 메운% |
|---|---:|---:|---:|
| #119 가 쓴 값 | 0.50 | **78.1대** (S1 대비 **+59%**) | 39.5% |
| **맞춘 값** | **0.30** | **56.3대** (+15%) | **24.3%** |

관측 예측이 이긴 것은 **45% 더 많이 내보냈기 때문**이다. 맞추면 완전예측(28.8%)이
이긴다.

> **내가 #119 에서 "손익분기 23.5시간이라 이탈 효과가 아니다" 라고 했다.** 그건
> **총 사회적 비용** 기준이었다. **대기만** 보면 이탈 차이가 그대로 남는다. 두
> 지표가 다른 말을 하고 있었고, 유리한 쪽을 인용했다.

## 3. 과잉반응 가설 — 기각

**가설:** 오라클은 **정확해서** 해롭다. 모두에게 같은 (틀린) 미래를 정확히 말해 주니
전원이 같이 피한다.

**대조군:** `BlurredForecast` — 오라클의 **개수를 그대로** 쓰고 **누가 언제 오는지만**
지운다. 정확도는 같고 정밀도만 없앤다.

**미리 정한 기준:** 흐림이 날것보다 총 대기 **5% 이상** 낮으면 확인.

### 결과 (이탈 맞춤, blur_scale 0.4 → 이탈 57 vs 54)

| | 총대기 |
|---|---:|
| 오라클 (날것) | 3,795h |
| 오라클 (흐림) | 3,627h |
| **차이** | **−4.4%** |

기준 미달이고, **시드별로 3승 3패 1무**다.

| seed | 날것 | 흐림 | |
|---|---:|---:|---|
| 1 | 3,674 | 4,035 | ✗ |
| 2 | 3,780 | 3,795 | ✗ |
| 3 | 3,728 | 3,340 | ✓ |
| 4 | 3,824 | 3,038 | ✓ |
| 5 | 3,786 | 3,360 | ✓ |
| 6 | 3,618 | 3,613 | = |
| 7 | 4,155 | 4,210 | ✗ |

> **기각.** 정밀도는 설명이 아니다. 그리고 §2 에서 보듯 **설명할 현상 자체가
> 없었다.** `docs/s2_observed.md` §7 을 그에 맞게 고쳤다.

## 4. ★ 진짜 결과 — 네 번 속을 뻔한 하나의 통로

사다리의 모든 칸이 통로를 하나 공유한다.

> **예측을 비관적으로 만들면 한계 차량이 코리도를 나간다.**
> 나간 차는 충전기를 안 쓰므로 **남은 사람의 줄이 짧아진다.**

이 프로젝트에서 **네 번** 여기에 속을 뻔했다.

| | 이탈 | 어떻게 드러났나 |
|---|---:|---|
| S0 | 294대 | S1 보다 좋아 보였다 (`docs/ladder.md` §3) |
| #119 strength 2 | 847대 | 총비용 최저. **EV 의 12%** 를 내보낸 값이었다 |
| #123 흐림 (초기) | 404대 | 대표 수요가 실제의 **2.4배**라 줄을 과대추정했다 |
| **#119 strength 0.5** | **78대** | **"관측 예측이 완전 예측을 이긴다" 가 여기서 나왔다** |

마지막 것은 **발표 문장까지 갔다가** 여기서 잡혔다.

### 그래서 규칙으로 만든다

> **엔진을 비교할 때는 이탈을 맞춘다.** 못 맞추면 "메운 %" 를 보고하지 않는다.

`scripts/matched_ladder.py` 가 강제한다 — S1 대비 이탈이 35% 넘게 벌어지면
*"이 표의 메운% 를 믿지 말 것"* 을 찍는다.

### 발표에서 쓸 문장

> *"엔진의 개선은 두 통로로 나뉜다 — **배정을 고치는 것**과 **한계 차량을 내보내는
> 것**. 둘째 통로는 이탈 비용 가정에만 기대어 있어서, 우리는 **이탈을 맞춘 비교**만
> 성과로 보고한다."*

## 5. ⚠ 같은 run_id 에 다른 실험을 덮어썼다 (두 번째)

#119 에서 **오라클과 관측 예측이 둘 다 `__S2__`** 라 서로 덮어쓰는 것을 고쳤다.
그러고 **날것 오라클과 흐린 오라클이 둘 다 `__PERFECT_ROLLING__`** 인 상황을 새로
만들었다.

그 결과 `oracle_blur: True, scale: 0.4` 인 런을 **날것인 줄 알고** 표를 만들었다
(완전예측 총비용이 6,017h → 5,926h 로 조용히 바뀌어 있었다).

**`run_params` 에 `oracle_blur` 를 기록해 둔 덕에 잡혔다.** 그런데 분석이
**파케이를 직접 읽어서 `stale_reason` 가드를 우회**하고 있었다.

> **교훈: `runs/<id>/*.parquet` 를 직접 읽으면 재사용 방어가 통째로 꺼진다.**
> `matched_ladder.py` 는 `params_json` 을 먼저 확인하고 다르면 멈춘다.
> 완전예측은 아예 **매번 다시 돌린다.**
