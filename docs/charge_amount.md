# 충전량을 실측 이용률에 맞췄다 — 그리고 결론이 더 단단해졌다 (#112)

> 한 줄: 우리 차들은 **목적지까지 갈 만큼만** 채우고 있었다 (종료 SoC 53%, 체류 9.5분).
> 사람처럼 **가득 채우게** 하니 체류가 2.4배가 되고, **이용률이 실측 33.5% 에 대해
> 31.6%** 로 맞는다.
>
> **그런데도 2026 설 재현의 대기는 여전히 0 에 가깝다.** 결론이 바뀌는 게 아니라
> **가장 큰 반박이 막힌다.**

코드: `world/charge_decision.py` (`habit_soc`) · `scripts/validate_utilization.py`

---

## 1. 충전 쪽에 처음으로 대조할 실측이 생겼다

교통은 실측으로 검증했지만 **충전은 대조할 숫자가 하나도 없었다** (#64).

충전사업자 **워터**가 **2026 설 연휴** — 우리 재현 기간 그대로 — 고속도로 충전소
49곳의 이용률을 공개했다 (오후 12~6시).

| | 실측 |
|---|---:|
| 충전기 7기 이상 | **33.5%** |
| 충전기 2기 이하 | 50.3% |
| 휴게소별 편차 (영동 인천방향) | 용인 46.8% · 문막 13.7% |

**이용률은 우리가 바로 계산할 수 있다** — 스냅샷에 `chargers_busy` 와 `chargers_total`
이 있다. 그리고 이 지표는 **도착수와 체류시간을 한꺼번에** 본다.

```
이용률 = 도착수 × 체류시간 ÷ 충전기수
```

둘 중 하나만 맞으면 안 맞는다. *"충전 수요를 제대로 만들고 있나"* 에 대한 단일 검사다.

---

## 2. 우리는 3분의 1이었다 — 그리고 원인이 이미 적혀 있었다

```
≥7기 이용률   우리 12.4%   실측 33.5%
```

**EV 비중을 올리고 싶어지는 자리다. 그게 함정이다.**

체류 쪽을 보면 원인이 나온다. #82 가 이미 *"미해결"* 로 적어 둔 값이다.

| | 우리 | 실측 (김범일 외 2022) |
|---|---:|---:|
| 충전 시작 SoC | 36.0% | 30% |
| **충전 종료 SoC** | **53.4%** | **85%** |
| ΔSoC | 17.4%p | 55%p |

```
12.4% × (55 / 17.4) = 39.2%      실측 33.5%
```

**3배 부족이 체류시간 하나로 설명된다.**

> ### ⚠ 이것이 모수 맞추기가 아닌 이유
>
> 이용률 하나에 EV 비중·참여율·충전 필요 확률을 **자유롭게 돌리면 항상 맞출 수 있고
> 아무것도 배우지 못한다.** 과적합이다.
>
> 여기서는 **충전 종료 SoC 가 독립적으로 측정된 값**이고, 고칠 곳이 미리 지목돼
> 있었다. **자유 모수를 돌린 것이 아니라 틀린 값을 바로잡은 것**이고, **이용률은
> 맞추는 대상이 아니라 검증 대상**으로 썼다. EV 비중은 건드리지 않았다.

---

## 3. 장치는 이미 있었다 — 꺼져 있었을 뿐

`charge_decision.py` 의 `habit_soc` 가 #82 에서 들어왔고 여섯 시나리오 전부 0.0 이었다.

```python
min(max(required_soc + safety_reserve_soc, habit_soc), target_soc_cap)
```

## 4. 상한은 0.80 이 맞았다 — 실측이 그렇게 말한다

`habit_soc = 0.85` 를 넣고 상한을 둘로 시험했다.

| | 종료 SoC | 충전시간 | **≥7기 이용률** | 실측 |
|---|---:|---:|---:|---:|
| 지금 (필요한 만큼) | 53.4% | 9.5분 | 12.4% | **33.5%** |
| **habit 0.85 · 상한 0.80** | **80.0%** | **23.7분** | **31.6%** | ✅ |
| habit 0.85 · 상한 0.85 | 85.0% | 36.4분 | 49.8% | ❌ 과함 |

**마지막 5%p 가 12.7분을 더 먹는다.** 충전곡선이 0.8 위에서 25.6 kW 로 꺾이기 때문이다
(그 아래는 89.6 kW).

> **설문의 85% 와 계량된 이용률이 다른 말을 한다.** 사람들이 *"85% 까지 채운다"* 고
> 답해도, 고속도로 급속충전기에서 실제로 끊는 지점은 **80% 에 가깝다.** 우리 상한
> 0.8 은 원래 맞았고, 틀렸던 것은 **"필요한 만큼만" 채운 쪽**이다.

### ⚠ 2기 이하 비교는 믿지 말 것

우리 하행 코리도에 충전기 2기 이하 휴게소가 **한 곳뿐**이다 (실측은 전국 49곳).
80.6% vs 50.3% 는 **표본이 1 인 비교**다. 기준표에는 남겨 두되 판단 근거로 쓰지 않는다.

---

## 5. ⭐ 그래서 결론이 바뀌나 — **안 바뀐다. 더 단단해진다**

하행 재현, 같은 시드:

| | 지금 | habit 0.85 | 배율 |
|---|---:|---:|---:|
| 충전 필요 EV | 1,923 | 1,923 | **1.00** |
| **총 체류** | 325.5h | **792.7h** | **2.44** |
| 최대 대기 | 0.93분 | 8.78분 | 9.5 |
| 최악 휴게소 평균 | 0.01분 | 0.75분 | 66 |
| **평균 대기** | 0.00분 | **0.07분** | — |
| **병목 슬롯** | **0** | **0** | — |
| 몰림비 | 4.30 | **2.77** | 0.64 |

**충전 필요 대수는 안 바뀐다** — 충전 규칙은 *얼마나* 채우는지를 바꾸지 *누가* 충전하는지를
바꾸지 않는다. 바뀐 것은 체류뿐이다.

### 이것이 왜 결론을 강화하나

전에는 이렇게 반박할 수 있었다:

> *"대기가 0 인 건 당신들 차가 9분만 충전하고 가기 때문 아니냐."*

**이제 막힌다.** 체류가 2.4배가 되고 **이용률이 실측과 맞는데도** 평균 대기가 0.07분,
병목이 0칸이다. *"2026 설엔 안 막혔다"* 가 **처음으로 충전 측 실측 위에 선다.**

### 몰림비가 내려간 것도 읽을 거리다

**4.30 → 2.77.** 체류가 길어지면 운전자가 붐비는 곳을 **더 적극적으로 피한다** —
UE 가 그렇게 반응한다. **쏠림이 저절로 줄어드는 쪽**이라 엔진이 일할 자리도 줄어든다.

## 5.5 ⚠ 상행이 수렴하지 않았다 — 그리고 원인이 같은 고장이었다

`habit_soc` 를 켜니 **상행 두 시나리오가 모두 UE 수렴에 실패**했다. gap 추이를 보면
종류가 분명하다.

```
상행 균형 (200회):  3.12% ↔ 3.20% ↔ 3.12% ↔ 3.20%   ← 완벽한 2주기
상행 재현  (50회):  2.4% 근처에서 평평 (마지막 30회 기울기 +3e-5)
```

**반복 부족이 아니라 진동이다.** 반복을 늘려도 안 된다.

### 원인 — 점질량이 무차별점을 만든다

전에는 차마다 *"목적지까지 필요한 만큼"* 이 달라 목표 SoC 가 **퍼져 있었다.**
`habit_soc` 를 켜면 **전원이 정확히 80% 를 목표로 한다.** 그러면 같은 휴게소에서
**체류시간이 전부 같아지고**, 무차별해진 차들이 작은 차이에 **한꺼번에 뒤집힌다.**

> **#55 의 기회충전, #78 의 이탈 비용과 같은 고장이다.** 그리고 해법도 같다 —
> **점질량을 분포로 바꾼다.**

### 고친 결과

`habit_soc_sigma` 를 넣어 차마다 잘린 정규분포에서 뽑는다
(목표 SoC 는 상·하한이 있는 양이라 로그정규가 맞지 않는다).

| sigma | 결과 | 반복 | gap |
|---|---|---:|---:|
| **0.00** | **수렴 실패** | — | 2.840% |
| **0.05** | **수렴** ✅ | 40회 | **0.771%** |
| 0.10 | 수렴 ✅ | 40회 | 0.624% |

종료 SoC 평균은 79.6% 로 유지된다. **0 이면 이전 동작 그대로**이고, 여섯 시나리오
전부에 키를 넣었다 — `variant()` 는 yaml 에 있는 키만 덮어쓴다.

### ⚠ 그런데 상행 **균형** 시나리오는 sigma 로도 안 고쳐진다 — 상한이 범인이다

| | gap | |
|---|---:|---|
| sigma 0 · 상한 0.80 | 3.20% | 2주기 진동 |
| sigma 0.05 · 상한 0.80 | **3.02%** | 거의 그대로 |
| **sigma 0.05 · 상한 0.90** | **0.960%** | **3배 개선** (기준 0.8% 에 근접) |

**상한이 분포를 다시 점질량으로 만든다.**

```
habit ~ N(0.85, 0.05) 인데 상한 0.80  →  84% 가 상한에 걸려 정확히 0.800
실측 확인: 종료 SoC 가 정확히 0.800 인 정차 85%
```

흩어뜨린 것이 **천장에서 다시 뭉친다.** 상행 재현은 남은 16% 로 간신히 넘겼고
(gap 0.771% vs 기준 0.8%), 더 어려운 균형 시나리오는 못 넘겼다.

### 그리고 균형 시나리오에는 점질량이 **둘**이다

```
상행 균형 (habit 없이도): 종료 SoC 가 정확히 0.800 인 정차 38%
   ← 기회 충전이 "상한까지 채운다" 라서 (#54)
```

**#55 가 기회 충전의 진동을 이미 적어 뒀는데 그게 같은 자리였다.** habit 을 켜면 두
점질량이 **같은 0.800 에 겹친다.**

### 구조적 문제 — `target_soc_cap` 이 두 가지 일을 겸한다

| 역할 | 실제로는 |
|---|---|
| *"급속충전은 80% 에서 끊는다"* — **행태** | 사람마다 다르다 → **분포여야 한다** |
| *"목표 SoC 상한"* — **결정변수 제약** (DESIGN §2.3) | 진짜 천장 |

**행태를 천장으로 표현하니 분포를 넣어도 천장에서 다시 뭉친다.**

> **고치려면 둘을 분리해야 한다** — `habit_soc` 가 *어디서 끊는가*(분포),
> `target_soc_cap` 은 *넘을 수 없는 선*. 그러면 **기회 충전도 상한이 아니라 habit 을
> 목표로 해야** 맞다. 들른 김에 채우는 사람도 자기가 늘 끊는 지점에서 끊는다.
>
> ⚠ 이건 #54 의 기회 충전 구조를 건드리는 변경이라 **상의하고 진행한다.**

### ⚠ 상행 이용률은 과하다

| | ≥7기 이용률 | 실측 |
|---|---:|---:|
| 하행 (habit 0.85) | **31.6%** | 33.5% |
| **상행** (habit 0.85 · sigma 0.05) | **53.0%** | 33.5% |

실측 33.5% 는 **전국 49곳 평균**이고 노선 편차가 크다 (용인 46.8% vs 문막 13.7%).
그래도 53% 는 높다. **하행은 거의 정확하고 상행만 과하다** — 방향 비대칭의 원인은
아직 모른다. 기록해 둔다.

## 6. 남은 것

- **상행·균형 시나리오**에서도 같은지 — 병목이 있는 유일한 균형 시나리오라 거기서는
  체류 2.4배가 다르게 작동할 수 있다
- **2기 이하 급**을 비교하려면 **상행을 같이** 봐야 한다 (하행엔 1곳뿐)
- 휴게소별 편차 — 실측 3.4배(용인 46.8 vs 문막 13.7) 대비 우리는 29배다.
  **일부 휴게소가 거의 안 쓰인다**는 뜻이고, #59 의 가동률 격차와 같은 이야기다
- `habit_soc` 를 **기본값으로 올릴지** — 올리면 지금까지의 모든 숫자가 움직인다.
  #101 에서 배운 대로 **run_id 가 세계를 구분하지 못하므로** 올릴 때 한 번에 다시 돌려야 한다

python scripts/validate_utilization.py --run <run_id> --stations

통과 기준은 **결과를 보기 전에** 정해 커밋했다 — 각 급이 실측의 ±30% 안,
