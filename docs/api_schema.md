| 항목 | 내용 |
|---|---|
| 제공 기관 | 한국환경공단 |

| API | `getChargerInfo` |

| 요청 방식 | GET |
| 응답 형식 | JSON |
| 참고 문서 | 한국환경공단 전기자동차 충전소 정보 OpenAPI 활용가이드 v1.25 |

### 1.1 요청 파라미터

| 파라미터 | 설정값 | 의미 |
|---|---|---|
| `serviceKey` | `.env`에서 로딩 | API 인증키 |
| `kindDetail` | `C001` | 고속도로 휴게소 |
| `dataType` | `JSON` | JSON 형식으로 응답 |
| `numOfRows` | `1000` | 페이지당 최대 요청 건수 |
| `pageNo` | `1`부터 순차 증가 | 전체 데이터 페이지 조회 |

- 샘플 수집 시에는 `numOfRows=10`을 사용하였다.
- 전체 수집 시에는 `numOfRows=1000`으로 요청하고, `totalCount`를 기준으로 마지막 페이지까지 조회하였다.
- 인증키는 `.env`에 저장하고 코드 및 문서에 직접 기록하지 않는다.
- `kindDetail=C001`은 전국 고속도로 휴게소를 의미한다. 경부고속도로만 선택하는 조건은 아니다.

## 3. API 응답 스키마

### 3.1 JSON 응답 구조

API 응답은 다음과 같은 구조를 가진다.

```json
{
  "items": {
    "item": [
      {
        "statNm": "김천(부산) 휴게소",
        "statId": "ME178004",
        "chgerId": "01",
        "lat": "36.129385",
        "lng": "128.164209",
        "output": "50",
        "kind": "C0",
        "kindDetail": "C001"
      }
    ]
  },
  "resultCode": "00",
  "resultMsg": "NORMAL SERVICE.",
  "totalCount": 2088,
  "pageNo": 1,
  "numOfRows": 10
}
```

위 JSON은 응답 구조를 설명하기 위해 충전기 필드 일부만 표시한 예시이다.

- `items.item`은 충전기 데이터 배열이다.
- 배열의 원소 하나는 충전기 데이터 한 건에 해당한다.
- 같은 충전소에 여러 충전기가 있으면 `statId`가 동일하고 `chgerId`가 다를 수 있다.

### 3.2 최상위 응답 필드

| 필드명 | 자료형 | 의미 |
|---|---|---|
| `resultCode` | string | API 처리 결과 코드. 정상 응답은 `00` |
| `resultMsg` | string | API 처리 결과 메시지 |
| `totalCount` | number | 요청 조건에 해당하는 전체 데이터 건수 |
| `pageNo` | number | 현재 페이지 번호 |
| `numOfRows` | number | 페이지당 요청 건수 |
| `items` | object | 충전기 목록을 포함하는 객체 |
| `items.item` | array | 충전기 데이터 배열 |

자료형은 실제로 확인한 JSON 응답을 기준으로 작성하였다.

**자료형 주의사항**

실제 JSON에서는 위도, 경도, 충전용량도 다음과 같이 문자열로 제공된다.

```json
{
  "lat": "36.129385",
  "lng": "128.164209",
  "output": "50"
}
```

이 값들은 원시 데이터 수집 단계에서는 변환하지 않는다. 이후 DB 적재 단계에서 필요한 자료형으로 변환한다.

일부 필드에는 빈 문자열이 들어올 수 있으므로, 후속 처리 시 누락값과 빈 문자열을 확인해야 한다.

### 3.4 주요 코드 및 식별 규칙

| 항목 | 값 | 의미 |
|---|---|---|
| `kind` | `C0` | 휴게시설 |
| `kindDetail` | `C001` | 고속도로 휴게소 |
| `resultCode` | `00` | 정상 응답 |
| `delYn` | `Y` / `N` | 충전기 삭제 여부 |
| `limitYn` | `Y` / `N` | 이용자 제한 여부 |

식별 규칙:

- `statId`: 개별 충전소 식별
- `(statId, chgerId)`: 개별 충전기 식별

예시:

| 충전소명 | statId | chgerId |
|---|---|---|
| 김천(부산) 휴게소 | ME178004 | 01 |
| 김천(부산) 휴게소 | ME178004 | 02 |
| 김천(서울) 휴게소 | ME178005 | 01 |

김천(부산) 휴게소와 김천(서울) 휴게소는 이름이 비슷하지만 서로 다른 충전소 ID를 가진다.

### 3.5 충전기 상태 코드 관련 주의사항

활용가이드에 명시된 상태 코드는 다음과 같다.

| stat | 의미 |
|---|---|
| 0 | 알 수 없음 |
| 1 | 통신 이상 |
| 2 | 사용 가능 |
| 3 | 충전 중 |
| 4 | 운영 중지 |
| 5 | 점검 중 |

실제 수집 데이터에서는 `stat="9"`도 확인되었다.

첨부된 활용가이드 v1.25에서 해당 값의 의미를 확인하지 못했으므로, `9`를 임의로 고장이나 운영 중지로 해석하지 않는다. 별도 확인이 필요하다.

## 4. 수집 과정에서 발견한 사항

### 4.1 고속도로 필터링 범위

`kindDetail=C001`을 적용하면 전국 고속도로 휴게소 충전기 데이터를 조회할 수 있다.

그러나 경부고속도로 소속 여부를 나타내는 전용 필드는 확인되지 않았다.

따라서 경부고속도로 본선에 속하는 휴게소만 선택하려면 별도의 휴게소 기준 목록 및 위치 검증이 필요하다.

### 4.2 상행·하행 구분

일부 충전소명에는 방향을 나타내는 정보가 포함되어 있다.

예시:

| 충전소명 | 방향 |
|---|---|
| 김천(부산) 휴게소 | 서울 → 부산, 하행 |
| 김천(서울) 휴게소 | 부산 → 서울, 상행 |

다만 모든 충전소명에 방향 정보가 포함되어 있다고 보장할 수 없으므로, 최종 방향 분류에는 추가 검증이 필요하다.

### 4.3 충전기 상태 정보의 한계

API가 반환한 `stat`과 `statUpdDt`는 수집 데이터에 포함된 충전기 상태 및 갱신 일시이다.

이를 과거 설 연휴의 충전기 상태라고 해석해서는 안 된다.

또한 실제 응답에서 활용가이드에 설명되지 않은 `stat=9`가 발견되었으므로 상태 코드 해석 시 주의해야 한다.

### 4.4 충전기 수와 충전소 수의 차이

이번 수집에서 확인한 충전소 수는 595곳, 충전기 데이터 수는 2,088건이다.

하나의 충전소에 여러 충전기가 존재할 수 있기 때문에 충전소 수와 충전기 수는 일치하지 않는다.

본 수집 결과는 전국 고속도로 휴게소 기준이며, 경부고속도로 충전기 수를 의미하지 않는다.

## 5. 후속 작업

GitHub Issue #7에서 다음 작업을 수행한다.

1. 수집된 원시 JSON을 읽어 경부고속도로 본선 휴게소를 필터링한다.
2. 휴게소명과 위치 정보를 바탕으로 상행·하행을 구분한다.
3. 충전소별 위도·경도와 기점 기준 `offset_km`을 계산한다.
4. `station`, `charger` 테이블에 데이터를 적재한다.
5. 경부고속도로 충전기 수를 공개 정보와 대조하여 검증한다.

원시 데이터는 변경하지 않고, 필터링 및 변환 결과는 별도로 관리한다.
