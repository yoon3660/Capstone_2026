1. 잘한 것 — 구체적으로
────────────────────────────────────────────────────────────

[1] ε 를 해시로 고정해 **난수 흐름을 소비하지 않는다**

    gumbel(seed, ev_id, alt) = blake2b 해시 → Gumbel(0,1)

    이게 이 PR 에서 가장 좋은 설계 결정입니다. 생성기에서 뽑으면 난수열이
    밀려 **뒤에 오는 추첨이 전부 달라집니다.** 그러면 "MNL 로 바꿨다" 가
    아니라 "차량 집합을 바꿨다" 가 되고, 짝지은 비교가 깨집니다.

    저는 어제 인내/우회 분리에서 이걸 **틀렸다가** 발견했습니다 — 같은
    generator 에서 한 번 더 뽑았더니 발길질이 240 → 256 으로 움직였고,
    탈출구 때문이 아니라 난수열이 밀려서였습니다 (`gen.spawn` 으로 고침).
    이 PR 은 처음부터 맞게 했습니다.

[2] `escape_mode="s0"` 기본값 — **한 번에 한 축**

    "어디서" 만 MNL 이고 "이탈할지" 는 S0 와 같은 잡음 없는 규칙입니다.
    그래서 두 세계의 차이가 **"선택이 퍼지는가" 하나**로 남습니다.
    `noisy` 를 민감도용으로 남겨 두고 기본값으로 안 쓴 판단도 맞습니다 —
    이탈 행동은 충전이력으로 식별되지 않습니다.

[3] θ → ∞ 이면 S0 와 비트 단위로 같다 (테스트로 고정)

    가족을 넓힐 때 **기존 동작이 특수경우로 들어 있는지**를 테스트로 박는
    것은 이 저장소의 규율과 같습니다.

[4] 조건 ② 진단이 날카롭습니다

    *"S1 은 대기를 예약 원장으로만 계산한다(`s1.py` 의 `dwell_if_i_go`).
      화면의 실제 줄(`st.wait_min`)은 쓰지 않는다. 원장에는 참여자 예약만
      들어간다. 그래서 p < 1 이면 엔진은 화면만 보는 S0·MNL 운전자보다도
      현재를 모른다."*

    이건 실험 설계 결함이고, 못 찾았으면 p<1 결과 전부가 틀렸을 자리입니다.
    "현재는 공개, 미래 계획은 비공개" 라는 해법도 원칙이 분명합니다.

[5] 제 결과를 정확히 인용했습니다

    S4 vs 완전예측 −27.6h, CI [−131.6, +76.4], 6/10 시드 — 제 10시드
    분해와 같습니다 (저는 % 로 +0.48%, CI [−1.01, +1.98] 로 냈습니다).
    "위반 의심, 미확정" 판정도 같습니다.

[6] 한계를 **먼저** 적었습니다

    θ 미식별 · MLE 아님 · ME 모집단 · 시간 분포는 개선 안 됨 ·
    추석 이력은 검증 자료로 인정 안 함. 이게 심사에서 깎이지 않는 쓰기입니다.

2. 동의하는 핵심 판정
────────────────────────────────────────────────────────────

**"MNL 은 바닥을 바꾸고 천장은 바꾸지 않는다."** p=1 에서 구조적으로
같은 계산이고 실측으로도 5,951h vs 5,917h 입니다. 맞습니다.

**"완전예측은 S2 의 천장이다."** 저도 독립적으로 같은 결론에 닿았습니다 —
`runner.py` 에서 `PERFECT_ROLLING` 이 `else: policy = S2Policy(...)` 로
떨어지고, 사다리 스크립트가 그 칸에 `s3_window`·`s4_lead_min` 을 안 줍니다.
즉 **S2 구조 + 완전한 미래**입니다. 두 사람이 다른 길로 같은 곳에 왔습니다.

### 가장 큰 차이는 **포기**입니다

제가 설 상행에서 잰 값입니다. 포기를 끄면 "이탈 기준 120분" 이라고 선언한
모형에서 **372.5분(6.2시간)** 기다리는 차가 생기고, 인내를 넘겨 기다린 시간이

    S0 561.8h   S1 99.5h   S2 21.1h   S3 39.5h   S4 34.9h

입니다. **S0−S2 격차 884.3h 중 540.7h (61%)** 가 그 기제에서 옵니다. 바닥이
더 당하는 이유는 발길질이 **예상** 대기로 이뤄지는데 S0 의 예상이 가장 많이
틀리기 때문입니다. 포기가 꺼진 무대의 사다리는 **그만큼 부풀어 있습니다.**

### 그리고 팀원 config 는 제 쪽에서 **돌릴 수 없습니다**

`reports/issue160_ctm_daily/inputs/...` 가 PR 에 없습니다 (`runs/` 를 커밋
안 한 것과 같은 이유로 보입니다). 저는 `data/processed/issue146_chuseok/` 를
`build_chuseok_demand.py --vds-from processed` 로 만들어 두었습니다
(커밋 f6b2ecc). **두 수요 프로파일이 같은 숫자인지 아무도 확인하지 않았습니다.**

### 제안 — 셋 중 하나로 정하면 됩니다

  (a) **팀원 config 에 `renege: true` 와 기회충전 레이어를 넣고 공급을 맞춘다**
      → 무대가 하나가 됩니다. 제 config 를 지웁니다
  (b) **제 config 를 쓰고 MNL 정책만 얹는다**
      → `--policy mnl` 식으로. 무대와 정책을 가릅니다 (권합니다)
  (c) **둘 다 두되 "MNL 보정용" 과 "엔진 비교용" 으로 용도를 못 박는다**
      → 발표에서 두 수치를 섞지 않는다고 적습니다

(b) 가 낫다고 봅니다 — 무대(config)와 정책(엔진)은 다른 축이고, 지금은
그 둘이 한 파일에 섞여 있습니다.

4. θ 가 식별되지 않는 것 — **나쁜 소식이 아닙니다**
────────────────────────────────────────────────────────────

보정 결과: TVD 최적이 격자 끝(θ=0.01)이고, θ가 작아질수록 0.36 근처로
평평합니다. 즉 **실측 분배가 우리 비용 모형이 예측하는 것보다 훨씬 고르게
퍼져 있습니다.** 거의 균등 무작위입니다.

처음 읽을 때는 "운전자가 시간을 최소화한다는 우리 전제가 안 맞는다" 로
들립니다. 그런데 **사다리에는 유리한 방향입니다.**

    운전자가 비용을 덜 볼수록  →  바닥이 더 나쁘다
                              →  최적화가 메울 자리가 더 크다
                              →  사다리가 길어진다

팀원 문서가 "MNL 은 바닥을 바꾼다" 로 적은 게 정확히 이겁니다. 발표에서는
이렇게 말할 수 있습니다 — *"실측 분배는 비용 최소화보다 훨씬 고릅니다.
그래서 S0(완전 합리) 를 바닥으로 쓰면 **엔진의 값어치를 과소평가**합니다."*

### 다만 **ME 배치 교란**을 먼저 걸러야 합니다

문서가 원인 후보로 적어 둔 것 중 하나입니다 — *"실측이 ME 장비만 담고 있어서
휴게소별 ME 비중이 분배를 좌우할 가능성"*. 이게 맞으면 우리가 맞추고 있는
것은 **운전자 선택이 아니라 충전기 배치**입니다. θ 는 아무 뜻이 없어집니다.

**한나절이면 가릅니다:**

    휴게소별 실측 ME 점유율  vs  휴게소별 **ME 충전기 수** 점유율
    두 분포의 TVD 를 낸다

    TVD(관측, ME기기비율) ≈ 0.1 이면  → 관측은 배치의 그림자다. θ 무의미
    TVD(관측, ME기기비율) ≈ 0.35 이면 → 선택 신호가 실재한다. θ 유의미

지금 모델(TVD 0.367)·S0(0.544)와 같은 자에 놓고 보면 바로 읽힙니다.
**이 한 줄이 θ 전체의 의미를 정합니다.** (2/2) 티켓 A 보다 먼저 해야 합니다.

### θ = 0.05 선택의 근거는 **간접적**입니다

TVD 최적(0.01)을 버리고 0.05 를 고른 이유가 "θ=0.01 은 이탈이 615대라
현실성이 없다" 입니다. 논리는 맞지만 **이탈 관측이 없습니다** (#165 표가
"충전 전 대기시간 N/A" 로 선언한 그 자리). 즉 관측으로 기각한 게 아니라
**그럴듯함으로** 기각했습니다. 그걸 그대로 적으면 됩니다 — 범위로 보고하는
지금 방식(θ ∈ {0.01, 0.05, 0.1})이 맞습니다.
