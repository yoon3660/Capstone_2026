# 참여율 실험에서 엔진이 비참여자를 보는 방식 — `nonpart_info` (#168)

작성: 2026-11-13 · 브랜치 `branch/168` · 대상: 참여율 실험 담당

> **한 줄 요약.** 참여율이 100% 미만인 실험은 `--nonpart-info present`로 돌린다. 그래야 엔진과 천장이 공정하게 비교된다. 엔진(S1~S4) 코드는 바뀌지 않았다. 바뀐 것은 엔진에 넘기는 정보다.

---

## 1. 왜 필요했나

참여율 실험에서는 일부 차(참여자, 비율 p)만 엔진의 배정을 따른다. 나머지(비참여자)는 스스로 휴게소를 고르고, #168의 MNL 세계에서는 MNL로 움직인다.

엔진(S1~S4)은 휴게소 대기를 **예약 원장**으로 계산한다. 예약 원장은 "어느 차가 언제 어느 휴게소에 오는지"를 적어 둔 장부다. 화면에 보이는 대기(`wait_min`)는 보지 않는다(`engine/s1.py`의 `ledger.dwell_if_i_go`).

그런데 원장에는 **엔진이 배정한 차만** 적힌다. 그래서 다음 일이 생겼다.

- 비참여자가 휴게소에 이미 줄을 서 있어도 엔진 눈에는 비어 보인다
- 엔진이 붐비는 곳으로 참여자를 보낸다. 그러면 줄이 더 길어지고, 엔진을 쓴 결과가 엔진이 없을 때(바닥)보다 나빠지기도 한다
- 반대로 천장(완전예측)은 비참여자의 과거·미래 도착을 모두 안다

그래서 엔진과 천장의 격차에 두 가지가 섞인다.

- **미래를 모르는 몫**: 엔진의 정당한 한계다
- **지금 휴게소 상황도 못 보는 몫**: 실험 설계 때문에 생긴 불이익이다

## 2. 원칙 — 현재는 공개, 미래 계획은 비공개

| 비참여자에 대한 정보 | 엔진 | 천장 |
|---|---|---|
| **현재** (휴게소에 와서 줄 서 있음, 충전 중) | **보게 한다.** 충전기 점유는 누구나 보는 공개 대기 정보다 | 본다 |
| **미래 계획** (어느 휴게소로 갈지) | 모른다 | 안다 |

이렇게 맞추면 엔진과 천장의 격차는 "미래 정보 + 조정 능력의 가치"만 남는다.

## 3. 어떻게 동작하나

### 3.1 바뀐 곳과 안 바뀐 곳

```
시뮬레이터 ──→ [참여율 래퍼] ──→ 엔진 (S1~S4, 그대로)
                    │
                    └─→ 비참여자는 MNL로 고르게 함
```

| 코드 | 상태 |
|---|---|
| 엔진 S1~S4 (`engine/s1.py` 등) | **안 바뀜** |
| 예약 원장 (`engine/reservation.py`) | **안 바뀜.** 기존 `book()`을 그대로 부른다 |
| 시뮬레이터 (`world/corridor_sim.py`) | **안 바뀜** |
| 참여율 래퍼 `ParticipationPolicy` (`engine/participation.py`) | #168 새 파일. `nonpart_info` 기능을 넣었다 |
| `MnlPolicy.plan_arrival` (`engine/mnl.py`) | #168 새 파일. 비참여자의 도착 정보를 계산한다 |

**계산기는 그대로 두고, 계산기에 넣는 숫자를 빠짐없이 넣어 준 셈이다.**

### 3.2 한 번의 결정(Δt = 5분)마다 래퍼가 하는 일

1. **참여자와 비참여자를 나눈다.** 차마다 고정된 난수로 정한다. 같은 시드면 같은 차가 참여자다
2. **엔진에게 묻기 전에, 이미 도착한 비참여자를 원장에 옮긴다.** 대기 목록에서 도착 시각이 지금보다 이른 차만 `ledger.book()`으로 적는다
3. **참여자는 엔진이 배정한다.** 평소와 똑같이 원장을 보고 계산한다
4. **비참여자는 MNL로 휴게소를 고른다.** `plan_arrival`이 그 차의 도착 정보를 계산한다
   - 도착 시각 = 지금 시각 + (휴게소까지 거리 ÷ 속도). S1의 `_eta`와 같은 식이다
   - 충전 요구 = 도착 SoC와 목표 SoC. MNL·S0와 같은 계산이다

   이 정보는 **바로 원장에 쓰지 않고 대기 목록에만 넣는다.** 지금 쓰면 엔진이 미래 계획을 알게 되기 때문이다

### 3.3 예시

```
10:00  비참여자 A가 안성휴게소를 고름
       → 거리 30km, 속도 80km/h → 도착 예정 10:22
       → 대기 목록에 메모만 함 (엔진은 아직 모름)

10:05 · 10:10 · 10:15 · 10:20
       → 엔진이 결정할 때 A는 원장에 없음 (아직 도착 전)

10:25  도착 시각(10:22)이 지났으니 A를 원장에 옮겨 적음
       → 이때부터 엔진은 "안성에 A가 와 있다"를 알고 대기를 계산
```

### 3.4 세 가지 방식

| `nonpart_info` | 비참여자를 원장에 적는 시점 | 용도 |
|---|---|---|
| `none` | 적지 않음 (기존 동작) | 비교용 하한 |
| **`present`** | **도착 시각이 지난 뒤** | **공식 실험용** |
| `plans` | 휴게소를 고르는 순간 (미래 계획까지 앎) | 비교용 상한. 현실에서는 불가능 |

세 방식은 이 "적는 시점" 하나만 다르다.

**천장 칸은 이 옵션과 무관하다.** 천장(완전예측)은 이미 `NonParticipantAwareForecast`로 비참여자를 전부 본다. 원장에까지 적으면 같은 차를 두 번 세게 되므로, 천장 칸은 항상 `none`으로 계산한다(`run_mnl_world.run_cell`).

### 3.5 단순화한 부분

- 도착 시각은 고정 속도로 계산한다. 설 adoption 무대는 통행시간이 고정(80 km/h)이라 실제 도착과 맞는다. 동적 통행시간(CTM) 무대에서는 오차가 생길 수 있다
- 줄에서 포기·이탈한 비참여자도 원장에 남는다. 그래서 엔진이 대기를 조금 길게 보는 쪽으로 오차가 난다
- 같은 차가 두 번째로 서면 `book()`이 첫 기록을 지운다. 엔진 참여자와 같은 동작이다

## 4. 기존 결과에 영향이 있나 — 없다

- 참여율 100%(p = 1)이면 비참여자가 없어서 세 방식 모두 결과가 기존과 **완전히 같다.** 테스트로 고정했다(`tests/test_mnl.py::test_full_participation_ignores_nonparticipant_info`)
- 그래서 지금까지의 사다리 결과(S0~S4, p = 1)는 그대로 유효하다
- 이 옵션은 **p < 1 실험에서만** 의미가 있다

**테스트** (`tests/test_mnl.py`):

| 테스트 | 확인하는 것 |
|---|---|
| `test_full_participation_ignores_nonparticipant_info` | p = 1이면 세 방식이 S1 단독 실행과 같다 |
| `test_partial_participation_books_nonparticipants_only_when_asked_to` | p = 0.5에서 원장에 적힌 수가 none(0) < present ≤ plans |
| `test_present_mode_reveals_a_nonparticipant_only_after_it_arrives` | present는 고른 순간에는 안 적고, 도착 시각(t = 100)이 지난 뒤에만 적는다 |
| `test_plans_mode_reveals_a_nonparticipant_when_it_chooses` | plans는 고르는 순간 적는다 |
| `test_rejects_unknown_nonpart_info` | 잘못된 값은 거부한다 |

## 5. p = 0.6 확인 결과

설 상행 adoption, θ 0.05, 이탈은 S0 규칙, 시드 1~3이다. 바닥(모두 MNL)은 7,294h, 천장(p = 0.6)은 6,184h다.

| 엔진이 비참여자를 | 엔진 | 총비용 | 바닥보다 나쁜 시드 | 천장보다 싼 시드 | 이탈 |
|---|---|---:|---|---|---:|
| 못 봄 (`none`) | S1 | 7,161h | 1/3 | 0/3 | 277 |
| 못 봄 (`none`) | S2 | 6,840h | 1/3 | 0/3 | 251 |
| **도착하면 봄 (`present`)** | **S1** | **6,957h** | **0/3** | 0/3 | **167** |
| **도착하면 봄 (`present`)** | **S2** | **6,787h** | **0/3** | 0/3 | **141** |
| 고르면 봄 (`plans`) | S1 | 6,801h | 0/3 | 0/3 | 157 |
| 고르면 봄 (`plans`) | S2 | 6,452h | 0/3 | 0/3 | 132 |

- **present로 하면 엔진이 바닥보다 나빠지는 경우가 사라진다.** 이탈도 바닥보다 적어진다
- **천장과 이탈 수를 맞춰 보는 검사**(S1 대비 ±35%)는 present에서만 통과한다. 천장 이탈(146대)은 present S1 대비 0.87배다. none S1 대비로는 0.53배라 미달이다
- **천장 검사**: 세 방식 모두 엔진이 천장보다 싼 시드가 없다
- **정보의 값**
  - none → present: S1 약 −200h. 현재를 보는 값이고, 엔진에게 줘야 공정하다
  - present → plans: 약 −160h. 미래 계획의 값이고, 엔진의 정당한 한계로 남긴다
- **주의**: 시드 3개, p = 0.6 한 점만 봤다. 평균 차이의 CI는 넓다

결과 파일: `runs/mnl_world/seollal_up_adoption_p06_info/comparison.csv` (git 제외, 로컬)

## 6. 실행 방법

`branch/168`에서 실행한다. 예: 참여율 0.6, S1·S2와 천장을 잰다.

```bash
python scripts/run_mnl_world.py --config config/scenario_seollal_up_adoption.yaml --p 0.6 --nonpart-info present --escape-mode s0 --theta 0.05 --stages S1,S2 --rounds 2 --seeds 1-3 --data-root <evdt 데이터 폴더> --out runs/mnl_world/p06_present
```

| 옵션 | 뜻 |
|---|---|
| `--p` | 참여율. 한 번에 하나씩(예: 0.3, 0.6, 1.0). 참여자 집합은 p에 대해 중첩된다(0.3의 참여자는 0.6에도 참여자) |
| `--nonpart-info present` | 이 문서의 방식. **빼면 기존 동작(`none`)으로 돈다** |
| `--escape-mode s0` | 이탈 여부는 S0 규칙(기본값). MNL은 휴게소 선택에만 쓴다 |
| `--theta` | 비참여자의 비용 민감도. 0.05와 0.1을 둘 다 돌려 범위로 보는 것을 권한다 |
| `--wait-weight` | 대기 가중치 w. 기본 1.0 |
| `--stages` | 잴 엔진 칸(S1, S2, S3, S4, MEC). S4는 한 번에 약 1시간 걸린다 |
| `--rounds` | 천장(완전예측) 회차 수 |
| `--skip-ceiling` | 천장을 건너뛴다. 같은 p에서 천장은 한 번만 재면 되므로, 정보 방식만 바꿔 다시 돌릴 때 쓴다 |

**환경**: DB는 `EVDT_DB_PATH`로 사본을 가리키는 것을 권한다. `--data-root`는 `data/`가 있는 저장소 루트다.

**결과 정리**: `scripts/analyze_p06_info_168.py --root <결과 폴더>`가 엔진 − 바닥, 엔진 − 천장, 이탈 비교표를 낸다. 폴더 아래에 `none/`, `present/`, `plans/`가 있다고 가정하므로 다른 p에서는 폴더 구조를 맞춘다.

## 7. 남은 확인 (참여율 실험에서)

| 확인 | 왜 |
|---|---|
| 다른 참여율(0.3 등)에서도 present로 엔진이 바닥보다 나빠지지 않는가 | p = 0.6 한 점만 봤다 |
| p마다 천장과 이탈 수가 맞는가 (S1 대비 ±35%) | 이탈 차이가 크면 비교가 착시가 된다 |
| p마다 엔진이 그 p의 천장을 넘지 않는가 | 넘으면 천장이 아니다. p = 1에서는 S4가 완전예측과 동점이었다 → 천장 포락선이 필요하다((2/2) 티켓) |
| 참여율이 높을수록 천장 비용이 줄어드는가 | 중앙 배정 대상이 늘어나니 상식적으로 그래야 한다 |
| θ 범위(0.05~0.1)마다 결론이 같은가 | 비참여자 행동(θ)이 아직 범위로만 정해져 있다. 범위 축소는 SUE·ASC 이슈(`docs/tickets/ticket_mnl_extra_params.md`)에서 한다 |
