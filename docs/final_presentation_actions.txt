3. §7 결과 — 오늘 측정했다
--------------------------------------------------------------------------------
구성안이 요구한 것: "MNL의 worst case(실제 선택 경향) 와 S4엔진의 best case를
비교해서 사회적 비용을 얼만큼 줄였는지".

**추석 무대에 MNL 바닥이 없었다.** #168 의 MNL 은 설 무대에서만 쟀고, 팀원의
추석 MNL config(`scenario_chuseok0925_up_ev15_mnl168.yaml`)는 **포기가 꺼져
있고** 그 주석이 직접 "이 config 의 run 으로 사다리 격차를 재면 안 된다" 고
적어 뒀다. 그래서 우리 엔진 비교 무대에서 MNL 바닥을 새로 쟀다.

**MNL 바닥 격자 (추석 9/25 EV15, 10시드).**

      θ     w     총비용    이탈   평균대기    P95   이탈/S0   기준2
  ----------------------------------------------------------------------
   0.01   1.0    4,262h   477.8    16.0분   64.6분   8.24x    ✗ 탈락
   0.05   1.0    2,688h    63.8     8.8분   43.7분   1.10x    ✓
   0.05   1.5    2,554h    78.2     7.5분   38.2분   1.35x    ✓ 경계

   0.10   1.5    2,331h    77.6     6.0분   32.6분   1.34x    ✓ 경계
  ----------------------------------------------------------------------
   S0 (사다리 바닥)  2,052h    58.0     4.5분   26.5분      —      —

  기준2 = 이탈 수가 S0 의 ±35% 안 (`docs/compare_rule.md`). θ=0.01 은 8.24배로
  완전히 탈락한다 — 설 무대에서 쓴 "채택 범위 θ 0.05~0.1" 이 추석에서도 같다.

**→ 발표 숫자 (MNL 바닥 → 각 칸 개선률, 짝지은 10시드).**

              θ=0.05 w=1.0 기준          θ=0.10 w=1.0 기준
  --------------------------------------------------------------
  S0           +23.7%                      +12.8%
  S2 (테슬라급) +35.8%  [34.3, 37.3]        +26.6%  [24.7, 28.5]
  S3           +36.2%                      +27.1%
  **S4**       **+40.3%**  [39.1, 41.6]    **+31.8%**  [30.4, 33.2]
  천장(포락선)   +42.7%                      +34.5%

★ 쓸 문장: **"실제 선택 경향을 바닥으로 두면, 4단계 엔진이 사회적 비용을
  31.8~40.3% 줄입니다."** (채택 θ 범위의 양 끝)
★ S4 는 천장에서 **2.3~2.6%p** 밖이다 — 완전한 미래 없이 거의 다 왔다

⚠ 이 숫자는 **비용 정의를 고친 뒤**의 값이어야 한다. 오늘 `run_mnl_world.py` 가
  총비용을 **두 항**(체류 + 이탈 대수 × 120분)으로 세고 있던 것을 찾았다.
  사다리는 **세 항**(체류 + 이탈 비용 + 포기 전 대기, `runner.social_cost_h`)이다.
  정의가 다른 두 숫자를 견주고 있었다 — 검증 리스트 내적 2번 위반이다.
  고쳤고(`cost_terms` 한 곳으로 묶음), 격자를 다시 돌리는 중이다. 시드 1 에서
  2,610.6h → 2,700.1h (+3.4%) 로 올라간다. 위 표는 재측정 후 갱신한다.

⚠ **θ 선택에 긴장이 있다.** 뉴스 보도 주말 대기 20~40분과 견주면 θ=0.1 (P95
  33.0분) 이 θ=0.05 (P95 43.7분) 보다 잘 맞는다. 그런데 설 무대 격자에서는
  θ=0.1·w=1.5 에서 "MNL 바닥이 격차를 더 크게 만든다" 가 동점이 된다
  (`docs/mnl_floor_grid_10seeds.txt`). 범위로 말하는 편이 안전하다.

→ 액션 A4. 격자 재측정 후 §7 표 확정
→ 액션 A5. θ 적합 근거를 팀원에게 확인 (어느 값, 어느 지표로 골랐나)

5. §8-2 증설 랭킹 — 실험을 새로 만들어야 한다
--------------------------------------------------------------------------------
구성안이 원하는 문장: "@@IC 구간이 막힐 때에는 안성에 1대 놓는게 칠곡에 3대
놓는 것보다 낫다".

**지금 있는 것은 그게 아니다.**

  `externality_rank.py`   한 번의 충전이 **남에게** 얹은 비용의 순위
                          (= 할인 정책의 신호. §8-1 쪽 재료다)
  `report_charger_gaps.py` 간격이 문제인가 용량이 문제인가 진단 (#54)

둘 다 "어디에 몇 대 놓으면 얼마가 줄어드나" 를 답하지 않는다. 그건 **충전기를
실제로 더 놓고 다시 돌려야** 나온다.

**막는 것.** 충전기 대수는 config 가 아니라 **DB** 에서 온다
(`runner.run_once` → `read_station_chargers`). 그리고 `run_id` 는 (시나리오,
스테이지, 시드, 참여율) 뿐이라 **충전기를 바꿔도 run_id 가 같다** — 조용히
기존 run 을 덮어쓴다 (#123 과 같은 고장).

→ 액션 A9. `run_once` 에 충전기 증설 손잡이를 더하고, **반드시
  `cfg.variant(tag, ...)` 로 scenario_id 를 바꾸게 강제**한다 (안 하면 멈춘다)
→ 액션 A10. 증설 실험: 상위 병목 휴게소(건천·칠곡·입장거봉포도) × {1, 2, 3}대,
  바닥(MNL)과 S4 둘 다에서. 결과는 "1대당 줄인 사회적 비용" 랭킹
→ 액션 A11. 발표 문장 확정. 숫자가 나오기 전에는 구체 지명을 쓰지 않는다


6. §8-3 EV 10% vs 15% — ✅ 준비됨
--------------------------------------------------------------------------------
                       EV 10%            EV 15%
  --------------------------------------------------------------
  S0 바닥               903.8h           2,052.3h
  S4                    851.5h           1,603.0h
  **S0→S4 개선**        **5.78%**        **21.75%**
  병목 슬롯 (S0)        **0.0**           9.2
  P95 대기 (S0)          2.5분           26.5분

★ 이게 그냥 "개선률 두 개" 보다 훨씬 좋은 이야기다: **EV 10% 추석에는 병목이
  아예 없다.** 기온이 22.18°C 라 충전이 빠르고(충전력 계수 1.000), 수요가
  공급을 못 넘긴다. 엔진이 할 일이 없으니 5.8% 밖에 못 줄인다.
  EV 15% 가 되면 병목이 9.2 슬롯 생기고, 그때 엔진이 21.7% 를 줄인다.

  → **"엔진의 가치는 병목이 생기는 순간 나타난다"** 를 숫자로 말할 수 있다

★ 솔직히 적을 것: EV 10% 에서는 **S4(5.78%)가 S3(6.44%)·S2(6.17%)보다 나쁘다.**
  병목이 없으면 5분마다 다시 배정하는 게 이득 없이 흔들기만 한다. 이건 약점이
  아니라 **"S4 는 병목이 있을 때만 이긴다"** 는 근거다

→ 액션 A12. 위 표를 슬라이드로. 추가 측정 없음


7. §8-4 참여율 — ❌ 데이터 0, 그리고 함정이 있다
--------------------------------------------------------------------------------
구성안: "전체 전기차 중에서 몇 퍼센트까지만 참여하더라도 유의미한 최적화를 할
수 있는지 확인할 수 있습니다."

**지금 참여율 실험이 하나도 없다.** `runs/` 의 모든 run 이 `p100` 이다.

★ **그리고 사다리는 참여율을 조용히 무시한다.** `runner.py` 에서
  `cfg.policy.participation` 은 **run_id 를 만들 때만** 쓰인다. 다른 곳에는
  없다. 즉 config 에 `participation: 0.6` 을 적으면 **이름만 다른, 물리가
  똑같은 run** 이 나온다. 그걸 결과로 쓰면 "참여율 60% 에서도 효과가 같다" 는
  완전히 틀린 결론이 나온다.

  참여율은 `engine/participation.py` 에 구현돼 있고 **`run_mnl_world.py` 만**
  그걸 쓴다. 그래서 참여율 실험은 그 경로로 가야 한다.

  #168 결정 문서가 참여율의 선행 조건을 이미 정리해 뒀다 (조건 ②: 엔진은
  비참여자의 **현재**를 보고 **미래 계획**은 모른다 = `--nonpart-info present`).

→ 액션 A13. **가드 먼저.** 사다리가 participation ≠ 1 을 받으면 멈추게 한다
  (조용한 무효 설정은 틀린 결론으로 직행한다)
→ 액션 A14. 참여율 스윕: `run_mnl_world.py --p {0.3, 0.6, 1.0}
  --nonpart-info present --stages S2,S4` 를 추석 무대 10시드로
→ 액션 A15. 판정: J(p) 단조성(⑤) · 이탈 맞춤(③) · 천장 검사(④)


8. §8-1 할인 정책 — 재료는 있다
--------------------------------------------------------------------------------
"할인 정책을 시행해서 쏠림현상 완화를 유도한다면" — 할인을 **어디에 얼마나**
줄지가 정책의 내용이고, 그 신호가 **한계 외부효과**다 (`externality_rank.py`).
한 대가 남에게 얹는 비용이 큰 휴게소를 비싸게, 작은 곳을 싸게 하면 된다.

이미 측정된 것: S0 상위 5% 방문을 지우면 1,685.7h 가 줄고, 같은 수를 무작위로
지우는 통제군은 1,116.5h 다 (1.47배). 즉 **"누구를 비키게 하느냐"가 1.47배
차이를 만든다** — 할인 대상 선별에 의미가 있다는 직접 증거다.

⚠ 쓸 때 조심할 것: 한계 외부효과는 **더할 수 없다** (Σ한계 ≠ 총량, S0 에서
  30,649.9h vs 체류 5,641.8h = 5.4배). "상위 5% 에 할인하면 1,685.7h 절감" 은
  말할 수 있지만 "전체 합이 30,649h" 는 말하면 안 된다.

→ 액션 A16. 추석 무대에서 `externality_rank.py` 재실행 (지금 값은 설 무대다)
→ 액션 A17. 발표 문장: 할인의 **신호**를 우리가 만들 수 있다는 것까지만.
  할인율 설계·수요 탄력성은 우리 모형 밖이다 — 그 선을 먼저 그어야 한다
