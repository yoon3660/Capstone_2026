# TCS OD 검증 결과

## 1. 데이터 수집

경부고속도로 실측 OD 구축을 위해 한국도로공사 TCS 영업소간 교통량 데이터를 사용하였다.

대상 기간은 다음과 같다.

- 설 연휴: 2026-02-13 ~ 2026-02-22
- 평시: 2026-03-06 ~ 2026-03-15

초기 계획에서는 포털의 「영업소간 이용차량」 화면 요청을 영업소 쌍별로 수집하려 했으나, 동일 데이터를 월 단위로 제공하는 「전체 영업소간 교통량 매트릭스」를 사용하였다.

동일 날짜와 OD 쌍에 대해 두 화면의 값을 직접 비교한 결과 값이 일치함을 확인하였다.

원본 파일은 수정하지 않고 보관하고, 전처리 후 다음 파일을 생성하였다.

- `data/processed/tcs_od_all.parquet`
- `data/processed/tcs_offices_gyeongbu.parquet`
- `data/processed/tcs_od_gyeongbu.parquet`

## 2. 경부선 영업소

전체 TCS Matrix와 경부선 영업소 위치 자료를 결합하여 분석 가능한 경부선 영업소 42개를 구성하였다.

도로공사 위치 API에서 직접 좌표를 얻을 수 없는 일부 영업소는 기존 경부선 IC 및 휴게소 원본 좌표를 사용하였다.

명시적인 테스트 항목인 `동김천(테스트)`는 분석에서 제외하였다.

Issue 작성 당시 예상한 44개와 달리 현재 데이터 기준 유효 분석 영업소는 42개이며, 임의로 수를 맞추지 않았다.

## 3. 영업소와 conzone 대응

각 영업소에 대해 UP/DOWN 방향별로 영업소 직후의 VDS conzone을 대응하였다.

기본적으로 영업소명과 conzone 시작 경계명을 이용해 매핑하고, 직접 이름 대응이 불가능한 경우 거리 기반으로 가장 가까운 시작 구간을 사용하였다.

총 42개 영업소 × 2방향 = 84개의 매핑을 생성하였다.

## 4. TCS OD와 구간 교통량 검증

각 날짜·출발 영업소·방향에 대해 경부선 내부 목적지로 끝나는 TCS 차량수를 합산하고, 출발 영업소 직후 conzone의 일교통량과 비교하였다.

검증 비율은 다음과 같다.

`coverage = 경부선 내부 목적지 TCS 출발량 / 출발 영업소 직후 conzone 교통량`

VDS 교통량은 24시간 값이 모두 존재하는 날짜만 검증에 사용하였다.

### 서울 영업소 검증

2026-02-14 서울 영업소의 부산 방향 결과는 다음과 같다.

- 경부선 내부 목적지 TCS 출발량: 47,522대
- 서울TG-신갈JC 일교통량: 97,540대
- 경부선 내부 목적지 설명 비율: 48.72%

Issue #61에서 제시한 약 48.7%를 동일하게 재현하였다.

전체 검증 결과에서 coverage가 100%를 초과하는 사례는 없었다.

## 5. 의심 OD 조사

### 서울 → 부산

Issue #61에서 의심 사례로 제시한 2026-02-14 서울→부산 OD는 74대로 원본 Matrix에서 동일하게 재현되었다.

설 연휴 10일 동안은 총 241대, 평균 24.1대/일이었으며 평시 10일은 총 77대, 평균 7.7대/일이었다.

설 연휴 평균은 평시보다 약 3.13배 높았다.

다만 250 km 이상 장거리 OD 전체를 조사한 결과 0~수십 대 수준의 희소 OD가 다수 존재하였다. 따라서 서울→부산 74대만을 근거로 데이터 오류라고 판단하기는 어렵다.

### 상서 하이패스IC

상서가 포함된 OD에서 한 방향은 차량이 존재하지만 반대 방향은 0인 사례가 다수 관찰되었다.

상서 하이패스IC는 방향 제한이 있는 나들목이므로 해당 값은 데이터 오류가 아니라 도로 구조에서 발생하는 구조적 0으로 분류하였다.

이 사례는 일반적인 양방향 비대칭 진단에서 제외하였다.

### 금강휴게소

`금강휴게소` 관련 OD는 일반적인 독립 영업소 간 OD와 동일하게 해석하기 어려운 특수 TCS 분류이다.

따라서 `금강 ↔ 금강휴게소`에서 나타나는 매우 큰 방향 비대칭은 일반 OD 이상치에서 제외하였다.

### 기타 비대칭

구조적·특수 사례를 제외한 후 일평균 10대 이상이면서 양방향 차이가 5배 이상인 사례는 소수만 남았다.

대표 사례:

- 천안 ↔ 칠곡물류: 약 5.75배
- 독립기념관 ↔ 칠곡물류: 약 5.35배
- 영동 ↔ 왜관: 약 5.33배

현재 자료만으로 이 차이를 데이터 오류라고 판단할 근거는 없으며, 실제 방향별 통행 수요 차이일 가능성을 배제할 수 없다.

## 6. 결론

TCS Matrix를 이용해 경부고속도로 내부 OD를 구축할 수 있었고, 독립적인 VDS 구간 교통량과 비교했을 때 Issue #61의 서울 영업소 검증값을 재현하였다.

일부 OD에서는 큰 비대칭 또는 매우 작은 장거리 통행량이 나타났지만, 방향 제한 IC나 특수 TCS 표기 등 설명 가능한 사례가 확인되었다.

따라서 현재 TCS OD는 경부고속도로의 중간 진입·진출 수요를 검증하고 보정하는 실측 자료로 사용할 수 있다. 다만 개별 OD 값 자체를 절대적인 수요로 간주하기보다 VDS 교통량 및 도로 구조와 함께 사용하는 것이 적절하다.


## 7. 수집 방식 변경 및 주의사항

Issue #61의 초기 계획에서는 고속도로 공공데이터 포털의 「영업소간 이용차량」 화면 요청을 영업소 쌍마다 호출하여 원본 JSON을 저장하는 방식으로 계획하였다.

구현 과정에서는 동일한 TCS OD 자료를 월 단위 전체 Matrix 형태로 제공하는 「전체 영업소간 교통량 매트릭스」를 사용하였다.

사용한 원본은 다음과 같다.

- `data/raw/tcs_od/tcs_od_202602.csv`
- `data/raw/tcs_od/tcs_od_202603.csv`

두 데이터가 같은 값을 나타내는지 확인하기 위해 동일 날짜·동일 출발/도착 영업소 조합을 「영업소간 이용차량」 화면과 직접 비교하였고 값이 일치함을 확인하였다.

따라서 본 구현에서는 영업소 쌍별 요청 대신 전체 Matrix를 원본으로 사용한다. 이 때문에 Issue에 처음 기재된 `fetch_od.py`, 요청 간격, 중단 후 재개 로직은 구현하지 않았다.

또한 이 데이터 취득 경로는 안정성이 보장된 프로젝트 내부 API가 아니라 한국도로공사 포털에서 제공되는 조회/다운로드 기능에 의존한다. 향후 포털 화면이나 데이터 제공 형식이 변경될 경우 수집 및 재현 과정이 영향을 받을 수 있으므로 원본 CSV를 별도로 보관한다.
