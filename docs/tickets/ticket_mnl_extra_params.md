# SP5 MNL 확장 — SUE(모드 B)를 구현하고, 비용만으로 설명되지 않는 분배를 추가 모수로 모델링한다

선행: #168 (MNL 도입 판단, 최소 설계) · 관련: #167 (설 충전이력), #149 (충전 판단 규칙), 대기·점유시간 리모델링

> **이 이슈는 #168에서 MNL 도입이 정해진 뒤에 시작한다.** #168은 도입 여부를 판단하는 단계라 MNL을 S0에 선택 잡음 하나(θ)만 얹은 형태로 두었다. 모수를 늘리면 차이가 MNL 때문인지 추가 모수 때문인지 구분할 수 없기 때문이다.

## 왜

#168 설 교차 검증(`docs/data_validation/mnl_ceiling_168_results.md` §3.3)의 결과는 이렇다.

- MNL은 S0보다 설 실측 분배에 확실히 가깝다(검증용 날 TVD 차이 약 −0.20)
- 그런데 **θ가 작을수록, 즉 비용을 덜 볼수록 더 잘 맞는다.** 최적점이 균등 무작위다. θ도 w도 식별되지 않았다
- 남은 분배 오차(TVD 약 0.28)는 비용(대기 + 충전시간)으로 설명되지 않는다

표준 MNL 설계에서 이 몫은 **선택지별 상수(ASC)**가 흡수한다. 계수는 개별 선택 자료로 추정하거나 문헌·지침에서 가져오고, 집계 비중으로는 ASC만 맞춘다. #168은 ASC 없이 θ 하나로 맞추려 해서 "더 무작위로"만 갈 수 있었다.

## 작업

### A. SUE (모드 B) — 설계 때 정한 2단계

#168 설계에서 MNL을 두 단계로 나눴다. **1단계(모드 A)를 먼저 해서 도입 여부를 정하고, 도입이 정해지면 2단계(모드 B, SUE)를 추가 구현한다.**

| | 모드 A (#168, 구현됨) | 모드 B (SUE, 이 이슈) |
|---|---|---|
| 보는 대기 | 지금 앱 화면의 대기 | **도착 시점의 실제 대기** |
| 성격 | 근시 확률 선택 | 확률적 **균형** (Daganzo & Sheffi 1977) |
| θ → ∞ | S0와 같다 | UE와 같다 |
| 구현 | `MnlPolicy`, 시뮬레이터에서 실행 | `ue.py`의 Gauss-Seidel 고정점 풀이에 고정 ε를 얹는다. 같은 ε를 쓰므로 MSA가 필요 없다 |

- **스프린트 노트의 후보 2가 말한 "SUE 모방 세상"은 모드 B다.** 지금 결과를 SUE 결과라고 부르지 않는다
- **역할**: 모드 A는 현실 바닥(쏠림이 있는 세계) 후보이고, 모드 B는 UE를 대신할 현실적 균형 기준점 후보다. 두 결과를 #167 설 실측에 같은 지표(TVD)로 대조한다. #167에서 UE는 S0와 비슷한 TVD(약 0.47)였다
**기존 UE가 하는 일 (`engine/ue.py`).**

1. 차마다 충전 계획(어느 휴게소들에 설지의 조합)을 만든다
2. `_plan_cost`로 각 계획의 실제 체류를 원장으로 잰다. 도착 시점의 대기가 반영된다
3. `_sweep`에서 "지금보다 나은 계획이 있으면 바꾼다"를 차례로 반복한다(Gauss-Seidel). 계획은 `_best`로 고른다
4. 아무도 바꿀 이유가 없으면 멈춘다. 그 상태가 균형이다

**SUE로 바꾸는 방법.**

- 계획 비용에서 `ε/θ`를 뺀다. ε는 MNL과 같은 해시 방식의 고정 Gumbel이다(`gumbel(seed, ev_id, 계획 키)`, 계획 키 = 휴게소 순서). 오차가 고정이라 기존 반복이 그대로 수렴한다. 확률 균형에서 흔히 쓰는 MSA가 필요 없다
- 큰 모집단에서 고정 ε의 균형 분포는 SUE 확률과 같다. 시드를 여러 개 돌리면 ε 표본에 따른 흔들림이 CI로 드러난다
- **이탈은 모드 A와 같은 원칙이다.** 이탈 여부는 잡음 없는 비용으로 정한다. 잡음은 휴게소 계획 사이의 선택에만 준다

**구현 (기존 파일 수정 없음).** 새 파일 `src/evdt/engine/sue.py`를 만든다. `ue._plan_cost`와 계획 선택(`_best`)을 감싸는 주입 방식으로 넣는다. `run_mnl_world._inject`와 같은 방식이다.

**테스트.**

- θ = ∞이면 기존 `solve_ue`와 계획·체류가 같다
- 같은 시드면 결과가 같다(ε 고정)
- 작은 예제에서 θ를 줄이면 휴게소 분배가 퍼진다

**검증.** 설 20개 시나리오(#168과 같은 경로: #64 설정 + BASE215 덮기)에서 S0 / UE / 모드 A / SUE를 같은 TVD 표로 대조한다. #167에서 UE는 TVD 약 0.47로 S0와 비슷했다. SUE가 UE보다 낮으면 "현실적 균형"이라는 새 기준점이 생긴다.

**주의.** UE 경로(`_run_ue`)는 S1~S4와 다른 시뮬레이션 경로다. 엔진과 비교할 때 시뮬레이터 차이가 섞이지 않는지 확인한다.

### B. 효용식 확장

    U_is = ASC_s − θ·(w·대기_s + 충전시간_is) [ + β·우회 + … ] + ε_is

- **ASC_s**: 휴게소별 상수. 편의시설, 브랜드, 위치 선호를 흡수한다. 상·하행 29곳
- **θ**: 집계 비중으로 맞추지 않는다. 문헌(충전소 선택 로짓 계수)이나 시간가치(KDI 예타 원단위)에서 가져오거나 범위로 둔다
- **w**: DESIGN §6.3 범위(1.0~1.5)와 교통 분야 관행(대기 1.5~2.5배)으로 민감도를 본다
- **이탈**: 충전이력으로 식별되지 않는다. 기본은 S0 규칙(`escape_mode="s0"`)이다. 이탈 상수는 민감도로만 둔다
- **구조**: 선택지끼리 비슷하면 nested logit(DESIGN 앵커 Bai et al.)을 쓴다. 개인차가 중요하면 mixed logit을 검토한다

**구현.** 모드 A는 `MnlPolicy`의 비용에서 `ASC_s`를 뺀다. SUE는 계획 비용에서 정차한 휴게소들의 `ASC`를 뺀다. 둘 다 `ASC = 0`이면 기존과 같다.

### C. 보정과 검증 (과적합 방지)

**정하는 순서.**

1. **θ를 먼저 고정한다.** θ와 ASC를 같이 맞추면 서로 바꿔치기되어 둘 다 정해지지 않는다. θ는 B의 출처(문헌·시간가치·범위)로 정한다
2. **ASC는 교통 수요모형의 표준 반복식으로 맞춘다.**

       ASC_s ← ASC_s + (1/θ) · ln(실측 비중_s / 모델 비중_s)

   모델 비중이 실측보다 낮은 휴게소는 상수를 올린다. 보통 5~10회면 수렴한다. 비용은 모델 1회 약 1초라서, 20개 시나리오 × 시드 3 × 10회면 15분 정도다
3. **보정용 날로만** 맞추고 검증용 날로 채점한다. #168과 같은 날짜 접기(홀수일·짝수일)를 쓴다
- ASC는 관측 휴게소 29곳만 정한다. 미관측 6곳은 0(기준)으로 두고, 그 사실을 기록한다
- **미리 정한 기준**: 검증용 날에서 ASC 모형이 θ만 쓰는 #168 MNL보다 TVD가 낮다(시드 대응 CI < 0). 대기가 있는 무대에서 대기 반응(w)이 식별되는지도 본다
- 휴게소×시간 TVD도 함께 본다. ASC는 시간 패턴을 못 바꾸므로 공간 분배만 맞추고 시간은 그대로일 수 있다

### D. w (대기 가중치)

설 실측에는 대기시간이 없다. 그래서 둘 중 하나로 정한다.

- **간접 지표**: #167의 동시 점유 수(`max_concurrent_sessions`)와 시간당 점유 분(`occupied_min`) 같은 혼잡 지표를 모델과 맞춰 본다. 대기가 생기는 시간대의 점유 포화가 맞는지 본다
- **범위**: DESIGN §6.3(1.0~1.5)과 교통 분야 관행(대기 1.5~2.5배)을 민감도로 둔다

### E. 정책 실험과의 분리

- ASC는 선택을 **고정**하지 않는다. 효용에 상수를 더할 뿐이라 대기가 늘면 다른 곳으로 옮겨 가는 반응이 남는다(참고문서 `dt_parameter_calibration_references.md`의 "관측 선택을 강제로 고정하지 않는다"와 충돌하지 않는다)
- 다만 ASC가 특정 휴게소로 차를 끌어당기면 바닥 비용이 바뀐다. 천장 비교에 쓰기 전에 #168 방식(R1~R7)으로 다시 잰다

## 순서와 크기

| 순서 | 작업 | 예상 |
|---|---|---|
| 1 | SUE 구현·테스트 (θ = ∞이면 UE) | 반나절~1일 |
| 2 | 설 대조: S0 / UE / 모드 A / SUE | 1~2시간 (실행) |
| 3 | 1·2 결과로 바닥 모델 선택 (모드 A 또는 SUE) | 회의 |
| 4 | 고른 모델에 ASC 추가, 날짜 접기 보정과 검증 | 반나절 |
| 5 | w 간접 검증 또는 범위 확정 | 반나절 |
| 6 | 바뀐 바닥으로 천장 비교와 사다리 다시 재기 | (2/2) 티켓과 함께 |

합치면 **2~3일**이다. 이 이슈는 #168 결론이 **C(보류)** 또는 **B + A(구현 계속)**일 때 연다. B만이면 바닥 용도로는 모드 A로 충분하다(팀 보고 §5.5).

## 완료조건

- [ ] SUE(모드 B)를 기존 파일 수정 없이 구현하고, θ = ∞이면 UE와 같음을 테스트한다. 모드 A·모드 B·S0·UE를 설 실측에 같은 표로 대조한다
- [ ] ASC 모형을 기존 파일 수정 없이 구현하고, ASC = 0이면 #168 MNL과 같음을 테스트한다
- [ ] θ의 출처(문헌·지침·범위)를 문서로 정한다. ASC는 θ를 고정한 뒤에 맞춘다
- [ ] w를 간접 지표(동시 점유·점유 분)로 검증하거나 범위로 확정한다
- [ ] 날짜 접기 교차 검증 결과를 미리 정한 기준으로 판정한다
- [ ] 바뀐 바닥으로 천장 비교와 사다리를 다시 잰다
- [ ] 결과 문서와 만든 파일 목록을 기록한다
