# T-21: EV 충전 판단 및 목표 SoC 규칙

## 1. 구현 목적

EV의 현재 배터리 상태, 차종별 전비, 온도, 주행거리 등을 이용해 충전 필요 여부와 목표 SoC를 계산한다. 목적지에 안전 여유를 남기고 직행하기 어려운 차량에 대해서는 경로상 충전소를 조회하고 추가 충전 방문 목록을 계획한다.

**구현 파일**

* `src/evdt/world/charge_decision.py`: 충전 판단, 목표 SoC 계산, 충전소 도달 가능 여부 및 충전 경로 계획
* `src/evdt/io/stations.py`: DB에서 주행 경로상 충전소 조회
* `tests/test_charge_decision.py`: 충전 판단 및 경로 계획 테스트

기존 `evdt.world.charging.energy_for_distance_kwh()`를 재사용하며, 충전 시간이나 충전곡선은 중복 구현하지 않는다.

## 2. 충전 판단 규칙

`needs_charging()`은 다음 조건을 이용해 충전 필요성을 판단한다.

* 다음 충전소가 목적지보다 앞에 있고, 현재 에너지로 `다음 충전소까지 거리 + 안전 버퍼`를 주행할 수 없으면 충전이 필요하다고 판단한다.
* 충전하지 않고 목적지에 도착했을 때 예상 SoC가 기준 미만이면 충전이 필요하다고 판단한다.
* 목적지보다 뒤에 있는 충전소는 다음 충전소까지의 에너지 부족 판단에서 제외한다.

`should_charge()`는 충전 필요성 판단 결과를 바탕으로 실제 충전 여부를 결정한다.

1. 현재 SoC가 목표 SoC 이상이면 충전을 생략한다.
2. 현재 SoC가 기준 미만이면 확률과 관계없이 충전한다.
3. 충전하지 않았을 때 목적지 도착 예상 SoC가 기준 미만이면 확률과 관계없이 충전한다.
4. 그 외 충전 필요 조건을 충족한 차량에는 설정된 충전 확률을 적용한다.
5. 충전 필요 조건을 충족하지 않은 차량은 충전하지 않는다.

**연동 시 주의:** `should_charge()`의 `arrival_soc_without_charging`은 기존 호출과의 호환성을 위해 선택적 인자다. 이 값을 전달하지 않으면 3번 규칙은 적용되지 않는다. 또한 현재 SoC가 목표 SoC 이상이어서 충전을 생략하더라도, 목적지 도착 조건을 만족하지 못한다면 추가 충전 경로를 별도로 검토해야 한다.

## 3. 시나리오 설정값

`config/scenario_seollal_down.yaml` 기준:

| 설정                         |    값 | 의미                            |
| -------------------------- | ---: | ----------------------------- |
| `demand.safety_buffer_km`  | 30.0 | 안전 여유 주행거리 30km               |
| `demand.charge_prob`       | 0.95 | 일반적인 충전 필요 조건 충족 시 적용할 확률 95% |
| `demand.low_soc_threshold` |  0.2 | SoC 판단 기준 20%                 |
| `vehicles.target_soc_cap`  |  0.8 | 목표 SoC 상한 80%                 |

주요 계산 함수는 설정값을 인자로 받는다. **실제 시나리오와 연동할 때는 설정값을 명시적으로 전달해야 한다.** 특히 목표 SoC 계산과 목적지 도달 가능 여부 검사에서 도착 SoC 20% 규칙을 적용하려면 `arrival_reserve_soc=0.2`를 전달해야 한다. 자동 경로 계획 함수의 해당 기본값은 0.2다.

## 4. 목표 SoC 및 목적지 도달 가능 여부

`calculate_target_soc()`은 목적지까지 필요한 주행 에너지에 안전 여유를 추가해 목표 SoC를 계산한다.

안전 여유는 다음 두 값 중 **큰 값**을 사용한다.

* 안전 버퍼 거리(예: 30km)를 주행하는 데 필요한 SoC
* 목적지 도착 시 확보할 최소 SoC(예: 20%)

계산식:

`목표 SoC = min(목적지까지 필요한 SoC + max(버퍼 SoC, 도착 최소 SoC), 목표 SoC 상한)`

30km 버퍼와 도착 SoC 20%를 단순히 더하지 않고, 둘 중 더 큰 안전 여유를 적용한다. 모든 차량이 항상 80%까지 충전하는 것은 아니며, 필요한 만큼 충전하되 목표 SoC는 설정된 상한을 초과하지 않는다.

`can_reach_destination()`은 주어진 SoC로 목적지에 도착한 뒤 안전 여유를 확보할 수 있는지 검사한다.

**80% 상한 때문에 목적지까지의 안전 조건을 만족할 수 없는 경우에는 중간 충전소를 추가로 방문하는 경로가 필요하다.** 단, 목적지 도착 SoC 20%는 경로 계획이 `destination` 상태로 성공한 경우의 계산상 조건이며, 모든 입력 차량의 실제 도착을 무조건 보장한다는 의미는 아니다.

## 5. 실제 충전소 조회 및 도달 가능 여부

`find_stations_on_route()`은 SQLite DB의 `station` 테이블에서 다음 조건을 만족하는 충전소를 조회한다.

* 차량과 동일한 `corridor_id`
* 현재 위치보다 앞에 있는 충전소
* 목적지보다 앞에 있는 충전소

프로젝트의 거리 좌표계에서는 상행과 하행 모두 **주행할수록 방향별 `offset_km`가 증가**한다. 따라서 경로상 충전소 조회에는 다음 조건을 사용한다.

`현재 offset < 충전소 offset < 목적지 offset`

실제 DB 조회를 통해 하행 충전소 19곳, 상행 충전소 16곳을 확인했다.

조회한 후보에 대해 `can_reach_station_with_buffer()`와 `find_reachable_stations()`를 이용하여 현재 배터리로 안전 버퍼를 남기고 도달 가능한 충전소를 추린다.

이때 ‘안전 버퍼를 남기고 도달할 수 없음’은 ‘충전소까지 물리적으로 도달할 에너지가 전혀 없음’과 동일한 의미가 아니다.

## 6. 추가 충전소 방문 및 자동 경로 계획

`decide_next_stop()`은 다음 세 가지 상태 중 하나를 반환한다.

| 상태                     | 의미                                   |
| ---------------------- | ------------------------------------ |
| `destination`          | 안전 조건을 만족하며 목적지 직행 가능                |
| `intermediate_station` | 중간 충전소를 다음 방문지로 선택                   |
| `no_reachable_station` | 현재 선택 규칙으로 안전하게 도달 가능한 중간 충전소를 찾지 못함 |

중간 충전소가 필요한 경우에는 현재 배터리로 도달 가능한 후보 중 **가장 먼 충전소**를 선택한다.

`plan_charging_stops()`은 이 결정을 반복하여 다음 과정을 수행한다.

1. 현재 SoC로 목적지 직행 가능 여부 확인
2. 직행이 불가능하면 다음 충전소 선택
3. 충전소까지 이동하며 감소한 SoC 계산
4. 충전소에서 목표 SoC 계산 및 충전
5. 다음 구간에 대해 동일한 과정 반복

결과에는 계획 상태인 `status`, 실제 충전량이 증가한 충전소 목록인 `charging_stops`, 목적지 도착 예상 SoC인 `final_soc`가 포함된다.

중간 충전 횟수를 차종에 따라 고정하지 않는다. 배터리 용량, 전비, 온도, 출발 SoC, 이동거리와 충전소 위치에 따라 필요한 방문 횟수가 달라진다.

**한계:** 가장 먼 충전소 선택은 현재 구현의 단순 규칙이며, 전체 경로 최적화나 충전 횟수 최소화가 증명된 알고리즘은 아니다. `no_reachable_station` 역시 현재 규칙과 안전 버퍼 조건으로 경로를 찾지 못했다는 의미다. 충전기 고장, 대기시간, 충전 속도 및 충전소의 실제 이용 가능 여부는 아직 고려하지 않는다.

## 7. 검증

`tests/test_charge_decision.py`에서 다음 사항을 검증했다.

* 저온에서 충전 필요성이 증가하는 사례
* 도착 예상 SoC 기준 및 안전 버퍼의 영향
* 목표 SoC 계산, 20% 도착 안전 여유 및 80% 상한
* 목적지 도달 가능 여부
* 충전 확률 및 강제 충전 조건
* 현재 SoC가 목표 SoC 이상일 때 충전 생략
* 실제 시나리오 설정값 사용
* 목적지보다 뒤에 있는 충전소 처리
* 음수 거리 입력 검증
* 테스트용 차량 100대에서 저온의 충전 차량 수가 상온보다 증가하는지 확인
* 중간 충전소 도달 가능 여부 및 후보 필터링
* 목적지 직행·중간 충전·경로 탐색 실패 상태
* 여러 충전소 방문 시 주행에 따른 SoC 감소
* 자동 충전소 방문 목록 생성
* 도달 가능한 충전소 중 더 먼 충전소 선택

**현재 T-21 단위 테스트: 31개 통과.** 프로젝트 전체 테스트에서도 오류가 발생하지 않았음을 확인했다.

100대 테스트는 합성된 검증 사례이며, 실제 명절 EV 통행량 대비 충전 수요 비율을 검증한 결과는 아니다.

실제 DB의 충전소 위치를 이용한 하행 100~300km 주행 예시에서는 캐스퍼급 차량이 222.066km 지점의 충전소 한 곳을 방문하고, 목적지 도착 예상 SoC가 20%인 경로를 계산했다.

## 8. 연동 시 확인할 사항

현재 충전 판단과 충전 경로 계획은 독립 함수로 구현되어 있으며, T-20 EV 합성데이터 생성기 및 실제 DES 시뮬레이션과의 연결은 별도 작업이다.

연동 시 다음 사항을 확인해야 한다.

* 시나리오의 온도·안전 버퍼·확률·SoC 기준·충전 상한 전달
* 충전하지 않을 때의 목적지 도착 예상 SoC 계산 및 `should_charge()`에 전달
* 차량 생성 시점이 아닌 실제 충전소 도착 시점의 SoC를 기준으로 충전량 계산
* 차량별 `corridor_id`, 현재 위치 및 목적지 위치를 이용한 충전소 조회
* 충전소별 실제 이용 가능 여부, 대기시간 및 충전 시간 반영
* `no_reachable_station` 발생 시 시뮬레이션에서의 처리 방법 결정
* 중간 충전소 방문 목록을 실제 주행 및 충전 이벤트에 반영

`writers.py` 및 기존 인터페이스의 스키마는 이번 티켓에서 변경하지 않았다.
