## 1. 무엇을 설계하는가

### 1.1 문제

설 연휴 경부고속도로에서는 특정 시간대에 몇몇 휴게소로 충전 차량이 몰린다.
같은 시각, 근처 다른 휴게소의 충전기는 비어 있다.
**충전기가 부족한 것이 아니라 나눠 쓰지 못하는 것이 문제다.**

원인은 두 가지다.

1. **혼잡 외부효과.** 운전자는 현재 상태를 보고 자기 대기시간만 최소화한다.
   한 대의 선택이 뒤차의 대기를 늘리는 비용은 그 운전자가 부담하지 않는다.
2. **본선 정체가 도착 패턴을 왜곡한다.** 정체가 풀리는 순간 충전 수요가
   파도처럼 한꺼번에 몰린다. 현재 상태만 보는 정보로는 이 파도를 미리 볼 수 없다.

기존 대응(이동형 충전차 투입, 충전기 점검, 앱 정보 정확도 개선)은 공급 측과
정보 측에 집중되어 있다. **수요 측 조정은 비어 있는 자리다.**

### 1.2 용어 정의 (발표·문서에서 통일)

| 용어 | 정의 | 주의 |
|---|---|---|
| **corridor** | 두 지점을 잇는 하나의 주요 교통축. 여기서는 "경부고속도로 본선 한 방향 + 그 위에 순서대로 늘어선 휴게소 충전소들" | 상행·하행은 서로 다른 corridor 2개 |
| **거시적 병목** | 개별 충전소의 대기가 아니라 corridor 전체에서 발생하는 **충전 수요의 시공간 쏠림** | 본선 교통 정체를 푸는 것이 아님. 발표 초반에 못 박을 것 |
| **충전 쏠림** | "충전 병목"보다 이 표현을 우선 사용 | "병목"은 공급 부족으로 들림. 우리 주장은 분배 문제 |
| **UE (User Equilibrium)** | 모든 운전자가 각자 자기에게 가장 유리한 곳을 고른 결과. 누구도 혼자 선택을 바꿔 이득을 볼 수 없는 상태 (Wardrop 제1원칙) | 시뮬레이션 구현은 근사. **"자율 선택 기준선 (UE 근사)"** 로 표기 |
| **SO (System Optimum)** | 전체 대기시간 합을 최소화하는 배정 (Wardrop 제2원칙) | 사후 최적해로 근사 |
| **사후 최적해** | 하루가 끝난 뒤 모든 차량의 도착 시각·SoC를 다 알고 푼 최선의 배정 | 목표가 아니라 **자(尺)**. 비용 기준이므로 "이론 최선"/"완전 정보 최적해"로 부르고 "상한"이라 하지 말 것 |

### 1.3 연구 질문

- **RQ1** 설 연휴 경부선에서 UE 하의 충전 쏠림은 어떤 수요 구간에서 조정으로 해소 가능한가?
- **RQ2** 정보와 결합 범위를 단계적으로 넓힌 최적화 엔진은 UE 대비 사회적 비용을
  얼마나 줄이며, 재계획 주기 안에서 작동하는가?
- **RQ3** 사후 최적해 대비 남은 격차는 예측 오차와 롤링 근시안 중 어디에서 오는가?

> **RQ1은 아직 가설이다.** "조정 실패"가 실제로 일어나는지 스프린트 1의 UE
> 히트맵으로 먼저 검증한다. 모든 휴게소가 동시에 포화되면 조정으로는 풀 수 없고,
> 그 경우 메시지를 바꿔야 한다.

### 1.4 Objective (제안서 문구)

> CTM(Cell Transmission Model) 기반 거시 교통류 모델과 휴게소 충전 Queue를 결합한
> Digital Twin을 구축한다. 이 Digital Twin에서 일정 주기마다 휴게소별 미래 도착 수요를
> 예측하고, Rolling Horizon MILP로 충전소 배정을 재최적화한다. Solver가 제한 시간 내에
> 해를 내지 못하면 예약 원장 기반 한계 외부비용 순차 배정으로 전환해 실시간 운영
> 가능성을 확보한다.

## 2. 스코프

### 2.1 포함

| 항목 | 정의 |
|---|---|
| 공간 | 경부고속도로 본선 서울↔부산, 상행·하행 (방향별 독립 인스턴스 2개) |
| 시간 | 설 연휴 (하행=귀성 피크일, 상행=귀경 피크일) + 대조군으로 평상시 주말 하루 |
| 공급 | 본선 휴게소 급속충전기 실제 인벤토리 (위치·기수·출력) |
| 수요 | 실측 통행량·구간 속도로 보정한 CTM 흐름 × EV 비중 × 충전 필요 확률 |
| 차량 | 합성 EV (차종 구성·출발 SoC·충전곡선·겨울 저온 감쇠 계수) |
| 엔진 | Stage 0 → Stage 4 단계 고도화 + 한계 외부비용 기반 배정 |
| 평가 | UE, 기반 논문 재현, 완전 예측 롤링, 사후 최적해 |

**설을 고른 이유:** 겨울 저온으로 충전 속도와 주행거리가 함께 떨어져 쏠림이 가장
뚜렷하고, 최근 정부 명절 대책과 바로 연결된다. 저온 효과는 충전곡선에 감쇠 계수
하나로만 반영하므로 복잡도가 거의 늘지 않는다.

### 2.2 제외 (후속 과제로 발표 마지막에 정리)

- 대체 경로(중부내륙 등)와 경로 선택 → 본선 고정
- 고속도로 밖 IC 인근 충전소
- 가격·인센티브 최적화 → 참여율 파라미터로 대체
- Vickrey 출발 시각 모델 → 시간대 차등 가격의 근거로만 언급
- 이동형 충전차 배치, 전력망 제약, 강화학습, 다른 corridor

### 2.3 핵심 가정

- 경로는 본선으로 고정
- 차량당 충전 정차는 최대 1회
- 목표 SoC = 목적지 도달 필요량 + 버퍼, **상한 0.8**. 결정변수에서 제외 (MILP 크기 통제)
- 인센티브 대신 **참여율(30/60/90%)** 을 파라미터로. 참여 차량은 배정을 따르고,
  비참여 차량은 UE 방식으로 행동
- 거시 교통류 → 충전 Queue는 **단방향 결합**. 충전 정차가 본선 흐름에 주는 영향은
  1차 구현에서 무시
- 상행 출발 SoC가 하행보다 낮을 수 있다는 가설은 **고정 가정이 아니라 민감도 파라미터**

## 3. 참고 논문과 하이브리드 전략

### 3.1 두 편의 역할 분담

**앵커 — Bai et al. (2026)**
*"Simulation of electric vehicle charging loads on highways considering fluid dynamics
under traffic flow congestion"*, Sustainable Energy Technologies and Assessments.

- 수정 CTM으로 고속도로 교통류의 시공간 분포 분석
- 여러 고속도로 충전소 간 충전 선택을 **nested logit**으로 모델링
- **Stationary Backlog Carryover(SBC)** 기반 큐 모델로 시간대를 넘는 누적 대기 처리
- 산둥성 고속도로 데이터로 검증
- **한계:** 유료 논문, 데이터는 요청 시 제공. 코드 없음 → 방법론 앵커·인용용

**구현 청사진 — Rupnik, Wang, Kramberger (2025)**
*"Hybrid Model for Motorway EV Fast-Charging Demand Analysis Based on Traffic Volume"*,
Systems 13(4), 272. MDPI **open access (CC BY)**.

수식이 전부 공개되어 있어 실제로 따라 만들 수 있다. 사실상 우리 **UE 베이스라인의
완성된 레시피**다.

| 요소 | 내용 |
|---|---|
| 도착 생성 | 시간당 교통량 → **비동질 포아송 과정**으로 개별 차량 도착 시각 |
| 도착 SoC | **Beta(2, 5)** 를 [0.1, 0.95]로 스케일링 (직전 충전소 60km 간격 가정) |
| 온도 효과 | 온도별 배터리 효율 곡선 → 잔여 주행거리 |
| 충전 판단 | 잔여거리 < 다음 충전소까지 거리(60km) + 안전버퍼(30km) **또는** 다음 충전소 도착 전 SoC < 0.2 → 충전확률 0.95. 여기에 시간대 가중치 곱 |
| 큐 | FIFO, 차량 최대 수용 출력에 맞는 충전기로 배정 |
| 목표 SoC | 0.8 ~ 1.0 랜덤 |
| 충전시간 | 비선형 충전곡선을 구간별로 나눠 계산 |

> **중요:** 이 논문은 명시적 한계로 **OD 매트릭스 부재**와 **네트워크 차원의 충전
> 인프라 조정**을 후속 과제로 남겼다. 우리 프로젝트가 정확히 그 자리에 들어간다.
> 제안서 차별점 문단에 인용할 것.

### 3.2 왜 하이브리드인가

| 항목 | 논문 추종만 | 자체 설계만 | **하이브리드 (채택)** |
|---|---|---|---|
| 목적 | 수요·부하 추정 (인프라 계획) | 배정 조정 (운영 최적화) | 둘 다 |
| 검증 | 실데이터로 검증된 구조 | 미검증 | DT는 검증 구조, 엔진은 기여 |
| 기여 | 없음 (재현) | 예측형 공동 배정 엔진 | 엔진이 기여 |
| 리스크 | 캡스톤 "깊이" 평가 약함 | 베이스라인 신뢰도 약함 | 양쪽 완화 |

두 논문 모두 **"얼마나 필요한가"를 답하는 계획 모델**이고, **"어디로 보낼 것인가"는
다루지 않는다.** Rupnik은 단일 허브, Bai는 다중 충전소를 다루지만 nested logit으로
운전자의 **자율 선택**을 모델링할 뿐 조정은 하지 않는다.

→ **층을 나눈다.**

| 층 | 출처 | 성격 |
|---|---|---|
| CTM 흐름 모델, 다중 충전소 선택 로짓 | Bai et al. | 이식 |
| 도착 생성·SoC 분포·온도 효율·충전 판단·DES 큐 | Rupnik et al. | 이식 |
| 명절 누적 대기 | Bai의 SBC 개념 | **인용만.** SimPy DES에서는 큐가 자연히 이월되므로 별도 구현 불필요 |
| **예약 원장 + 한계 외부비용 + 롤링 공동 배정 엔진** | **본 프로젝트** | **기여** |

발표 문구: *"DT와 베이스라인은 선행연구의 검증된 구조를 이식했고, 배정 엔진이
본 프로젝트의 기여입니다."*

```
  (충전기 인벤토리·통행량·속도)      (차종·SoC·저온 감쇠)

              ┌─────────────────────┐

              └─────────────────────┘
                         │
   ┌─────────────────────┴──────────────────────┐

   │                                            │
   │  예측 모듈 → 후보 필터 → 결정 코어 ⇄ 예약 원장 │

```

**매 Δt 루프:** 상태 동기화 → 예측 → 배정 → 원장 갱신 → 시뮬레이터 실행

### 4.1 설계 규칙 (위반 시 결과 전체가 오염됨)

1. **큐 규칙은 단일 모듈.** 시뮬레이터와 예약 원장이 **같은 함수**를 호출한다.
   두 곳에 따로 구현하면 원장이 틀린 미래를 예측하고 한계 외부비용이 전부 오염된다.
2. **`world/`는 `engine/`을 임포트하지 않는다.** 시뮬레이터는 `Policy` 객체를 주입받을 뿐,
   어떤 스테이지가 도는지 모른다. 이것이 공정 비교의 물리적 보장이다.
3. **모든 공간 엔티티에 선형 좌표(`offset_km`)와 위경도를 동시에 저장한다.**
   시뮬레이션은 선형 좌표로, 렌더링은 위경도로 돈다. 나중에 추가하려면 셀 분할을
   다시 해야 한다.
4. **시뮬레이터와 뷰어 사이에 스냅샷 스트림을 둔다.**
   `(t_min, entity_type, entity_id, lat, lon, state, value)`.
   렌더러를 바꿔도 시뮬레이터를 고치지 않는다.
5. **Parquet에는 재현 가능한 것만.** 재현의 근거(scenario/stage/seed/params/git SHA)는 SQLite.

## 5. 엔진 고도화 계획

### 5.1 두 축

엔진 고도화는 **예측 모델 학습도 파라미터 튜닝도 아니다.** 정식화와 파이프라인 구조의
변경이며, 두 축으로 정리된다.

| Stage | 알고리즘 | 정보 축 (무엇을 아는가) | 결합 축 (무엇을 함께 결정하는가) |
|---|---|---|---|
| **S0** | Nearest Station | 현재 큐만 | 차량마다 독립 |
| **S1** | Queue-aware Greedy + 예약 원장 | + 이미 배정된 차량의 미래 점유 | 순차 결합 (앞 배정이 뒤에 영향) |
| **S2** | Predictive Greedy | + 도착 시점의 미래 Queue | 순차 결합 |
| **S3** | Coordinated Assignment (공동 배정) | + 차량별 점유시간 | **윈도우 내 동시 결정** (공간축) |
| **S4** | Rolling-Horizon Optimization | + 아직 배정 안 된 미래 도착 (예측) | **시간축 결합** — 기존 배정도 상황 변화 시 재배정, horizon 끝의 충전소 부담을 terminal penalty로 반영 |

**한계 외부비용 기반 배정은 세 번째 종류의 변경이다.** 정보와 결합은 그대로 두고
**결정 기준**을 사적 비용 → 사회적 비용으로 바꾼다. S1의 변형이자 S3/S4 MILP가
시간 초과했을 때의 fallback.

### 5.2 terminal penalty

롤링은 창 안만 본다. 창 끝 직후 도착할 차량이 목적함수에 안 잡히므로, 엔진이
창 끝에 차량을 몰아넣는 **근시안적 배정**을 한다.

→ 창이 끝날 때 각 충전소에 남은 **예약 점유시간의 합**에 가중치를 곱해 목적함수에 더한다.
창 이후 예측 도착량이 많은 충전소일수록 가중치를 키운다.
가중치는 민감도 분석으로 정하고, **terminal penalty를 뺀 ablation** 한 줄로 기여를 보인다.

### 5.3 알고리즘적 개선 (엔진을 빠르고 정확하게)

각각 ablation 한 줄로 기여를 보인다.

1. 진행 방향 + SoC 도달성 기반 **후보 필터링** (EV당 후보 2~4곳)
2. 비선형 충전곡선의 **piecewise linear 근사**
3. 롤링 호라이즌 **terminal penalty**
4. 솔버 시간 초과 시 **한계 외부비용 순차 배정 fallback**

### 5.4 예약 원장 (Reservation Ledger)

**정의:** "누가, 어느 충전소에, 언제 도착해서, 얼마나 점유할 예정인가"를 **연속시간(분)** 으로
기록하는 공유 상태.

**설계 원칙 3가지**

1. **연속시간으로 저장.** MILP용 5분 슬롯은 원장에서 파생한 **뷰**. 슬롯으로 저장하면
   이산화 오차가 누적되고 진실의 원천이 둘이 된다.
2. **소프트 예약.** 예약은 우선권이 아니라 **FIFO 큐의 예측**이다. 실제 순서는 실제
   도착 순서로 정해진다. (슬롯을 확보해주는 하드 예약은 다른 메커니즘 → 스코프 밖)
3. **큐 규칙은 시뮬레이터와 동일.** FIFO 도착순 / 유휴 충전기 중 최고출력 선택 /
   전부 사용 중이면 최단 해제 대기.

**데이터 구조** — `src/evdt/engine/ledger.py` 참고

```python
@dataclass
class Reservation:
    ev_id, station_id
    eta: float            # 도착 예정 시각(분), 매 Δt마다 CTM 속도로 갱신
    soc_in, soc_target, battery_kwh, vmax_kw
    cold: float           # 저온 감쇠 계수
    status: PLANNED | CHARGING | DONE | NO_SHOW
    fixed_start, fixed_charger    # CHARGING일 때만 확정
```

점유시간은 **저장하지 않고** 충전기 출력별로 계산·캐시한다 (같은 차량도 50kW / 200kW에서
다름). 시작·종료 시각과 충전기 배정도 저장하지 않고 필요할 때마다 `project()`로 재계산한다.
충전소당 수십~수백 대 규모라 재계산이 싸고, 상태 불일치 버그가 원천 차단된다.

**연산 6가지:** `commit` / `cancel` / `update_eta` / `project` / `occupancy` / `evaluate`

**매 Δt 원장 갱신 순서**

1. **상태 동기화** — 충전 시작 차량은 CHARGING (시작 시각·충전기 고정),
   완료는 DONE, 휴게소를 지나쳤는데 안 들어온 차량은 NO_SHOW
2. **ETA 갱신** — 주행 중 PLANNED 차량의 ETA·도착 SoC를 CTM 구간 속도로 재계산
3. **신규 배정** — 새 요청 + 아직 첫 후보 휴게소를 지나지 않은 PLANNED 차량(재배정 가능)
4. **확정** — `commit` 후 다음 Δt 대기

## 6. 경제 모델

| 모델 | 엔진 안에서의 역할 | 적용 근거 |
|---|---|---|
| 혼잡 외부효과, Wardrop UE/SO (Wardrop 1952) | 문제 정의와 평가의 틀. UE = 자율 선택, SO = 사후 최적해 | 충전기는 용량 고정 공유 자원이고 한 대의 선택이 타인 대기를 늘림 → 외부효과 성립 조건 충족 |
| 한계 사회적 비용 원리 (Pigou 계열) | **결정 기준.** 한계 외부비용 순차 배정(S1 변형·fallback), MILP의 경제적 해석 | 이용자가 한계 사회적 비용으로 선택하면 균형이 SO와 일치. 예약 원장으로 외부비용을 직접 계산 가능 |
| 일반화 비용 · 통행시간가치 (KDI 예타지침 원단위) | 목적함수 가중치, 결과의 원화 환산 | 국내 공공투자 평가 표준 원단위 → 가중치 임의성 제거, 결과를 정책 언어로 |

세 모델이 각각 **문제 정의 / 해법 / 평가**에 대응한다.
경제 모델이 장식이 아니라 엔진의 세 지점에 들어간다는 것이 핵심 메시지.

### 6.1 한계 외부비용 계산

- **사적 비용 PC** = 차량 i 자신의 체류시간 (대기 + 충전)
- **한계 외부비용 MEC** = Σ(다른 차량 j의 **종료 시각**, i 포함 투영) − Σ(j의 종료 시각, i 제외 투영)
- **사회적 비용 SC** = PC + MEC, × 시간가치(원/분)

> **종료 시각**을 쓰는 이유: i가 끼어들면 뒤차의 **충전기 배정**이 바뀌어 충전 출력,
> 즉 충전시간까지 달라진다. 종료 시각은 대기와 충전시간 변화를 모두 담는다.

**검증 예제** (`demo.py`) — 충전소 A, 30km 뒤 B, 각각 100kW 2기.
A는 곧 충전 시작 2대 + 뒤에 확정 3대, B는 2대 충전 중이나 뒤가 비어 있음.
신규 차량 i는 A에 60분(SoC 30%), B에 78분(SoC 24%) 도착.

| 후보 | 사적 비용 | 한계 외부비용 | 사회적 비용 |
|---|---|---|---|
| A | 43.0분 | 22.0분 | 65.0분 |
| B | 48.4분 | 0.0분 | **48.4분** |

→ **사적 기준은 A, 사회적 기준은 B.** 시스템 전체로 16.6분 절약.
외부비용이 고르게 퍼지지 않는 점도 중요하다 (뒤차 3대 중 1대가 19분을 떠안고 나머지는
1.5분). "앞차 수 × 평균 충전시간" 같은 근사로는 이 분포가 안 나온다.

**S4 확장:** 예측 모듈이 비참여 차량의 미래 도착 시나리오 K개(10~20)를 만들고,
각 시나리오마다 두 번 투영해 외부비용을 평균 (표본평균 근사, SAA).
위 예제에 B 뒤 도착 시나리오 3개를 넣으니 B의 MEC가 0 → 10.0분으로 올랐다.
**"지금은 한산해 보이지만 곧 붐빌 충전소"** 의 비용이 이렇게 반영된다.

### 6.2 목적함수 (제안서 문구)

> Stage 2의 순차 배정에서는 차량 i의 배정 비용을 **사적비용(개인 체류시간: 대기 + 충전)
> + 한계 외부비용(i의 진입으로 다른 차량들의 종료 시각이 밀린 시간의 합)** 으로 계산하여,
> 사회적 총 비용이 가장 적게 늘어나는 충전소를 선택합니다.
>
> Stage 3~4의 공동 최적화에서는 윈도우 안 모든 차량의 체류시간 합을 한 번에 최소화하므로
> 외부효과가 목적함수에 자연히 포함됩니다. 즉 목적함수는 **"윈도우 내 전체 차량의
> 사회적 비용(체류시간 × 시간가치) + terminal penalty"** 이며, 순차 배정의 한계 외부비용
> 방식은 이를 한 대씩 근사하는 형태입니다.

> **우회비용은 넣지 않는다.** corridor에서는 어느 휴게소를 고르든 본선을 따라가므로
> 우회가 거의 없다. 뒤쪽 휴게소를 고르는 대가는 **도착 SoC가 낮아져 충전이 길어지는 것**
> 으로 이미 체류시간에 반영된다. 대기비용을 따로 쓰는 것도 체류시간과 중복이다.

### 6.3 이론적 한계 (발표에서 먼저 짚을 것)

- 한계 사회적 비용 결과는 **정적이고 비용이 분리 가능한** 혼잡 게임에서 엄밀히 성립한다.
  동적 큐에서는 근사다. → *"이론적으로 최적"이 아니라 "이론에 근거한 휴리스틱이며,
  그 성능을 사후 최적해로 검증했다"* 고 말할 것. 이것이 사후 최적해를 넣는 이유이기도 하다.
- 시간가치: 대기를 주행시간과 같은 가치로 볼지가 쟁점. 교통경제학에서는 대기를 더 무겁게
  보는 경우가 많고, 휴게소에서는 식사와 겹쳐 가볍게 느낄 수도 있다.
  → **대기시간 가중치를 범위(1.0~1.5)로 두고 민감도 분석.**
- **CTM은 경제 모델이 아니다.** 거시 교통류 모델(수요 예측용 공학 모델)과 위 세 경제 모델
  (배정 판단·평가용)을 발표에서 분리해 소개할 것.

## 7. UE 규칙 (스프린트 1의 핵심 산출물)

### 7.1 정의

UE는 **"시스템이 아무것도 조정하지 않은 오늘의 현실"** 을 대표하는 기준선이다.
모든 개선은 이 대비 몇 % 줄였는지로 말한다.

### 7.2 구현 규칙

```
1. 충전 필요 판단  (Rupnik 규칙)
   잔여 주행거리 < (다음 충전소까지 거리 + 안전버퍼 30km)
     OR  다음 충전소 도착 시 예상 SoC < 0.2
   → 충전확률 0.95, 시간대 가중치 곱
   현재 SoC < 0.2 → 무조건 충전

2. 충전소 선택  (이슈 #29 에서 UE 와 S0 를 나눴다 — docs/UE_equilibrium.md)
   UE : 도달 가능한 충전 계획(정차 휴게소들의 순서) 중
        **내가 도착했을 때의** 대기 + 충전시간 합이 가장 짧은 것.
        모두가 이렇게 고른 반복 균형 (누구도 혼자 바꿔서 줄일 수 없음)
   S0 : 앱에 보이는 **현재** 대기 + 예상 충전시간이 가장 짧은 곳 (근시안)

3. 목표 SoC
   목적지 도달 필요량 + 버퍼, 상한 0.8

4. 큐
   FIFO 도착순 / 유휴 충전기 중 최고출력 선택 /
   전부 사용 중이면 최단 해제 충전기 대기 (동률 시 고출력)
```

### 7.3 반드시 인지할 두 가지

1. **UE 는 반복 균형이다 (이슈 #29).** 한 번 서는 차만 있으면 정확한 균형이 한 바퀴에
   나온다 (FIFO 에서 내 대기는 먼저 온 차만 정한다). 두 번 이상 서는 차가 있으면 추월
   때문에 상대 gap 이 0 까지 안 가고 몇 % 에 남는다 → 수렴 기준 gap 3%.
   발표에서는 **"자율 선택 균형 (UE, gap ≤ 3%)"** 으로 표기.
2. **UE 와 S0 는 이제 다른 행동이다.** 처음에는 "현재 대기를 보고 고른다" 하나로 둘이
   같았다. 지금은 UE = 도착 시점의 대기를 아는 운전자(경험), S0 = 출발 시 화면만 보는
   운전자(근시안). S0 의 쏠림은 **같은 화면을 본 차들이 한꺼번에 몰리는 것**이고,
   UE 의 쏠림은 **각자 최선인데도 남는 혼잡 외부효과**다 (배터리가 적어 앞쪽 휴게소밖에
   못 가는 차가 대신 기다린다).

### 7.4 "잘 만든 UE"의 조건

- 파라미터 근거가 논문에 있을 것 (Rupnik)
- **쏠림 현상을 실제로 재현할 것**
- 나중에 엔진과 **같은 튜닝 예산**으로 비교될 것
  (베이스라인만 대충 튜닝하면 허수아비 비교라는 지적을 받는다)

## 8. 평가 체계

### 8.1 지표

| 구분 | 지표 |
|---|---|
| **헤드라인** | corridor 총 사회적 비용 (원) = 체류시간 × 시간가치 |
| 보조 | P95 대기시간 / 병목 충전소-시간 (대기가 임계값 30분 초과한 충전소×시간 슬롯 수) |
| 엔진 품질 | 윈도우별 **MIP gap** 분포 (중앙값·P95·기준 초과 비율) / 재계획 **solve time P95** / fallback 발동 윈도우 비율 |

> **최대 Queue 대신 P95 대기**를 쓴다. 단일 값은 노이즈가 크다.
> 모든 지표는 **"비용이 낮을수록 좋다"** 로 통일한다.

**MIP gap** = (최선해 − 하한) ÷ 최선해. gap 0%여도 실제 결과가 최적이라는 뜻은 아니다
(문제 자체가 예측을 믿는 가정 위에 있음). **풀이 품질은 MIP gap, 문제 설정 품질은
격차 분해**로 역할을 나눈다.

**solve time P95**: 통과 기준 `P95 < Δt`. 단, 솔버 시간 제한을 걸면 P95가 제한값에
붙을 수 있으므로 그때는 **"시간 제한에 걸린 윈도우 비율"과 "그 윈도우들의 gap"** 이
의미 있는 지표다. 실험 환경 하드웨어 사양도 기록할 것.

### 8.2 기준점 사다리와 격차 분해

| 기준점 | 엔진이 아는 정보 | 인접 기준점과의 차이가 뜻하는 것 |
|---|---|---|
| **사후 최적해 (SO)** | 하루 전체 모든 도착, 전체 호라이즌 동시 결정 | 이론 최선 |
| **완전 예측 롤링** | 미래 도착은 정확히 알지만 호라이즌이 잘림 | SO와의 차이 = **롤링 근시안 손실** |
| **제안 엔진 (S4)** | CTM 예측으로 미래 도착 추정 | 완전 예측 롤링과의 차이 = **예측 오차 손실** |
| **UE** | 각자 자기 도착 시점의 대기 (경험) — 누구도 혼자 바꿔 이득 없는 균형 | 제안 엔진과의 차이 = **엔진이 만든 개선** |

> **완전 예측 롤링은 거의 공짜다.** 롤링 엔진에 예측 대신 시뮬레이터의 실제 미래 도착을
> 넣으면 된다. 시뮬레이터가 이미 정답을 알고 있다.

이 분해가 깊이를 보여주는 핵심 결과다. *"남은 격차 중 몇 %가 예측 때문이고 몇 %가
롤링 구조 때문인가"* 를 원화로 말할 수 있고, 다음 개선 투자처까지 데이터로 답한다.

### 8.3 사후 최적해 계산 전략

이진변수 수 ≈ (충전 EV 수 × 후보 충전소 수 × 허용 시작 슬롯 수).
예: 2,000대 × 3곳 × 5분 슬롯 최대 2시간 대기 ≈ **14만 개.** 정확해 보장이 어려울 수 있다.
→ **S2를 만든 직후 실측해서 결정한다.**

| 범위 | 방법 | 주장 |
|---|---|---|
| 피크 3~4시간 | **정확해** (솔버가 최적임을 증명) | 가장 중요한 구간에서 진짜 최적과 직접 비교 |
| 하루 전체 | 시간 제한 + **솔버 하한(dual bound)** | "제안 엔진은 이론 최선보다 최대 X% 나쁘다" — **보수적 보증** |

- 피크 구간을 자르면 **시작 시점에 이미 충전 중/대기 중인 차량을 초기 조건으로 고정**해야
  공정하다.
- 하한은 항상 `하한 ≤ 진짜 최적 ≤ 찾은 최선해`. 따라서 격차 해소율도 보수적 추정이 되고,
  발표에서 *"과장하지 않은 수치"* 라고 말할 수 있다.
- **중단 기준:** 하루 전체 bound gap이 10%를 넘으면 피크 구간 결과만 헤드라인으로 쓴다.
- 우선순위: **피크 정확해 > 전일 하한.** 시간이 부족하면 전일 하한을 후속으로 미룬다.

### 8.4 그 외

- **수요 구간(regime) 분석** — 수요 배수·EV 비중을 쓸어가며 UE와 SO의 격차를 그린다.
  여유 구간(조정 불필요) / **조정 구간(우리 영역)** / 포화 구간(공급 확충만이 답).
  결과가 어떻게 나오든 의미가 있고, 정부의 이동형 충전 대책과 **보완 관계**라는 메시지가 나온다.
- **강건성** — 참여율(30/60/90%), 예측 오차 크기, 예상보다 30% 큰 수요 급증
- **반복** — 시드 20개 이상, 신뢰구간 표기
- **CTM 신뢰도** — 과거 명절 VDS 속도로 보정하고 정체 시작·해소 시각 재현을 먼저 제시.
  합성 데이터 프로젝트에서 **실측과 비교 가능한 유일한 지점**이며, 이 슬라이드가 있으면
  "더미 데이터 아니냐"는 질문의 절반이 사라진다.

### 9.5 ⚠️ CTM 구현 시 반드시 알아야 할 함정

삼각형 기본도(fundamental diagram)에서 `q_max`는 **독립 파라미터가 아니다.**

```
q_max = v_free × w_back × k_jam / (v_free + w_back)
```

이걸 어기면 **정체가 아예 생기지 않는다** (실제로 겪음).
`v_free`, `w_back`, `k_jam` 세 개를 정하면 용량은 따라오는 값이다.
`cell` 테이블에 일관성 검사를 넣어둘 것.

CTM 핵심은 40줄이다 (`src/evdt/world/ctm.py`). 검증 결과: 병목 셀 상류에 정체가 생겨
속도가 100 → 33 km/h로 떨어지고, 피크가 끝나면 해소된다.

```
src/evdt/

  engine/   policy.py  ledger.py  milp.py                # 배정 엔진

  viz/      frames.py  plots.py                          # 스냅샷 → 렌더러

data/       raw/ (원본 불변)  processed/
runs/       <run_id>/*.parquet + meta.json
```

### 10.1 엔진 ↔ 트윈 인터페이스

```python
class Policy(Protocol):
    stage: str
    def decide(self, evs: Sequence[EVState], world: WorldView) -> Mapping[str, str]:
        """{ev_id: station_id} 반환"""
```

`WorldView.forecast`와 `WorldView.ledger`는 **옵셔널**. UE와 S0는 보지 않고,
S1부터 원장을, S2부터 예측을 쓴다. **사후 최적해도 "전체 도착을 다 아는 Policy" 하나로
구현된다.** 스테이지 간 차이가 "같은 세계에서 `decide`만 다르다"로 환원되는 것이
공정 비교의 핵심이다.

### 11.1 ⚠️ 일정 리스크 (반드시 반영할 것)

원래 계획은 마지막 개발 스프린트에 UE 비교, 사후 정확해, 전일 하한, 격차 분해, 민감도,

**그래서:**

- **UE 비교 → Sprint 1 끝 (완료).** 문제 정의의 증거라 일찍 확보했다.

  결과와 함께 남으므로, 뒤가 밀려도 앞의 비교는 발표에 쓸 수 있다.
- **평가 · 2.5D 는 Sprint 6.** 개발로 당긴 두 스프린트 중 하나를 통째로 쓴다.
- CTM 이 Sprint 2 에 들어가면서 무거워졌다. CTM 이 밀리면 **S0 를 먼저** 끝낸다 — S0 는 CTM 없이
  고정 속도로도 돈다.

## 13. 발표 스토리 (최종 산출물 기준)

| 평가 영역 | 핵심 메시지 | 보여줄 결과 |
|---|---|---|
| **문제 정의** | 명절 충전 쏠림은 총량 부족이 아니라 조정 실패다 | UE 하의 충전소×시간 이용률 히트맵, 수요 구간 분석 |
| **기술적 어려움** | 단순 추천은 쏠림을 옮길 뿐이다 | S0/S1의 큐 진동 시계열, 어려움별 실패 증거 |
| **기술적 타당성** | 격차의 X%를 Δt 안에서 메우고, 조건을 흔들어도 유지된다 | 사다리 비교표, ablation, 강건성, CTM 실측 검증 |
| **스코프·깊이** | 한 corridor, 두 방향, 한 명절, 하나의 엔진을 끝까지 | solve time·MIP gap 분석, 격차 분해 |

**한 문장 요약**

> 설 연휴 경부선 충전 쏠림은 혼잡 외부효과가 만든 corridor 단위의 조정 실패이고,
> 거시 교통류 예측과 한계 사회적 비용 기반 롤링 공동 배정으로 이를 해소하며,
> 그 효과를 사후 최적해 대비 격차 분해로 검증한다.

### 13.1 기술적 어려움 4가지와 대응 (요약)

| 난점 | 대응 | 실패 증거로 보여줄 것 |
|---|---|---|
| 미래 수요 불확실성 | 확정 수요(배정된 EV) / 불확실 수요 분리. 분위수 예측(P80) 또는 SAA | 과거 평균 예측이 정체 해소 직후 파도를 놓치는 장면 |
| 배정 상호의존성 | 예약 원장 + 공동 최적화 | S0의 큐 진동 시계열 (**주연**) |
| 차량별 충전시간 차이 | 점유시간 계산기 + piecewise linear 근사 | 대기 대수만 세는 추정 vs 점유시간 반영 추정의 오차 |
| 다수 차량 최적화 복잡도 | 후보 필터 + 롤링 호라이즌 + fallback | 전체 호라이즌 MILP의 solve time이 Δt를 넘는 지점 |

> **학습/평가 분리:** 같은 시뮬레이터가 만든 데이터로 예측 모델을 학습·평가하면 성능이
> 과대평가된다. 학습용/평가용 시나리오 파라미터를 분리하고, 예상보다 20~30% 큰 귀성 피크
> 같은 **분포 이동 테스트**를 반드시 넣을 것.
