# MNL 도입 판단 — 천장 설정에 얼마나 도움이 되고, 도입하면 비교가 가능한가 (#168)

작성: 2026-11-12. 대상: 팀 회의. 근거 문서는 `docs/data_validation/mnl_ceiling_168_results.md`다.

> **최종본 (2026-11-12 23:00).** 추천은 **B + A**다(§5, §6). 격차 축소율은 시드 1~4 기준이다. 시드 5는 UE가 수렴하지 않아 격차 축소율에서 제외했다(반복 200회 실패 gap 0.0131 > 0.008, 800회 재시도는 23시에 중단). 천장 검사·S4·조건 ②는 UE가 필요 없어 시드 5를 포함한다.

## 1. 질문

| | 질문 |
|---|---|
| **Q1** | MNL을 도입하면 천장 설정에 얼마나 도움이 되나 |
| **Q2** | MNL 세계에서 엔진과 천장을 **공정하게 비교**할 수 있나 |

여기서 "MNL 천장"은 **참여율 p를 바꿔 가며 MNL 세계에서 구한 천장 J(p)**를 말한다. p < 1이면 엔진을 따르지 않는 차(비참여자)가 MNL로 움직이고, 천장은 그 세계에서 완벽한 정보로 최적화한 값이다.

## 2. 지금까지의 답

| p | Q1: 천장 설정에 도움 | Q2: 비교 가능 |
|---|---|---|
| **p = 1** | **도움 없음.** 천장은 기존 완전예측과 같은 계산이다(구조상 + 실측 5,951h vs 5,917h). MNL은 **바닥**만 바꾼다 | 가능. 엔진 칸이 기존 세계와 같다 |
| **p < 1** | **여기서만 의미가 있다.** 비참여자가 현실적으로 움직이는 세계의 천장이기 때문이다. 다만 아직 잴 수 없다 | **지금은 불가능.** 조건 ②·③이 막혀 있다(§3) |

- **별개 문제**: 완전예측 자체가 천장이 아닐 수 있다. 팀원 결과(같은 설 상행 adoption 무대, 포기 모형 켬, 시드 10개)에서 S4가 완전예측보다 평균 27.6h 쌌다. CI [−131.6, +76.4]라 확정은 아니고, S4가 6/10 시드에서 더 쌌다(위반 의심). 팀원 README도 "완전예측은 S2의 천장이지 S4의 천장이 아니다"라고 적었다. 이 문제는 MNL로 풀리지 않는다. 완전예측-S3/S4 포락선이나 사후 최적해(MILP)가 필요하다
- **용어**: 지금 MNL은 1단계(모드 A, 근시 확률 선택)다. SUE(모드 B)는 도입이 정해진 뒤 구현한다

## 3. p별 천장 J(p)를 도입하려면 필요한 조건

| 조건 | 왜 필요한가 | 현재 상태 | 해야 할 일 | 담당 |
|---|---|---|---|---|
| **① 비참여자 행동 모델이 맞아야 한다** | p < 1이면 비참여자가 MNL로 움직이므로 θ가 천장값을 직접 바꾼다 | 설(#167) 교차 검증에서 S0보다 확실히 낫다(검증용 날 TVD 차이 약 −0.20). **θ는 미정**이다(설 분배는 θ ≤ 0.02를 모두 비슷하게 맞춤) | θ 범위를 줄일 근거가 필요하다(혼잡 무대 이탈 기준, 대기 관측, SUE·ASC) | #168 → 다음 이슈 |
| **② 엔진과 천장의 비교가 공정해야 한다** | 같은 정보 조건이 아니면 정보 차이가 그대로 "격차"로 잡힌다 | **문제 있음.** 엔진(S1·S2)의 예약 원장은 참여자만 안다. 천장(Oracle)은 비참여자 도착까지 본다. p = 0.6에서 S1·S2가 바닥보다 나빴다 | **해결 가능 (§3.1).** 원칙은 "현재는 공개, 미래 계획은 비공개"다. 비참여자가 휴게소에 실제로 도착한 시점에 원장에 올린다 | #168 (래퍼 수정 + p = 0.6 한 점 확인) → 참여율 담당 (스윕) |
| **③ 이탈 수 맞춤을 p마다 통과해야 한다** | 이탈을 덜 내서 싸 보이는 착시를 막는다(S1 대비 ±35%) | p = 0.6에서 미달이다(옛 이탈 방식). 개선 1(이탈은 S0 규칙) 뒤로는 다시 재지 않았다 | p 스윕 때 함께 잰다 | 참여율 담당 |
| **④ 천장 검사: 어떤 p에서도 엔진이 그 p의 천장을 넘지 않아야 한다** | 넘으면 천장이 아니다 | 하지 않았다. p = 1에서도 위반 의심 1건(S4 < 완전예측)이 있다 | p마다 `엔진 − 천장 ≥ 0`을 시드 대응으로 검사한다 | (2/2) 티켓 C |
| **⑤ J(p)가 상식적으로 움직여야 한다** | p가 커질수록 중앙 배정 대상이 늘어나니 천장 비용은 줄어야 한다 | 하지 않았다 | p ∈ {0.3, 0.6, 1}에서 J(p)의 단조성을 확인한다 | 참여율 담당 |

**순서**: ②를 먼저 고쳐야 한다. 안 그러면 어떤 p에서도 비교가 성립하지 않는다. 그다음 p 스윕으로 ③④⑤를 보고, ①의 θ 범위마다 결과가 버티는지 본다.

### 3.1 조건 ② 해결 방안 (2026-11-12)

**원인 (코드 확인).** S1은 대기를 예약 원장으로만 계산한다(`s1.py`의 `ledger.dwell_if_i_go`). 화면의 실제 줄(`st.wait_min`)은 쓰지 않는다. 원장에는 참여자 예약만 들어간다. 그래서 p < 1이면 엔진은 **화면만 보는 S0·MNL 운전자보다도 현재를 모른다.** 반면 천장은 비참여자의 과거와 미래를 모두 안다. 지금 격차에는 "미래를 모르는 몫"과 "현재를 못 보는 몫"이 섞여 있다. 앞의 것은 정당한 한계이고, 뒤의 것은 실험 설계 때문에 생긴 불이익이다.

**원칙.**

| | 엔진 | 천장 |
|---|---|---|
| 비참여자의 **현재** (줄 서 있음, 충전 중) | **보게 한다** (충전기 점유는 공개 대기 정보에 나타나는 현재 상태다) | 본다 |
| 비참여자의 **미래 계획** (어디로 갈지) | 모른다 | 안다 |

**구현 (기존 파일 수정 없음).**

- 참여율 래퍼가 비참여자의 목적지를 시뮬레이션 내부에서 안다. 그 정보를 **실제 도착 시각이 되었을 때만** 원장에 올린다. 이 무대는 통행시간이 고정이라 도착 시각이 정확하다
- 원장에 올리는 비참여자의 충전 요구는 그 차의 실제 요구다(충전기에 꽂으면 충전기가 SoC를 본다는 근사). 처음 계획한 "실측 평균 세션 길이(설 #167, 27.1분)로 근사"는 구현에서 쓰지 않았다
- 원장은 `run_corridor(ledger=…)`로 넘어가므로 `run_mnl_world._inject`로 접근한다

**비교군 (결과를 사이에 끼워 읽는다).**

| 엔진 정보 | 뜻 |
|---|---|
| ① 비참여자 안 보임 (지금) | 하한 |
| ② 현재 공개 (위 방안) | **공식 비교용** |
| ③ 계획까지 공개 (비참여자 예약도 원장에) | 상한. 비현실적이지만 정보 차이의 최대 크기를 본다 |

**확인 기준.**

- p = 1이면 세 방식 모두 지금과 같다(테스트로 고정한다)
- p = 0.6에서 "S1·S2가 바닥보다 나쁨"이 사라지거나 크게 준다
- 남아 있으면 S1 자체의 약점(p = 1에서도 S0 대비 −2%, 동점)과 구분해 적는다

**확신 정도.**

| 항목 | 확신 |
|---|---|
| 원인 진단 | 높음 (코드 확인) |
| 기존 파일 수정 없이 구현 | 높음 (경로 확인) |
| 고친 뒤 S1 < 바닥 현상 해소 | 중간 |
| 고친 뒤 J(p) 조건 ③④⑤ 통과 | 모름 (p 스윕, 참여율 담당) |

## 4. 요소 사이의 관계

```
θ (운전자가 비용 차이에 얼마나 민감한가)
 ├─ 실측 분배 적합 ............ 작은 θ가 유리 (설 #167)
 ├─ 혼잡 반응 · 이탈 수 ....... 큰 θ가 필요 (θ 0.01이면 이탈 S0의 약 1.7배)
 ├─ 바닥 비용 → 격차 축소율 ... θ 0.1 → 약 28%, θ 0.01 → 약 44% (대략값)
 └─ p < 1 천장 J(p) ........... 비참여자의 움직임을 통해 직접
w (대기 가중치) ── 대기가 있을 때만 θ와 함께 작동. 설 재현 무대에서는 식별 불가
p (참여율) ── 엔진 정보(원장)와 천장 정보(Oracle)의 비대칭 ② 를 키운다
이탈 비용 E ── 격차 축소율의 크기 (방향은 E 0~2h에서 유지)
충전 규칙 결함(#149) ── S0의 쏠림 · 정차 소진 이탈 ── 분배 적합 차이의 일부
천장 포락선(완전예측-S2/S3/S4) ── 격차 축소율의 분자 쪽. MNL과 무관
```

## 5. 선택지

| 선택지 | 내용 | 필요한 것 | 위험 |
|---|---|---|---|
| **A. J(p) 도입 추진** | MNL 세계에서 p별 천장을 공식 천장으로 쓴다 | ② 수정 → p 스윕 → ③④⑤ 검사 → θ 범위별 결과 | 가장 비싸다. θ가 미정이라 J(p)도 범위로만 나온다 |
| **B. 바닥만 MNL, 천장은 포락선** | p = 1에서 바닥을 MNL로 바꾸고, 천장은 완전예측-S2/S3/S4 포락선으로 둔다. J(p)는 보류한다 | 개선 3 결과(이번 실행), 천장 포락선((2/2) 티켓) | p < 1 질문은 답하지 못한다 |
| **C. 보류** | SUE(모드 B)·ASC로 θ·w 근거를 먼저 만든다 | `ticket_mnl_extra_params.md` | 이번 스프린트 안에 결론이 없다 |
| **D. 기각** | S0 바닥을 유지한다 | 없음 | "S0 바닥은 실측과 맞지 않는다"는 한계를 발표에 명시해야 한다 |

**추천 (2026-11-12 확정): B + A.** 판정 (가)이고 조건 ②가 해결됐다. 바닥은 MNL(θ 0.05~0.1, w 1.0~1.5 범위)로, 천장은 완전예측-S2/S3/S4 포락선으로 둔다. J(p)는 present 방식으로 참여율 담당과 추진한다. 상세는 팀 보고 `docs/report_mnl_ceiling_168_team.md` §5.5에 있다.
