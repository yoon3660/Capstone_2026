# T-06 경부고속도로 휴게소 및 충전 인프라 구축

## 1. 작업 목적

환경부 전기차 충전소 OpenAPI와 한국도로공사 데이터를 이용해  
경부고속도로 시뮬레이션용 휴게소 및 충전기 데이터를 구축한다.

- 경부고속도로 휴게소 필터링
- UP / DOWN 방향 분리
- 위도·경도 및 `offset_km` 생성
- `station`, `charger` DB 적재
- 공개데이터와 충전기 대수 검증

---

## 2. 휴게소 구성

현재 시뮬레이션 대상은 총 **33개 휴게소**이다.

- **DOWN (서울 → 부산): 17개**
- **UP (부산 → 서울): 16개**

환경부 데이터와 한국도로공사 데이터의 휴게소명을 정규화한 뒤

```text
(휴게소명, 방향)
```

기준으로 매칭하였다.

운영사명이 포함되어 매칭되지 않는 일부 데이터는 명시적인 alias로 처리하였다.

```python
STATION_NAME_ALIASES = {
    "워터경주휴게소": "경주휴게소",
    "워터칠곡휴게소": "칠곡휴게소",
}
```

---

## 3. offset_km

`offset_km`은 방향별 기점에서 각 휴게소까지의 거리를 나타내는 값이다.

- DOWN 기점: 양재IC (`0010I00045`)
- UP 기점: 구서IC (`0010I00001`)

Sprint 1에서는 방향별 기점과 휴게소 좌표 사이의
**Haversine 직선거리**를 `offset_km`으로 사용한다.

따라서 현재 값은 실제 경부고속도로 본선을 따라 이동한 누적거리가 아니라,
휴게소 순서 및 초기 시뮬레이션 좌표를 위한 근사값이다.

`offset_km` 계산은 별도 함수(`add_offset_km`)로 분리하였다.
따라서 Sprint 2에서 실제 도로 누적거리 기반 계산으로 변경할 때
station/charger 적재 로직을 수정하지 않고 거리 계산 로직만 교체할 수 있도록 구성하였다.

## 4. DB 적재

DB 적재 스크립트:

```bash
python scripts/load_chargers.py
```

최종 적재 결과:

| 항목 | 결과 |
|---|---:|
| station | 33개 |
| charger group | 100개 |
| physical charger | 276기 |

`charger` 한 행은 동일한 출력 및 커넥터 타입을 가진 충전기 여러 기를 나타낼 수 있으므로  
실제 충전기 수는 다음과 같이 계산한다.

```text
SUM(charger.n_units)
```

## 5. 충전기 대수 검증

검증 스크립트:

```bash
python scripts/audit_charger_counts.py
```

환경부 raw 데이터의 고유한

```text
(statId, chgerId)
```

조합을 실제 충전기 1기로 계산하여 DB와 비교하였다.

최종 결과:

```text
현재 DB: 276
환경부 공개데이터: 276
차이: 0
```

**33개 휴게소 모두 개별 충전기 대수도 일치하였다.**

초기에는 268기만 매칭되었으나 다음 데이터가 휴게소명 앞의 운영사명으로 인해 누락되어 있었다.

- `워터 경주휴게소 부산방향`: 5기
- `워터 칠곡휴게소 서울방향`: 3기

alias 적용 후 최종 **276기**가 정상적으로 매칭되었다.

## 6. 현재 제외 대상

현재 시뮬레이션 대상에서 제외된 시설은 다음과 같다.

- **언양(부산)휴게소:** 충전 데이터 매칭 제외
- **서울하이패스센터쉼터:** 방향 미확정
- **옥천만남휴게소:** 방향 미확정
- **기흥복합휴게소:** 방향 미확정

따라서 본 문서의 **33개 휴게소 / 276기**는  
현재 시뮬레이션 대상으로 확정한 범위를 기준으로 한다.
